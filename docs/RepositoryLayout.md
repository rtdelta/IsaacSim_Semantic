# 仓库文件布局

2026-10-19 整理范围：保持项目根目录、功能源码包和启动路径，整理正式报告与验收摘要，归档可再生成的临时产物，并排除原始采集和实验数据。

## 文件职责

| 位置或材料 | 职责 | Git 策略 |
| --- | --- | --- |
| 项目源码包、入口、`config/`、`web/`、`tests/`、`tools/` | 功能、配置、测试及可复用工具 | 保留 |
| 项目 `docs/` | 实现方案、使用说明和正式记录 | 保留 |
| 项目 `docs/reports/` | 结论报告、精选验收摘要及必要配图 | 保留，原始数据不得写入此处 |
| 项目 `repro/` | 可复现示例、配置和必要的历史源码快照 | 保留源码；运行输出按具体目录排除 |
| 运行 `reports/`、已确认的实验 `results/` | 采集与分析流水、原始证据、部署回传 | 排除 |
| 混有脚本的 `evidence/`、`diagnostics/` | 历史诊断工具及原始观测 | 保留工具，按具体路径排除原始数据 |
| `output*/`、`remote_output*/` | 轨迹、采集会话及其元数据 | 排除 |
| 根目录 `_local/` | 本地归档、迁移备份和一次性工具 | 排除 |

`results` 和 `capture` 也是部分项目的 Python 包名，不能使用同名目录的全局排除规则。正式配置、schema、清单和小型测试样例中的 JSON、JSONL 仍可纳入 Git。

## 报告与证据

各项目的 `docs/reports/README.md` 提供报告导航；`evidence_index.json` 记录原路径、当前路径、迁移方式、大小、原始 SHA-256 和整理后的 SHA-256。

- 结论报告移动到文档区；只调整必要的路径引用。
- 精选验收摘要和配图复制到文档区，原运行目录中的内容保留，运行程序继续使用原路径。
- 原始 MCAP、图像和点云、逐帧状态、完整日志、资源采样及性能数据库不随报告上传。
- 完整原始画廊等本地证据在正文中明确标为本地材料；不将其当作已上传附件。
- 报告记录的是各自历史版本的结果，目录整理不代表在当前环境重新验证了全部实验。

现有资产、纹理和采集图片的排除规则继续生效。文档区仅放行精选 PNG/JPEG/SVG 配图，不自动放行模型和整个数据集。
