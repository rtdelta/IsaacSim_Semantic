# 自有挖掘机与 CET200 对比

本报告依据 2026-09-16 对云端文件的只读检查。未启动仿真、未修改资产或场景。

比较对象：

- 自有资产：`/root/gpufree-data/IsaacSim_Asset/excavator_module_set/Sim_Fangshan_02/Excavator_Fangshan_05_origin03.usda`
- 自有组合场景：`/root/gpufree-data/IsaacSim_Asset/combine_stage/combine_scene_11_origin03.usda`
- CET200：`/root/gpufree-data/IsaacSim_Asset/excavator_module_set/CET200/usd/CET200.usda`

必须区分资产、场景和运行脚本。自有资产本身不包含 13 个雷达；雷达安装在组合场景中，TF 与 MCAP 流程由配套脚本完成。CET200 此处指已经部署的 USD，不代表上游 AGX 应用的全部能力。

## 1. 定位与外观

| 项目 | 自有 05_origin03 | CET200 已部署版 |
|---|---|---|
| 来源 | 自有挖掘机扫描部件，按原有 URDF 角度规则重新组织 | 上游虚构 20 吨级工程挖掘机模型 |
| 主要显示方式 | 3DGS；15 个高斯部件，397,747 个高斯中心 | 传统多边形网格和材质；约 30 万可见顶点 |
| 视觉特点 | 带真实采集的颜色、标识、污渍和表面细节；有重建模糊和不规则边缘 | 表面与轮廓规整，但材质单调，液压部件等可见细节不足 |
| 外观与工程结构关系 | 可见液压缸/杆不等于存在独立液压执行器和闭环运动约束 | USD 中也未迁移上游 AGX 液压系统 |
| 可选显示 | 3dgs、source_mesh、URDF 对比与叠加 | 当前为导入的网格显示；Physics variants 不等同于视觉模式 |
| 当前选择 | 独立资产默认 overlay_urdf，组合场景覆盖为 3dgs | Physics 默认 physx |
| 真实机器一致性 | 采集外观与真实设备有关，但尺寸、销轴和坐标系仍需实测标定 | 工程参数较齐，但不是目标真实设备的数字副本 |

视觉真实、几何准确、动力学准确是不同指标，不能互相替代。

## 2. 几何与缩放

自有资产的 5 个部件都相对于原 03 几何等比放大 2.4 倍；CET200 按源 URDF 的米制 1:1 导入。二者入口 Xform 的 Scale 均应为 1。这不意味着自有整机是 CET200 的 2.4 倍，因为源几何基准不同。

05 保留的是原 URDF 的角度规则，关节安装平移来自缩放后的自有销轴数据，因此其所有尺寸并不等于最初的原 URDF。

| 姿态无关的尺寸 | 自有 05_origin03 | CET200 | 自有相对 CET200 |
|---|---:|---:|---:|
| 动臂两端销轴中心距 | 5.750906 m | 5.694385 m | +0.056521 m，约 +0.99% |
| 斗杆两端销轴中心距 | 2.921876 m | 2.900000 m | +0.021876 m，约 +0.75% |

CET200 动臂长度由 `sqrt(4.71397² + 3.19445²)` 计算，不能把其 X 分量 4.71397 m 当作真实销轴间距。

整机长宽高会随姿态改变；两个资产的 q=0 不是同一机械姿态，因此需要先统一姿态才能比较整机包围盒。上述长度接近也不代表上车宽度、安装偏置、铲斗形状或工作包络相同。

## 3. 原点、坐标系和层级

两者均采用米制、Z 向上。

| 项目 | 自有 05_origin03 | CET200 |
|---|---|---|
| 默认根节点 | `/Excavator` | `/CET200` |
| 底座刚体 | `/Excavator/track_prim` | `/CET200/Geometry/TF_Origin` |
| articulation 根 | `/Excavator/track_prim` | `/CET200/Geometry` |
| 原点语义 | 恢复原 03 履带原点的语义，撤销 2.4 缩放后与原 03 一致 | 采用上游 TF_Origin；未定义为自有 03 的同一实测点 |
| USD 几何层级 | 5 个刚体通常同级，由关节连接 | 下游刚体在 Geometry 中递归嵌套，关节集中于 Physics |
| 独立资产底座固定 | 不带世界固定关节，由组合场景/脚本控制 | 资产内有 root_joint 固定底座 |

回转关节中心在各自底座坐标系中的位置：

- 自有：`(-0.058161, -0.034142, 0.420904) m`。
- CET200：`(0, 0, 1) m`。

上述数值的原点不同，不能直接据此判定哪台机器的实际回转台高出多少。

动臂根部销轴在各自上车 link 中的位置：

- 自有：`(0.187004, -0.546694, 0.981823) m`。
- CET200：`(0.18, 0, 0.83) m`。

自有模型保留约 0.547 m 的侧向安装偏置，CET200 此项为 0；这会改变传感器、机身与臂机构之间的相对几何关系。

## 4. 关节、零位和正方向

| 项目 | 自有 05_origin03 | CET200 |
|---|---|---|
| 刚体数 | 5 | 27 |
| 转动关节数 | 4 | 26 |
| 四个主要关节 | swing、boom、arm、bucket | Hinge_Slew、Hinge_Boom、Hinge_Arm、Hinge_Bucket |
| 额外运动结构 | 履带整体作为底盘部件 | 增加左右驱动轮、导向轮和支重轮等 22 个轮系关节 |
| 完整履带链 | 未建模 | 当前 URDF/USD 也未建模；固定带体外观不等于履带板链 |

两台机底盘 XYZ 方向对齐、零位下：

- 自有回转轴为底盘 +Z。三个臂关节局部 axis 属性为 +Z，经 joint origin 的 Rx(1.5707 rad) 后，在底盘中约为 `(0, -0.999999995, 0.000096327)`，即近似 -Y。
- CET200 回转为 +Z，三个臂关节为 +Y。

因此回转正方向相同，臂关节正方向近似相反；比较必须包含关节安装旋转，不能只看 axis 字符。

零位也不同：

- 自有动臂和斗杆的销轴连线在 q=0 下都朝 +X 水平伸展。
- CET200 在 q=0 下，动臂销轴连线相对水平约上仰 34.124°，斗杆销轴连线约向下 90.012°。
- 自有组合场景另设初始角度 `[0, 38, -106, -5.874158]°`；这不是独立资产的全零姿态。CET200 预览使用全零姿态。

同一组四关节数值不能直接互换；映射需要考虑轴向符号、零位偏置、父子坐标系和铲斗参考定义。不同安装尺寸也会使相同姿态对应不同末端位置。

| USD 中的关节位置限位 | 自有 | CET200 |
|---|---|---|
| 回转 | 无有限角度上下界 | 连续旋转 |
| 动臂 | 无有限角度上下界 | -25.382° 至 64.572° |
| 斗杆 | 无有限角度上下界 | -80.214° 至 37.128° |
| 铲斗 | 无有限角度上下界 | -70.818° 至 101.414° |

自有表中的“无限位”指 USD 物理关节字段，软件控制层可以另外规定范围。CET200 的限位也不能原样套到自有模型，否则零位/符号差异会导致错误。

## 5. 质量、惯量、驱动与碰撞

| 项目 | 自有 | CET200 当前部署 |
|---|---|---|
| 显式质量 | 5 个刚体各 1 kg，总计 5 kg，占位值 | 来自源 URDF，总计 16,016 kg |
| 惯量 | 每个刚体 diagonalInertia=(1,1,1)，占位值 | 按部件提供质心和惯性张量，导入为主惯量与主轴 |
| 主要关节驱动 | force；stiffness=10000，damping=200，maxForce=100000 | acceleration；stiffness=1000，damping=100，maxForce=∞ |
| 刚体重力 | 5 个刚体均 disableGravity=true | 资产按宿主场景重力；预览 PhysicsScene 重力为 0 |
| 碰撞体 | 该独立资产当前没有 CollisionAPI 碰撞体 | 23 个：铲斗凸包 + 22 个轮系圆柱 |
| 完整整机接触 | 未实现 | 上车、动臂、斗杆、履带架和带体等未补齐 |
| 液压与土壤 | 未实现 | 未从上游 AGX 迁移 |

两套驱动类型和刚体质量不同，不能直接凭 stiffness 数字大小比较“力度”。它们目前都用于姿态/关节检查，未校准真实液压力。

CET200 的“20 吨级”是上游模型定位；当前 URDF 显式质量之和实际为 16.016 t。不能把其标称吨级当作本次 USD 已具备完整 20 t 质量分配的证据。

视觉网格、RTX 雷达射线求交与 PhysX 接触碰撞不是同一个能力。“没有 CollisionAPI”不等于“雷达完全扫不到”，但不能依靠当前自有资产完成物理接触防碰撞验证。视觉逼真也不能直接证明雷达量程、反射强度与遮挡准确。

## 6. 雷达、TF、业务链路

自有组合场景已安装 13 个雷达（6 个 NZ3 + 7 个 OS0），以及动臂相机。配套脚本启用自动节点发现，发布关节和姿态，组织 ROS 2 / MCAP 数据。

当前业务 TF 约定为：

```text
world
└── swing_horizontal_coordinate
    └── swing_coordinate
        └── 各雷达坐标系
```

`swing_coordinate` 按既定近似跟随底盘，水平坐标系与其同原点并保留水平航向。TF 层级不等于 USD 传感器安装层级；实际雷达安装在 cab 等具体节点下。

CET200 部署只有资产与预览场景，未安装这 13 个雷达，也没有现成的同名业务 TF 和采集流程。替换到现有流程需要：

1. 映射 articulation 路径与四个主要关节名字。
2. 转换零位、正方向与允许角度范围。
3. 明确业务 swing 参考点如何落在新底座上。
4. 根据新几何重新校核传感器安装位姿与遮挡。
5. 调整固定底座策略；当前 CET200 资产内含 root_joint，自有场景锚点的组织方式不同。

不能仅替换 Payload 文件路径就认为整条业务链路保持等价。

## 7. 文件依赖与运行代价

本次检查到的资产依赖文件合计：自有约 250.48 MB，CET200 约 1.56 MB。CET200 的 STEP、GLB、Git 源仓库未计入此处，因为它们不是 USD 打开时的运行依赖。

自有资产有较多高斯数据；CET200 有更多刚体、关节、网格实例与材质实例。因此文件大小只能说明存储依赖，不能直接说明帧率、显存或 CPU 代价。本次没有做同场景、同视角、同传感器设置的性能对照测试。

额外发现：自有扫描 Mesh 依赖 `waji_mesh_corrected.usdc` 中有一个无法解析的 HDR 路径：`.\textures\color_121212.hdr`。这不代表 3DGS 主体缺失；本次仅记录，未修改。

## 8. 对当前项目的判断

自有模型更贴合当前真实设备外观、现有传感器安装和业务数据链。CET200 的长处是工程源资料、部件分解、质量惯量和关节限位较完整，适合对照学习。

现阶段最有价值的方向是保留自有资产，补全可追溯的尺寸/销轴标定、关节安全范围、碰撞几何和物理参数；CET200 可以作为组织方法的参考，其具体数值不能未经校核直接覆盖自有机器。

依据文件：`comparison_raw.json`、`comparison_pipeline.txt`、`geometry_audit.json`、`validation_report.json`，以及 `../20260916_origin03_horizontal/kinematics_origin03.json`。
