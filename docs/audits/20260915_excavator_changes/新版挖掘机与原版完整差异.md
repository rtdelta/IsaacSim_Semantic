# 原版与新版挖掘机的完整差异

核对日期：2026-09-15。原版指 `Excavator_Fangshan_03 + combine_scene_08`；当前新版指 `Excavator_Fangshan_05 + combine_scene_11`。04 和 Stage 10 是中间版本。本次读取磁盘 USD、制作记录及采集代码，没有启动物理仿真或修改云端资产。GUI 中未保存的会话修改不在此磁盘比较内。

## 1. 版本与文件职责

| 版本 | 作用 |
|---|---|
| 03 | 原分件扫描资产和原有人工设置的关节 |
| 04 | 按 URDF 重建坐标系、零位、转轴、正方向和关节安装尺寸；扫描几何按部件、按方向配准缩放 |
| 05 | 按后续要求将原扫描几何统一放大 2.4 倍；保留 URDF 角度规则，安装平移改为放大后的扫描铰点 |
| Stage 10 | 以 Stage 08 为基础装入 05，迁移传感器、设置折臂初始姿态并整理输出管线 |
| Stage 11 | 从 Stage 10 派生，环境尺寸及环境物体间距放大 2.5 倍，Cube、挖掘机和传感器不随之放大 |

各版为独立新文件，原始 03 未被覆盖。05 后来增加了 URDF 叠加显示，修改前的 05、说明和验收记录保存在其 `05_data/overlay/backup_20260914T082819Z/`。

04/05 独立资产 defaultPrim 为 `/Excavator`，场景中引用为 `/Excavator_Fangshan_05`。资产可通过 Payload 加载，不依赖 `.sh`、Python 启动脚本或运行回调。独立资产不含 PhysicsScene、世界固定关节、相机、灯光或传感器输出管线，这些由预览场景或 combine 场景提供。03 内原有的两个 RenderProduct 定义没有带入新资产。

05 继续通过相对路径引用 `3dgs_usd`、`waji_mesh_corrected.usdc` 和 `Excavator_Fangshan_05_data`；搬迁不能只复制主 USDA，也不需要依赖 04 主文件。原有 NVIDIA 在线资产依赖没有全部改成离线依赖。

## 2. 部件原点与几何安装

原版五个刚体在保存的初始姿态下原点均为资产根中的 `(0,0,0)`。扫描几何自带的部件位置和关节 localPos 决定外观与铰接位置。

新版把 cab、boom、arm、bucket 原点分别放到连接其父部件的关节中心，再在 Visuals 下对几何作平移、旋转和缩放配准。原点移动与几何补偿是配套修改，不能只移动刚体原点。

下表是独立 05 四关节全零时的原点，均以各版资产根为参照，单位米。Stage 11 的折臂姿态另见第 6 项。

| 部件 | 原版原点 | 05 零位原点 |
|---|---|---|
| track_prim | (0,0,0) | (0,0,0) |
| cab_prim | (0,0,0) | (0,0,0.525903702) |
| boom_prim | (0,0,0) | (0.187003689,-0.546694413,1.507726812) |
| arm_prim | (0,0,0) | (5.937909933,-0.546694413,1.507726812) |
| bucket_prim | (0,0,0) | (8.859785819,-0.546694413,1.507726812) |

05 base 的 XY 基准对准回转轴，Z 沿用构建时的底盘高斯中心包围盒高度基准，不是地面基准。05 根 Z=0 不等于履带着地。

原版 cab/track 初始原点重合，但共同原点不在原关节实际转轴上，回转会使 cab 原点绕轴移动。05 的 cab 原点就是 swing 中心，回转时在 track 中始终保持 `(0,0,0.5259037)`，只改变方向。

五个部件仍在 USD 根下并列；运动学链通过关节 body0/body1 表达，没有把目录强制嵌套成 track/cab/boom/arm/bucket。

## 3. 关节名称、零位、转轴与限位

| 原关节名 | 新关节名 | 父 → 子 | 03 本体限位 / 度 | Stage 08 限位 / 度 | 新版 |
|---|---|---|---|---|---|
| track_operator_cab_joint | swing | track → cab | -180～180 | -180～180 | 无有限限位 |
| platform_boom_joint | boom | cab → boom | -35～70 | -170～170 | 无有限限位 |
| boom_small_arm_joint | arm | boom → arm | -80～70 | -170～170 | 无有限限位 |
| small_arm_bucket_joint | bucket | arm → bucket | -90～80 | -170～170 | 无有限限位 |

原关节局部 `physics:axis=X`，实际方向还要乘以 localRot0。新版局部正轴统一为 +Z，安装旋转按 URDF 定义。以下方向都表达在各版零位的资产根坐标中：

| 关节 | 原版实际正轴（约） | 新版零位实际正轴（约） |
|---|---|---|
| swing | (0.006190,0.064814,-0.997878) | (0,0,1) |
| boom | (0.087395,0.993531,0.072514) | (0,-0.999999995,0.000096327) |
| arm | (0.036032,0.993399,0.108907) | (0,-0.999999995,0.000096327) |
| bucket | (-0.067632,-0.996426,-0.050616) | (0,-0.999999995,0.000096327) |

这同时改变了旧回转轴的倾斜、后三轴的非平行关系及正方向。旧 swing 大致向 -Z，新版为 +Z；旧 boom/arm 大致向 +Y，新版零位约向 -Y。不能只改关节名称或统一对旧角度取负，就认为旧轨迹兼容。

新版 q=0 时，大臂和小臂的销轴连线沿 +X；扫描外形本身仍可能弯曲。boom 安装 roll 保留 URDF 原值 1.5707 rad，没有取整成精确 π/2。正角遵守局部正轴右手规则。

原 URDF 四关节均为 continuous，因此新版使用无有限限位的 RevoluteJoint，没有照搬 URDF 反置的 lower/upper 或零 effort/velocity。这不代表真实挖掘机没有机械止挡。

新版子侧关节帧为 localPos1=(0,0,0)、localRot1=identity，子 link 原点直接对应关节中心；父侧帧使用下面的安装参数。

## 4. URDF 尺寸、04 尺寸与当前 05 尺寸

| 关节 | 04 / 原 URDF 在父 link 中的 xyz / m | 05 在父 link 中的 xyz / m |
|---|---|---|
| swing | (0,0,0.6) | (0,0,0.525903702) |
| boom | (0.53,0,0.77) | (0.187003689,-0.546694413,0.981823111) |
| arm | (5.715,0,0) | (5.750906244,0,0) |
| bucket | (2.95,0,0) | (2.921875886,0,0) |

05 大臂轴心距来自原扫描 2.396210935 m × 2.4，小臂来自 1.217448286 m × 2.4。平台到大臂约 -0.546694 m 的侧向偏移来自原铰点，没有强制归零。

04 曾使用的几何倍率为：底盘 (2.211002,2.550158,1.946645)、平台 (1.745227,1.872521,1.024989)、大臂 (2.385015,1.624461,0.678465)、小臂 (2.423101,2.413326,0.381046)、铲斗和斗齿 (1.828379,1.986555,1.980027)。臂的方向以销轴局部坐标定义。

05 按后续要求把这一方案替换成原始 03 几何的统一 (2.4,2.4,2.4)，不是在 04 倍率上再乘 2.4。因此当前 05 保留 URDF 角度约定，但不再具有原 URDF 的完整运动学尺寸。末端位置、逆运动学和工作范围必须使用 `kinematics_05.json`。

## 5. 几何、显示模式与保留内容

每个刚体下新增 Visuals/GS、Visuals/Mesh，承载几何的平移、旋转和 2.4 倍缩放。根、刚体和传感器本体保持单位缩放。增加 base_link、swing_link、boom_link、arm_link、bucket_link 的显示名和 URDF 对应信息。

原 15 个 GS 分件继续使用：底盘、平台/驾驶室、大臂、小臂、铲斗壳体和 10 个斗齿。斗齿与壳体共用变换，原始相对位置保留。原高斯数据、颜色、透明度文件未改写，高斯中心间距和椭球尺寸通过父变换一起缩放。原油缸、连杆仍是扫描件中的刚性几何，没有新增伸缩或闭环机构。

| visualization | 内容 |
|---|---|
| 3dgs | 05 正常扫描外观 |
| source_mesh | 05 配准后的扫描 Mesh，含辅助分件颜色 |
| urdf_reference | 原米制 URDF 单部件挂到 05 link 上，作部件标尺 |
| urdf_original | 原始尺寸、安装关系和 q=0 姿态的完整 URDF |
| overlay_urdf | 05 与原 URDF 在共同 base 下叠加，附关节点与连线 |

05 主资产当前默认 overlay_urdf；Stage 10/11 显式选择 3dgs，并停用该模式下的 Mesh、URDFReference、URDFOverlay，避免参考几何参与测距。叠加模式将高斯 opacity 乘以 0.08；切回 3dgs 恢复原值，原始高斯文件不变。原 URDF 叠加体与对比标记是静态零位参考，不会自动跟随 05 的运行时关节。

## 6. 场景摆放和折臂初始姿态

独立 05 默认关节目标全为 0。Stage 10/11 另外保存 `[swing,boom,arm,bucket]=[0,38,-106,-5.874158]` 度。这是场景初始姿态，不是重新定义零点。

同时写入刚体初始变换、Angular Drive 目标、PhysicsJointStateAPI 初始角度，减少点击 Play 后姿态跳变。折臂姿态参考原外观，并抬高大臂为栏杆留出间隙。

整机世界位置由 Stage 08 的 `(-1.158813,1.580568075,0.218755592)` 改为 `(-1.183046738,1.566342156,0.525280709)` m。XY 对齐旧回转轴位置；Z 以世界网格 Z=0 和履带高斯中心最低处加 2 cm 作预览摆放，未做地形接触或实机标定。根旋转仍为单位旋转，根缩放仍为 1。

## 7. 传感器的全部迁移规则

数量保持 13 个雷达（6 个 MyNZ3、7 个 MyOS0）和 1 个大臂相机。根前缀 03 改为 05；13 雷达仍直接挂 cab_prim，相机仍直接挂 boom_prim，设备内部子节点层级保留。

12 个普通雷达及相机按所属部件的几何配准变换更新挂载位置、朝向；设备本体不放大。MyOS0_up 按明确要求原样保留相对 cab 的挂载位姿、字段精度和操作顺序，不做位置放大或重新定向。其位置仍为 `(-1.180720806,-1.300093822,8.032114189)` m，内部 sensor 的 Z=0.03622 m 偏移也保留。

扫描 profile、量程、扫描参数、相机内参、原外壳显隐和内部光学偏移按制作记录保持，原相机画面滚转保留。本次逐项检查确认 Stage 10 和 Stage 11 的 14 个设备挂载字段完全一致。

全部设备新旧位置、姿态四元数、xform 顺序与路径见本目录 `sensor_mounts_actual.json`，四元数顺序为 xyzw。挂载节点位姿与其内部 sensor 的最终光学位姿要区分。

## 9. 物理属性与驱动

新版新增四个预览 Angular Drive：stiffness=10000、damping=200、maxForce=100000、type=force、targetVelocity=0。03/Stage 08 四关节没有这些 Drive 定义。独立 05 目标角全零，场景目标角为上述折臂姿态。

质量、惯量、质心继续是预览占位值，没有实机校准。保持禁用重力的意图；相连刚体的 joint collisionEnabled=false 保留。部分旧文件中显式写入的默认速度、密度、睡眠等属性被省略。原点变化后，保留相同的 centerOfMass 数值不代表保留相同的真实质心位置。

没有建立经过验证的整机接触碰撞体、液压模型或随 2.4 倍缩放校准的质量惯量。渲染可见、雷达有回波与 PhysX 接触碰撞是不同功能。

## 10. Stage 11 环境修改

Stage 10 继承 Stage 08 环境摆放。Stage 11 以 `C=(-1.183046738,1.566342156,0)` m 为中心，应用 `p11=C+2.5×(p10−C)`，同时放大环境物体尺寸和到中心的距离。

作用于 `/environment_Fangshan_02`、`/FlatGrid/Environment`、`/FlatGrid/GroundPlane`。环境根新平移为 `(1.372031058,-0.538554393,2.737092749)` m，原旋转不变；两个地面组平移为 `(1.774570107,-2.349513234,0)` m。可视有限地面由 100×100 m 变为 250×250 m；无限碰撞平面仍位于 Z=0。

Cube 保持 1 m 及原位姿；挖掘机和设备没有再乘 2.5，几何倍率仍为 2.4。环境内 DomeLight 添加逆向补偿变换以维持原世界位姿，光照参数和其他灯不变。总览相机后移，传感器安装及相机内参不变。原隐藏/停用内容保留状态，网格材质、纹理与环境源顶点未改写。

## 11. 后续 ROS/MCAP 采集脚本与资产本体的区别

ROS 功能由 LidarVisualizer 在匿名会话层创建，不是 05/Stage 11 自带的持久 ROS 功能：

- `/LidarVisualizer`：时钟、TF、点云和状态发布相关运行图。
- `/LidarVisualizerFrames/excavator_root`：本次配置下对应资产根基准、随底盘运动的参考节点。
- `/tf`：world→excavator_root，以及 excavator_root→13 雷达；没有完整发布 cab/boom/arm/bucket 的 link TF 树。
- `/joint_states`：swing/boom/arm/bucket 原生 DOF 角度，单位 rad；速度与力矩数组未发布。
- `/excavator/root_pose`：根相对 world 的位置和四元数。
- `/clock` 与 `/lidar/<设备名>/points`：仿真时间和 SENSOR 坐标中的 XYZ 点云。

脚本接管雷达时，在会话层暂停对应持久 RenderProduct 初始化节点并停用相应场景产品，创建自己的产品以避免重复。脚本控制模式还临时禁用世界底座固定关节、抑制 Drive 力并直接写状态。移除会话层后恢复磁盘定义，并没有永久删除 BaseAnchor。

复制 USD 不会自动录 MCAP；复制 MCAP 可以离线读取点云、TF 和角度，但其中没有完整挖掘机网格、3DGS 或运动学模型。

## 12. 对旧代码和三维查看器的影响

1. 更新机器人根路径、关节名、设备路径；只替换 03 为 05 不足以兼容旧轨迹。
2. 使用新版零位、正轴、安装旋转和 05 安装平移，不能直接使用原 URDF 长度。
3. 旧雷达相对共同原点的安装数字不能原样填到新 link 坐标系，采用新挂载矩阵或对应时刻的 TF。
4. 点云世界位置用 `T_world_from_root(t) × T_root_from_sensor(t) × p_sensor`。已使用完整 root→sensor TF 后，不要再额外乘一次 swing 旋转。
5. 绘制机器人各部件时，另用四关节角度与 05 运动学链计算 link 位姿；MCAP 没有完整 link TF 树。
6. 根位姿、几何倍率和安装偏移各应用一次，避免重复平移或重复放大。

## 13. 核对证据与范围

本次直接核对 03/04/05、Stage 08/10/11 的磁盘定义、部件原点、关节参数、实际正轴、路径、文件哈希，以及 14 个设备的安装字段。当前 05、Stage 10、Stage 11 主文件哈希与制作时最终验收记录一致；03/04 当前哈希与 05 构建时的记录一致。
