# 可直接交给制作人员或 agent 的任务模板

请按同目录 `SPEC.md` 的挖掘机资产接口规范 v1.0 制作资产，并使用 `asset_manifest.template.json` 记录实际接口。

## 本次输入（下发任务时填写）

- 型号/asset_id：待填写。
- 输入模型、单位、版本及权威尺寸/关节资料：待填写。
- 所需外观：Mesh / 3DGS / 两者；默认展示选项：待填写。
- 运行 profile：prescribed_motion / dynamic_drive。
- 原点 policy：新推荐基准 / 明确声明的 legacy 基准。
- 要兼容的脚本及精确版本：待填写，不能只写“所有脚本”。
- 传感器型号、安装槽及坐标资料：待填写；无传感器则写空清单。
- 输出目录和资产版本：待填写。

## 执行约束

1. 先识别资料中缺失/冲突的尺度、原点、关节轴、零位、符号和限位。把未知值列出来；不能根据截图、名字或旧型号参数默补。
2. 独立输出一个新版本。先确定 `track → cab → boom → arm → bucket` 机构与两侧关节帧，再配准各部件外观。
3. 五刚体同级，关节存入 Joints；不要用嵌套变换代替 articulation 关系。修改结构时同时更新所有引用目标。
4. 单独定义数学零位、合法 home 和任务 operating 范围；不要把某次演示的 ±15°写成机械限位。
5. 保留有出处的原始精度，如 1.5707 rad 不能擅自改成 π/2。单位/四元数顺序/矩阵方向按规范显式转换。
6. 给出每个关节实际 +δ 的方向证据；先声明测试范围和误差阈值再执行。
7. 将主资产、预览场景、combine 场景和运行 Session 覆盖分开。主资产不得依靠启动脚本修补才能加载。
8. 逐一核对实际组合的 Mesh/GS、物理、传感器外参及数据坐标。原点相同不代表射线发射原点或逐射线偏移相同。
9. 执行所有适用的 ACCEPTANCE 条目，保留原始日志和结果。未测项目明确标记，不能把推断写成测试通过。
10. 交付入口文件、完整依赖与哈希、实际清单、构建来源、验收报告、变更说明和使用方式；说明哪项能力需适配现有代码。

## 最终交付说明的固定格式

```text
资产身份：asset_id / asset_version / spec_version
主入口：
依赖方式：self_contained 或 shared_tree
机构：刚体清单 / 关节清单 / articulation root
坐标：base 原点 / 轴向 / 原点版本 / 单位
角度：零位 / 正向 / home / 物理限位 / 软件范围 / 单位
外观：默认 variant / 注册变换 / 已知近似
物理：prescribed 或 dynamic / 占位参数与标定范围
传感器：槽位 / 父刚体 / 型号 / 外参 / 发射坐标约定
兼容：每个消费者的版本、适配配置和实测状态
验收：通过、失败、未测、不适用条目及证据
限制：当前不能保证的能力
迁移：与旧版本的原点、路径、角度或 TF 变更
```
