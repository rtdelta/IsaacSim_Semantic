# 260730_01ThresholdFilter 完整逻辑规则 v02

## 1. 文档目的

本文档定义 `260730_01ThresholdFilter` 后续修正所依据的完整业务逻辑。

从本版本开始：

- 原“斗齿集合框”统一称为“斗齿碰撞模型框”；
- 遮挡判断和斗齿姿态判断使用相互独立的指标；
- 所有按斗齿数量进行的统计固定以五颗物理斗齿为基数；
- 单齿框使用 `a、c、d` 三类阈值；
- 斗齿碰撞模型框同时考虑遮挡状态和收起状态；
- 斗齿碰撞模型框使用 `full_scene` 与 `excavator_only` 的混合几何信息生成。

本文档只定义逻辑，不代表当前代码已经全部实现。

---

## 2. 名词与数据源

### 2.1 五颗物理斗齿

系统固定处理以下五颗斗齿，顺序不可随某一帧实际存在的 YOLO 框数量变化：

```text
teeth_01_front_3DGS
teeth_02_front_3DGS
teeth_03_front_3DGS
teeth_04_front_3DGS
teeth_05_front_3DGS
```

最新 PostProcess 单齿 YOLO class ID 与物理斗齿的映射为：

```text
0 -> teeth_01_front_3DGS
1 -> teeth_02_front_3DGS
2 -> teeth_03_front_3DGS
3 -> teeth_04_front_3DGS
4 -> teeth_05_front_3DGS
```

过滤器后续应使用显式 `class_id_map`，不再以旧的
`legacy_zero_class_order` 作为最新数据的正式配置。

### 2.2 `full_scene`

`full_scene` 表示包含土石、场景物体及其他外部遮挡物的实际采集场景。

它提供：

- 实际训练使用的 RGB 图片；
- 每颗斗齿在外部遮挡后的语义像素数；
- 已有的单齿 YOLO 框；
- 斗齿碰撞模型框长度方向的可见边界。

### 2.3 `excavator_only`

`excavator_only` 表示相同帧、相同相机和相同挖掘机姿态下，去除外部遮挡物后的参考场景。

它提供：

- 每颗斗齿理论上可见的参考语义像素数；
- 排除外部遮挡影响后的斗齿轮廓；
- 框内目标像素占比；
- 斗齿旋转框长宽比；
- 斗齿旋转方向角；
- 斗齿碰撞模型框宽度方向的完整参考边界。

## 3. 基本数据定义

对于第 `f` 帧、第 `i` 颗斗齿，定义：

```text
W[f, i]
    = full_scene 中该斗齿的语义像素数

R[f, i]
    = excavator_only 中该斗齿的语义像素数

V[f, i]
    = 该斗齿的显露比例
```

显露比例计算为：

```text
当 R[f, i] > 0 时：
    V[f, i] = W[f, i] / R[f, i]

当 R[f, i] == 0 时：
    V[f, i] = -1
```

`V=-1` 是参考数据缺失的哨兵值，不是真实比例。报告中还必须保留：

```text
ratio_status = reference_missing
```

`-1` 不得参与平均值、中位数等正常比例统计。

## 4. 四个核心阈值

### 4.1 阈值 `a`：单齿遮挡显露比例阈值

用于判断单个斗齿在外部遮挡情况下是否保留已有 YOLO 框。

```text
V[f, i] < a  -> 遮挡条件不合格
V[f, i] >= a -> 遮挡条件合格
```

### 4.2 阈值 `b`：碰撞模型框遮挡显露比例阈值

用于判断每颗斗齿是否应计入斗齿碰撞模型框的低显露数量。

```text
V[f, i] < b  -> 该斗齿计为一个低显露斗齿
V[f, i] >= b -> 该斗齿不计入低显露数量
```

`a` 和 `b` 服务于不同的输出对象，不要求取值相同，也不要求存在固定的大小关系。

### 4.3 阈值 `c`：参考框内目标像素占比阈值

`c` 用于判断斗齿是否因铲斗收起、侧转或只露边缘而不适合作为检测目标。

该指标只使用 `excavator_only` 语义轮廓计算，避免把外部遮挡误判为斗齿收起。

对斗齿参考语义轮廓计算最小旋转外接矩形，定义：

```text
C[f, i]
    = R[f, i] / 旋转外接矩形面积
```

判断规则：

```text
C[f, i] < c  -> 姿态条件不合格
C[f, i] >= c -> 姿态条件合格
```

当参考语义轮廓不存在、旋转框无法计算或 `R[f, i] == 0` 时：

```text
C[f, i] = -1
```

并判定该斗齿的姿态条件不合格。

### 4.4 阈值 `d`：参考旋转框长宽比阈值

为了避免实际相机旋转 90°后图像水平轴和竖直轴与仿真场景相反，不直接使用普通轴对齐 YOLO 框的 `width / height`。

对 `excavator_only` 中的斗齿语义轮廓计算最小旋转外接矩形，定义：

```text
long_side[f, i]
    = 旋转框长边

short_side[f, i]
    = 旋转框短边

D[f, i]
    = long_side[f, i] / short_side[f, i]

Theta[f, i]
    = 旋转框方向角
```

判断规则：

```text
D[f, i] < d  -> 姿态条件不合格
D[f, i] >= d -> 姿态条件合格
```

相机旋转 90°会改变 `Theta`，但原则上不会改变 `D`，因此 `D` 比图像轴对齐框的宽高比更稳定。

`Theta` 在 v02 中先作为分析和报告字段，不直接作为硬过滤阈值。待真实数据明确正常角度范围后，再决定是否增加独立角度规则。

当参考旋转框无法计算时：

```text
D[f, i] = -1
```

并判定该斗齿的姿态条件不合格。

## 5. 固定五齿基数规则

任何斗齿数量统计都必须固定遍历五颗物理斗齿。

例如某帧只有四个单齿 YOLO 框：

```text
实际存在的单齿 YOLO 框数量 = 4
斗齿碰撞模型框判断基数   = 5
```

第五颗斗齿即使因为遮挡严重、语义像素过少或轮廓残缺而没有生成单齿 YOLO 框，它的 `V、C、D` 仍必须参与碰撞模型框判断。

禁止使用以下做法：

- 只遍历当前存在的 YOLO 行；
- 将当前 YOLO 框数量作为统计基数；
- 因缺少某颗单齿框而把五齿规则自动改为四齿规则；
- 使用最终保留下来的单齿框数量代替五颗物理斗齿的指标统计。

单齿 class ID 独立为 `0～4` 后，应直接通过 class ID 判断哪颗斗齿存在、哪颗缺失。

## 6. 单个斗齿框过滤规则

对每颗斗齿独立计算：

```text
V[f, i] -> 遮挡显露比例
C[f, i] -> 参考旋转框内目标像素占比
D[f, i] -> 参考旋转框长边/短边比例
```

单齿框保留条件为：

```text
single_keep[f, i]
    = full_scene 中原始单齿 YOLO 框存在
      且 V[f, i] >= a
      且 C[f, i] >= c
      且 D[f, i] >= d
```

等价删除条件为：

```text
single_drop[f, i]
    = V[f, i] < a
      或 C[f, i] < c
      或 D[f, i] < d
```

规则说明：

- `a、c、d` 只要任意一个不满足，就删除已有单齿框；
- 比例等于阈值时保留；
- `V、C、D` 中任意一个为 `-1` 时，对应条件必然不合格；
- 上游不存在单齿框时，过滤器不得补造；
- 保留时继续使用 `full_scene` 中已有的单齿 YOLO 框坐标；
- 单齿框是否存在不影响该斗齿参与五齿碰撞模型框统计。

## 7. 斗齿碰撞模型框过滤规则

斗齿碰撞模型框同时执行遮挡多数判断和姿态多数判断。

### 7.1 遮挡不合格数量

固定遍历五颗斗齿：

```text
occlusion_bad[f, i]
    = V[f, i] < b
```

```text
occlusion_bad_count[f]
    = 五颗斗齿中 occlusion_bad[f, i] 为真的数量
```

其中：

- `V == b` 不计入低显露数量；
- `V == -1` 必然计入低显露数量；
- 不论该斗齿有没有单齿 YOLO 框，都要参与统计；
- 不使用聚合的 `tooth_front_group` 像素比例；
- 不使用经过 `a、c、d` 过滤后的单齿框数量代替此统计。

### 7.2 姿态不合格数量

每颗斗齿的姿态状态定义为：

```text
pose_bad[f, i]
    = C[f, i] < c
      或 D[f, i] < d
```

固定遍历五颗斗齿：

```text
pose_bad_count[f]
    = 五颗斗齿中 pose_bad[f, i] 为真的数量
```

使用三颗多数规则，可以避免单颗语义轮廓噪声直接删除整个碰撞模型框，同时保证铲斗整体收起时不输出碰撞模型框。

### 7.3 最终删除条件

```text
collision_drop[f]
    = occlusion_bad_count[f] >= 3
      或 pose_bad_count[f] >= 3
```

保留条件为：

```text
collision_keep[f]
    = occlusion_bad_count[f] < 3
      且 pose_bad_count[f] < 3
      且混合框几何可以有效生成
```

因此：

- 三颗或更多斗齿遮挡不合格时，删除斗齿碰撞模型框；
- 三颗或更多斗齿姿态不合格时，删除斗齿碰撞模型框；
- 铲斗整体收起时，即使五颗斗齿均未被外部物体遮挡，也不保留斗齿碰撞模型框；
- 上游或参考数据无法提供有效混合框几何时，不得生成无效框。

## 8. 斗齿碰撞模型框的混合几何规则

### 8.1 规范坐标系

后续实际相机会旋转 90°拍摄，因此不能直接把图像的 `x/y` 或水平/竖直方向称为业务上的长度和宽度。

先定义与相机画面旋转无关的规范轴：

```text
L 轴
    = 五颗斗齿的排列和跨度方向
    = 斗齿碰撞模型框的长度方向

W 轴
    = 与 L 轴垂直的斗齿伸出方向
    = 斗齿碰撞模型框的宽度方向
```

处理时应：

1. 根据相机旋转方向，将 `full_scene` 和 `excavator_only` 几何转换到同一个规范坐标系；
2. 在规范坐标系内生成混合框；
3. 将混合框转换回实际图像坐标；
4. 最终写出与 `full_scene RGB` 对齐的普通轴对齐 YOLO 框。

相机旋转配置必须明确记录是顺时针 90°还是逆时针 90°，不得根据单帧坐标自动猜测。

### 8.2 长度方向

长度方向使用 `full_scene` 中五颗斗齿当前可见语义区域的整体并集：

```text
L_min = full_scene 中所有有效斗齿可见区域在 L 轴上的最小边界
L_max = full_scene 中所有有效斗齿可见区域在 L 轴上的最大边界
```

长度边界反映实际完整场景中的当前可见跨度。

### 8.3 宽度方向

宽度方向使用 `excavator_only` 中五颗斗齿完整参考语义区域的整体并集：

```text
W_min = excavator_only 中所有有效斗齿参考区域在 W 轴上的最小边界
W_max = excavator_only 中所有有效斗齿参考区域在 W 轴上的最大边界
```

宽度边界排除外部遮挡影响，使用相同姿态下的完整参考轮廓。

### 8.4 混合框

规范坐标系中的斗齿碰撞模型框为：

```text
[L_min(full_scene), L_max(full_scene)]
    ×
[W_min(excavator_only), W_max(excavator_only)]
```

采用边界混合而不是只混合标量长度和宽度，可以同时确定框尺寸和框中心，避免框的位置来源不明确。

### 8.5 使用五齿整体并集

混合框两个方向的边界均以所有有效斗齿区域为候选，不再只依赖画面最左和最右两个端部斗齿框的上下边界。

原因是中间斗齿可能比两个端部斗齿更向上或向下突出。只使用两个端部框可能无法完整覆盖中间斗齿。

## 9. 图片与标注坐标来源

最终输出的图像和标注来源必须明确解耦：

### 9.1 单齿输出

```text
图片：
    full_scene RGB

单齿框坐标：
    full_scene 中已有的单齿 YOLO 框

过滤指标：
    V 来自 full_scene / excavator_only
    C、D、Theta 来自 excavator_only
```

### 9.2 斗齿碰撞模型框输出

```text
图片：
    full_scene RGB

长度方向：
    full_scene

宽度方向：
    excavator_only

遮挡判断：
    五颗斗齿的 V 与 b

姿态判断：
    五颗斗齿的 C、D 与 c、d
```

不得因为碰撞模型框使用了 `excavator_only` 的参考宽度，就把最终训练图片替换为 `excavator_only RGB`。

## 10. `-1` 哨兵值处理

### 10.1 显露比例

```text
R == 0 -> V = -1
```

业务含义：

- 单齿遮挡条件不合格；
- 在碰撞模型框判断中计入一个低显露斗齿；
- 报告状态记录为 `reference_missing`；
- 不参与正常比例汇总统计。

### 10.2 姿态指标

当参考语义轮廓或旋转框无法得到时：

```text
C = -1
D = -1
```

业务含义：

- 单齿姿态条件不合格；
- 在碰撞模型框姿态判断中计入一个姿态不合格斗齿；
- 报告中记录具体的缺失原因；
- 不参与正常 `C、D` 分布统计。

### 10.3 比较约束

正式配置中的 `a、b、c、d` 必须为非负数。逻辑中应显式识别 `-1` 和状态字段，不应只依赖普通浮点比较来解释异常。

## 11. 每帧完整处理顺序

对每一帧执行：

```text
1. 严格对齐 full_scene、excavator_only、PixelRatio 和 YOLO 的 frame ID

2. 固定加载五颗物理斗齿的身份

3. 对每颗斗齿计算 W、R、V

4. 从 excavator_only 参考语义轮廓计算：
   - 旋转外接矩形
   - C
   - D
   - Theta

5. 对每个已有 full_scene 单齿框应用：
   - V >= a
   - C >= c
   - D >= d

6. 固定以五颗斗齿统计：
   - occlusion_bad_count
   - pose_bad_count

7. 判断斗齿碰撞模型框是否允许输出：
   - occlusion_bad_count < 3
   - pose_bad_count < 3

8. 若允许输出，生成混合框：
   - 长度边界来自 full_scene 五齿可见区域并集
   - 宽度边界来自 excavator_only 五齿参考区域并集

9. 将混合框从规范坐标系转换回实际旋转后的图像坐标

10. 输出：
    - full_scene RGB
    - 过滤后的单齿 YOLO 标注
    - 过滤并重新生成的斗齿碰撞模型 YOLO 标注
    - 逐齿指标、逐框决定、异常及汇总报告
```

## 12. 数学汇总

### 12.1 单齿

```text
single_keep[f, i]
    = source_box_exists[f, i]
      AND V[f, i] >= a
      AND C[f, i] >= c
      AND D[f, i] >= d
```

### 12.2 碰撞模型框遮挡状态

```text
occlusion_bad_count[f]
    = SUM(I(V[f, i] < b)), i = 1..5
```

### 12.3 碰撞模型框姿态状态

```text
pose_bad_count[f]
    = SUM(I(C[f, i] < c OR D[f, i] < d)), i = 1..5
```

### 12.4 碰撞模型框最终状态

```text
collision_keep[f]
    = occlusion_bad_count[f] < 3
      AND pose_bad_count[f] < 3
      AND mixed_geometry_valid[f]
```

### 12.5 碰撞模型框几何

```text
collision_box[f]
    = FullSceneVisibleUnionLengthBounds[f]
      × ExcavatorOnlyReferenceUnionWidthBounds[f]
```

## 13. 配置与输入契约要求

后续实现至少需要在配置和输入契约中表达：

- 最新五颗斗齿 semantic label；
- `0～4` 的 class ID 映射；
- `full_scene` PostProcess 输出；
- `excavator_only` PostProcess 或参考几何输出；
- SemanticPixelRatio 输出；
- 阈值 `a、b、c、d`；
- 碰撞模型框遮挡不合格数量阈值，当前为 `3`；
- 碰撞模型框姿态不合格数量阈值，当前为 `3`；
- 相机旋转角度和顺/逆时针方向；
- `-1` 与 `reference_missing` 的处理规则；
- 旋转框几何或参考 semantic mask 的来源。

三个项目的目标 label、顺序、semantic mapping、frame ID 和数据源路径必须严格一致。

## 14. 当前仍需通过数据标定的参数

以下参数不能仅靠逻辑推导，需要使用真实采集样本统计后确定：

- 单齿遮挡阈值 `a`；
- 碰撞模型框遮挡阈值 `b`；
- 参考框像素占比阈值 `c`；
- 参考旋转框长宽比阈值 `d`；
- 正常 `Theta` 的分布范围；
- 相机旋转是顺时针 90°还是逆时针 90°；
- `D=long_side/short_side` 在真实“收起到打开”过程中是否保持预期的单调趋势。

在设置正式阈值前，应至少覆盖以下样本：

- 完全打开；
- 正常工作角度；
- 逐渐收起；
- 完全收起、只露边缘；
- 单颗遮挡；
- 两颗遮挡；
- 三颗遮挡；
- 端部斗齿被遮挡；
- 中间斗齿比端部更突出；
- 铲斗和小臂张开到未采集过的远角度。

如果真实数据证明 `D=long_side/short_side` 与收起程度不呈预期关系，应重新定义并重命名该指标，不允许只通过反转比较符号而隐藏指标语义变化。

## 15. v02 最终规则摘要

```text
1. 所有统计固定以五颗物理斗齿为基数。

2. V = full_scene_pixels / excavator_only_pixels。
```
