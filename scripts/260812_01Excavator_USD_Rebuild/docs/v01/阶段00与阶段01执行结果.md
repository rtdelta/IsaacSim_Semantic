## 1. 执行范围

## 2. 运行环境与 Gaussian 转换结论

远端环境：

- Isaac Sim：`6.0.1-rc.7`；
- Kit：`110.1.2`；
- Gaussian 转换扩展：`omni.kit.converter.gsplat 0.1.14`；
- 写出 Schema：`ParticleField3DGaussianSplat`；
- 粒子 Schema 插件：`usdParticleField`，已正确注册并加载。

以 `tooth_01_back.ply` 的 211 个 Gaussian 做最小转换试验，转换和重新打开 USD 均成功：

- 输入 211 个 Splat；
- 输出 211 个 `positions`、`scales`、`orientations` 和 `opacities`；
- 输出三阶 SH，共 `211 × 16 = 3376` 个 `float3` 系数；
- 输出 Stage 为 Z-up、`metersPerUnit = 1.0`；
- 输出默认 Prim 类型为 `ParticleField3DGaussianSplat`。

因此，正式构建器可以直接调用 Isaac Sim 内置 `usd_convert_gsplat` API，不必依赖 UI 导入操作。当前推荐使用 `run_usd_python_remote.sh` 提供的独立 USD 运行时，以避免启动完整 Kit。

## 4. Mesh 输入清单

输入文件：

```text
/root/gpufree-data/stage_material_set/excavator_module_set/
sim_Fangshan_01/mechanic_parts_set/mesh_parts/拆分成五部分的mesh.usd
```

扫描结果：

- Mesh Prim：`/World/mesh_`；
- 顶点数：317,675；
- 三角面数：628,868；
- face-vertex index 数：1,886,604；
- subdivision scheme：`none`；
- orientation：`rightHanded`；
- 材质：`/World/Looks/material`；
- 连通分量：3,892；
- 前五大分量顶点数：114,475、99,820、57,195、23,661、18,288；
- 前五大分量合计覆盖 98.67% 顶点；
- 单顶点分量：3,861。

这说明 Mesh 不是五个独立 Prim，但存在五个明显的大型主体分量和大量零散小分量。实现时必须以完整连通分量为分类单位，并结合对应 Link 的 Gaussian 参考点云决定归属；不能逐顶点切面。

### Mesh 单位元数据注意事项

Mesh Stage 写有 Y-up 和 `metersPerUnit = 0.01`，但其数值坐标包围盒与 PLY 的米级数值包围盒几乎完全重合：六个边界的差异绝对值均不超过约 2.24 cm。如果机械地乘以 `0.01`，Mesh 将缩小 100 倍并与 3DGS 不重合。

因此候选配置暂时设置：

```json
"units_to_meters": 1.0
```

其含义是按 Mesh 数值坐标直接和 PLY 对齐，不采用源 Layer 中疑似错误的厘米元数据。该判断需要用户确认，并应在阶段 3 用点云—Mesh 距离统计再次验证。

## 5. 旧 USD 的使用边界

旧文件：

```text
/root/gpufree-data/stage_material_set/excavator_module_set/
sim_Fangshan_01/Excavator_Fangshan_01.usda
```

阶段 1 最初只把旧 USD 用作参考；后续只读诊断确认当前组合 Mesh 与旧五部件 Mesh 的 317,675 个顶点多重集合完全相同，当前 15 个 PLY 与旧 15 个 3DGS positions 逐点同源，旧四个 Joint 的两端中心和轴也内部自洽。因此实施方案修订为：旧 Joint 旋转线可以作为本次旧模型转新模型的权威初值，但只能通过独立工具执行一次性迁移。

一次性迁移读取：

- 五 Link 和四 Revolute Joint 的历史命名；
- Joint 的 body 顺序；
- 历史关节限位；
- 15 个 Gaussian 的语义标签；
- 历史 Joint 的 localPos/localRot、轴 token 和 Link Xform；
- 旧 Mesh/3DGS 子 Prim 的公共视觉变换。

迁移过程不能原样复制旧 localPos/localRot，而应：恢复旧世界 `center/axis`，反解旧视觉公共变换，换算到当前源 Mesh 数值坐标，再用 Mesh 铰接结构验证。确认后的结果写入新 `joint_calibration.json`。

该操作仅用于这一次 Fangshan 旧模型转新模型。新标定文件固化后：

- 正常构建器、重复构建和部署不读取旧 USD；
- 新主配置和最终 USD 不引用旧路径或旧 Prim；
- 标定缺失时构建失败，不自动回退到旧模型；
- Mesh 拟合用于验证迁移旋转线，只有超阈值 Joint 才进入人工复核或重新标定。

## 7. 候选配置中需要确认的事项

进入正式构建前，需要确认：

1. 15 个 PLY 到五个 Link 的候选归属是否接受；
2. 是否沿用旧模型的 15 个语义标签；
3. 四个 Joint 的拓扑、body 顺序、轴方向、零位和历史限位是否作为新配置的迁移约定；
4. 是否接受 Mesh 按数值坐标采用 `units_to_meters = 1.0`；
5. 根路径 `/Excavator` 和 Link/Joint 候选命名是否接受。

四个关节中心和轴采用“一次性旧 Joint 旋转线迁移 + Mesh 几何验证”产生，不再默认要求四组全部重新拟合。迁移数值、验证差异和轴正负方向仍需在写入正式标定文件前确认。
