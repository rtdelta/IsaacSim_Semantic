# 配置关系与校验规则

本文补充说明配置对象之间如何关联、如何解析成 USD Prim，以及构建器应执行哪些前置校验。它是 `配置参数说明.md` 的实现约束补充。

## 1. 对象关系

配置的中心对象是 Link。Mesh 和 Gaussian 归属于 Link，Joint 连接两个 Link。

```text
Gaussian part ─┐
               ├─ link_id ─> Link（RigidBody）<─ body0/body1 ─ Joint
Mesh part ─────┘
```

例如：

```text
boom_gaussian ─ link_id=boom ─┐
                              ├─ /Excavator/Links/boom
boom_mesh ───── link_id=boom ─┘

cab_boom_joint.body1 = link:boom
→ 直接解析为 /Excavator/Links/boom
→ 写入 physics:body1
```

因此可视 Mesh 可以隐藏、替换或重新拆分，而 Joint 始终连接稳定的刚体 Link Xform。Fangshan 正式配置要求 body 直接引用 Link；`mesh_part` 间接解析只作为通用协议兼容能力。

## 2. 完整 Prim 路径生成

### Link

```text
full_link_path = stage.root_prim_path + "/" + links[].prim_path
```

示例：

```text
/Excavator + Links/boom
→ /Excavator/Links/boom
```

### Gaussian 或 Mesh

```text
full_part_path = full_link_path + "/" + part.relative_prim_path
```

示例：

```text
/Excavator/Links/boom + Visual/Mesh/boom
→ /Excavator/Links/boom/Visual/Mesh/boom
```

### Joint

```text
full_joint_path = stage.root_prim_path + "/" + joints[].prim_path
```

在拼接前后必须进行 USD Prim 路径合法性校验，禁止 `..`、空段、非法标识符和重复斜杠。

## 3. Joint body 解析

### `reference_type=link`（Fangshan 推荐且正式使用）

解析顺序：

1. 用 `reference_id` 查找唯一且启用的 `links[]`；
2. 生成 Link 完整 Prim 路径；
3. 检查目标 Prim 类型为 Xform 或兼容的 Xformable 容器；
4. 检查该 Link Xform 应用并启用 RigidBodyAPI；
5. 将该 Link Xform 路径写入 Joint relationship。

最终 `physics:body0/body1` 必须指向 Link Xform，不得指向其下的 `Visual`、Mesh 或 Gaussian Prim。

### `reference_type=mesh_part`（兼容模式）

解析顺序：

1. 用 `reference_id` 查找唯一且启用的 `mesh.parts[]`；
2. 读取该 Mesh 的 `link_id`；
3. 查找唯一且启用的 `links[]`；
4. 生成 Link 完整 Prim 路径；
5. 检查 Link 开启 RigidBody；
6. 将此 Link 路径写入 Joint relationship。

任一步失败都必须停止，不允许退回到名称模糊匹配。

### `reference_type=prim_path`

使用 `prim_path` 中的绝对路径。该模式面向外部刚体，配置静态校验只能检查路径语法；加载目标 Stage 后还必须确认 Prim 存在并具有 RigidBodyAPI。

### `reference_type=world`

表示 Joint 的一端连接世界。只有 FixedJoint 或构建器明确支持世界端的类型才能使用。普通浮动式四个 RevoluteJoint 不应使用 `world`。

### body0/body1 与验证 Mesh 的一致性

标定记录中的 `selection.source_mesh_part_ids` 不再承担 body 解析，而是声明迁移结果由哪些 Mesh 部件验证。例如 `cab_boom_joint` 的两个 body 直接引用 `cab`、`boom` Link，验证 Mesh 应分别归属于这两个 Link。顺序可以不同，但集合必须一致；否则严格模式报错。

## 4. 默认值和覆盖规则

### Gaussian

```text
最终 units_to_meters =
  parts[].units_to_meters_override 非 null
  ? override
  : gaussian.defaults.units_to_meters
```

`visibility_override` 使用同样规则。

### Mesh

`visibility_override`、`purpose_override` 和 `create_collision_override` 非空时覆盖 `mesh.defaults`；否则继承默认值。

### Link 物理属性

1. 读取 `links[].physics_profile` 指定的模板；
2. 深度合并 `links[].physics_overrides`；
3. 对合并结果执行数值和逻辑校验；
4. 把最终值写入 `resolved_build_config.json`。

未知 override 字段应报错，避免拼写错误被静默忽略。

### Joint 几何

Fangshan 的正式标定文件由一次性旧 Joint 迁移和 Mesh 验证产生。正常构建只执行以下读取与转换规则，不读取旧 USD。

#### `source=calibration_file`

1. 读取 `calibration_id` 对应记录；
2. 以标定 `center`、`axis` 为基础值；
3. 用非空 `center_override`、`axis_override` 分别覆盖；
4. 归一化轴；
5. 乘以 `axis_sign`；
6. 应用公共坐标变换；
7. 根据 body0/body1 当前初始世界变换，计算两端 LocalPos 和 LocalRot。

#### `source=explicit`

必须提供非空的 `center_override` 和 `axis_override`，不读取标定记录。

### `axis_sign`

`axis_sign` 只能为 `1` 或 `-1`。它不改变几何关节线，但会改变关节角的正方向。若翻转轴，需要同步核查上下限和既有轨迹角度约定，构建器不能自行猜测是否要交换或取反限位。

## 5. 坐标变换规则

所有几何和关节必须使用同一个刚性变换：

```text
p_new = R × (s × p_source - origin) + offset
axis_new = normalize(R × axis_source)
```

其中：

- `s` 是输入对象的 `units_to_meters`；
- `origin` 是履带 OBB 中心或配置指定原点；
- `R` 是自动估计或显式给出的公共旋转；
- `offset` 是 `origin.offset_m`；
- 平移不作用于关节轴。

3DGS 除 position 外，还要正确旋转 Gaussian orientation；scale、opacity 和 SH 属性按其数学定义处理，不能把 PLY 当普通点云只改 XYZ。

Mesh 要同时转换点坐标、法线和可能依赖方向的 Primvar，并保持拓扑与插值方式。

## 6. Mesh 拆分规则

当前默认源是一个组合 Mesh，目标是得到任意数量的逻辑 Mesh 部件。

推荐步骤：

1. 读取完整顶点、面和 Primvar；
2. 以面连接关系计算连通分量；
3. 对每个连通分量分别计算到各 `mesh.parts[].reference_gaussian_part_ids` 联合点云的距离；
4. 将整个分量分给一个逻辑 Mesh，而不是逐顶点拆分；
5. 对输出顶点和面索引重新编号；
6. 同步重映射 vertex、varying、faceVarying、uniform 插值数据；
7. 校验每个源面恰好进入一个输出部件；
8. 输出分类统计、歧义分量和最大距离。

当 `fail_on_ambiguous_component=true` 时，不能为了完成构建而任意选择候选；必须报告分量信息并由用户修订参考配置或显式分配。

Fangshan 的 31 个有面连通分量中有 14 个在当前 Gaussian 距离阈值下属于歧义分量。由于旧五部件 Mesh 与当前组合 Mesh 的顶点 multiset 完全一致，本次一次性迁移使用旧 Link Mesh 的精确顶点归属生成 `mesh_component_assignment_file`。正常构建只读取这份固化映射并校验源 Mesh SHA-256、Prim、点/面数及每个分量的面/点指纹，不再读取旧 USD，也不再对歧义分量猜测。

## 7. 结构校验

### ID 和引用

- `links[].id` 唯一；
- `gaussian.parts[].id` 唯一；
- `mesh.sources[].id` 唯一；
- `mesh.parts[].id` 唯一；
- `joints[].id` 唯一；
- 每个启用引用只能解析到一个启用对象；
- 禁止依靠数组顺序、文件名相似度或部分字符串匹配补全引用。

### Prim 路径

- `root_prim_path` 和 `default_prim_path` 必须是合法绝对路径；
- Link、部件和 Joint 的最终完整路径必须唯一；
- 部件 Prim 必须位于其 Link Prim 之下；
- Joint Prim 不能位于任何 RigidBody 子树中，建议统一位于根下 `Joints`；
- 不允许输出覆盖输入文件。

### articulation 图

把启用 Link 当作节点，把启用 Joint 当作边：

- `chain`：图连通、无环、无分支；单 Link 特例没有 Joint；
- `tree`：图连通、无环，允许分支；
- `any_connected`：只要求连通。

每个 RevoluteJoint 的 body0 和 body1 不得解析到同一 Link。重复连接同一对 Link 应产生错误或明确警告。

### 浮动和固定模式

| 模式 | 要求 |
|---|---|
| `floating` | `fixed_base.enabled=false`；根 Link 为启用非运动学刚体；无世界固定关节 |
| `fixed` | `fixed_base.enabled=true`；固定 Joint body 能解析到有效 Link |

### 物理最小属性

采集占位 profile 仍必须满足：

- RigidBody 启用；
- `kinematic_enabled=false`；
- mass 为有限正数；
- diagonal inertia 三项均为有限正数；
- Joint 轴非零并归一化；
- 启用限位时 lower、upper 有限且 lower ≤ upper；
- 当前直接关节位置采集配置不创建 Angular Drive。

碰撞体、真实质量、真实重心和真实惯量不属于 v01 采集模型的必需输入。报告应明确列出使用占位物理属性的 Link。

## 8. 关节标定校验

每个从标定文件读取的 Joint 应检查：

1. 标定 ID 唯一且存在；
2. `center` 是三个有限数；
3. `axis` 是三个有限数且长度大于最小阈值；
4. 标定坐标系名称与主配置一致；
5. 源 Mesh ID、源文件和 Prim 路径与主配置一致；
6. 如提供 SHA-256，当前输入文件摘要必须匹配；
7. `provenance` 能说明几何来源；Fangshan 迁移结果应记录旧输入摘要、迁移工具、旧世界旋转线、旧视觉逆变换和人工确认状态；
8. 如使用 Mesh 圆弧/轴孔验证，选点数量、圆和平面误差、迁移中心距离和轴夹角应满足阈值；没有使用的拟合字段允许为空，但必须说明验证方式；
9. 两个 source Mesh 所属 Link 与 body0/body1 集合一致；
10. `axis_sign`、零位和限位由旧运动约定迁移并经人工确认，不能只凭圆弧拟合自动决定；
11. 旧 USD 不得成为正式构建输入；迁移结果固化后，即使旧 USD 不可访问，本节校验仍应通过。

### 一次性迁移规则

一次性迁移工具独立于正常 pipeline，处理链固定为：

```text
旧 localPos/localRot + 旧 Link Xform
→ 旧世界 center/axis
→ 反解旧视觉子 Prim 公共变换
→ 当前源 PLY/Mesh 数值坐标 center/axis
→ Mesh 几何验证
→ 新 joint_calibration.json
```

禁止把旧 `localPos0/1`、`localRot0/1` 原样写入新标定文件。迁移工具只能显式运行，不能在 `center/axis` 缺失时由构建器自动触发。确认后的新标定文件是长期输入，旧 USD 路径不得写入正式主配置、最终 USD 或正常构建报告；迁移证据报告可以保存旧文件摘要和当时的诊断路径。

## 9. 配置解析输出

`resolved_build_config.json` 建议至少增加以下派生字段：

- 所有输入和输出的规范化绝对路径；
- 每个 Link 的完整 Prim 路径；
- 每个 Mesh/Gaussian 的完整 Prim 路径；
- 每个 Joint body0/body1 最终 Link ID 和完整 Prim 路径；
- 每个部件继承后的最终默认值；
- 最终单位比例、原点、旋转矩阵及其求解依据；
- 转换后的关节中心、轴、LocalPos0/1、LocalRot0/1；
- 输入文件摘要；
- 构建器版本和时间。

解析输出用于审计和复现，不应被构建器反向当作下一次构建的唯一源配置，除非以后明确设计锁定配置格式。

## 10. 构建阶段

建议 `stop_after_phase` 支持以下阶段名：

| 阶段 | 工作内容 |
|---|---|
| `config` | 读取、合并、路径解析、引用解析、静态校验 |
| `inspect_inputs` | 检查 PLY Schema、Mesh 拓扑、单位和包围盒 |
| `coordinates` | 求公共原点和旋转矩阵 |
| `gaussian` | 转换 Gaussian 数据和属性 |
| `mesh` | 拆分、转换并写 Mesh |
| `joints` | 读取标定、转换关节并计算局部 Joint frame |
| `compose` | 组合视觉、物理、语义和入口 Stage |
| `validate` | 执行 USD、articulation、语义和对齐校验 |

`dry_run=true` 至少应完成 `config`，在输入读取安全可行时也可执行只读 `inspect_inputs`，但不得写正式 USD。

## 11. 错误、警告和禁止猜测

### 必须报错

- 必需输入文件不存在；
- ID 或最终 Prim 路径重复；
- 部件引用不存在或指向禁用对象；
- Joint body 无法解析到刚体 Link；
- 标定中心或轴缺失；
- 单位比例非正或坐标矩阵非法；
- Mesh 分量未分配或分类歧义且相应 fail 开关开启；
- articulation 图不满足配置拓扑；
- 输出目标位于输入路径或超出解析后的输出目录约束。

### 可以警告

- Mesh 与 Gaussian 包围盒差异较大但未设置强制阈值；
- 标定文件未保存源摘要；
- 使用占位质量和惯量；
- Mesh 完全隐藏且未创建碰撞体，因此只作为重建和标定参考；
- `disable_gravity=true`，资产适合直接根位姿控制而非真实自由落体。

### 不允许静默猜测

- PLY 文件顺序与 Link 对应关系；
- Joint body0/body1；
- 关节轴正方向、零位和限位；
- Mesh 数值单位；
- 多个同名或近似 Prim 中的目标 Prim；
- 歧义 Mesh 连通分量的归属。

这些信息缺失时，构建器必须输出具体字段路径和修正建议，等待用户补充配置。

- 增加“旧 USD 不可访问时正式构建仍必须通过”的独立性校验。
