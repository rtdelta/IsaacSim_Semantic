## 2. 已实现模块

### 2.1 候选配置生成与严格校验

- `tools/generate_fangshan_candidate.py`：根据远端真实输入生成候选配置；Joint body 直接映射到 Link。
- `tools/validate_candidate_config.py`：校验输入路径、数量、ID 引用、Link 链、Joint body、标定完整性和一次性迁移边界。
- 正式候选配置的静态校验结果为 `ready_for_formal_build=true`，错误、警告和阻塞项均为空。

### 2.2 一次性 Joint 数据迁移

`tools/migrate_fangshan_joint_frames.py` 只用于本次旧模型转新模型：

1. 读取旧 USD 的 Link 变换和四条 Joint 旋转线；
2. 去除旧公共视觉变换，把 Joint 中心和轴还原到当前原始 PLY/Mesh 数值坐标；
3. 用旧五部件 Mesh 与当前组合 Mesh 的顶点全集做一致性检查；
4. 用当前 PLY 与旧 Gaussian 点做变换拟合检查；
5. 将结果固化到新的 `joint_calibration.json`。

迁移验证结果：

- Mesh 顶点数：`317675`；最大逐点差：`0 m`；
- Gaussian 点数：`397747`；最大拟合误差：约 `7.39e-16 m`；
- 迁移结果标记为 `one_time_operation=true`、`normal_build_dependency=false`。

因此，正常构建不读取旧 `Excavator_Fangshan_01.usda`。旧 USD 路径只保留在标定文件的来源追溯信息中，不是生产依赖。

### 2.3 正式 USD 构建器

`tools/build_excavator_usd.py` 已实现：

- 读取主配置和固化后的 Joint 标定；
- 根据 PCA 和配置的方向判定建立公共坐标变换；
- 将履带 OBB 几何中心移动到目标原点；
- 转换参数化数量的 3DGS PLY；
- 保持 Gaussian 局部 `positions`、`orientations`、球谐和其他辐射属性不变，在组合入口 Prim 上统一写公共变换；
- 读取组合 Mesh，按连通分量和对应 Gaussian 几何自动归类为五个 Link Mesh；
- 对 Fangshan 的 31 个有面连通分量读取一次性迁移时固化的精确归属；14 个 Gaussian 距离歧义分量不做猜测；
- 构建五个刚体 Link Xform 和四个直接连接 Link 的 RevoluteJoint；
- 构建 floating articulation，不创建世界固定关节；
- 根据配置为五个 Link 写入 `RigidBodyAPI`、`MassAPI`、`PhysxRigidBodyAPI` 和 `disableGravity=true`；
- 实际应用 Gaussian/Mesh 的 `units_to_meters`、visibility 和 purpose 配置；
- Mesh 默认作为隐藏 proxy，避免与 3DGS 重叠显示；
- 分别生成 `excavator_visual.usda`、`excavator_physics.usda`、入口 `excavator_floating.usda` 和显示 Mesh 的 `excavator_debug.usda`；
- 以临时目录构建，全部验证通过后才原子替换正式输出；失败不会破坏上一版产物。

## 5. 运行时验收阻塞

运行时验证脚本为 `tools/validate_excavator_runtime.py`。在执行它之前，先运行了完全不加载资产的 `tools/probe_simulation_app.py`。

探针使用：

- headless；
- `multi_gpu=false`；
- `disable_viewport_updates=true`；
- 不导入、不引用、不打开生成 USD。

远端 Isaac Sim 6.0.1 仍在启动第三个扩展 `omni.kit.async_engine-0.0.3` 时退出，进程退出码为 `139`；回溯位于 Python 3.12 `_asyncio` 和 Kit 扩展启动原生层。GPU 驱动可访问、显存空闲，且未发现其他 Kit 进程。因此现有证据只说明运行环境无法启动，不能归因于本资产。

证据文件：

- `analysis/stage02/fangshan_runtime_validation.blocked.json`
- 远端日志：`/root/isaacsim/kit/logs/Kit/Isaac-Sim Python/6.0/kit_20260812_181233.log`

## 6. 下一阶段目标

阶段 03 的入口条件是最小 `SimulationApp` 探针能够打印 `SIMULATION_APP_STARTED` 并正常退出。满足后按以下顺序继续：

1. 在 Isaac Sim 中加载 `excavator_floating.usda`；
2. 验证 3DGS schema、语义 API 和所有 payload；
3. 建立临时 PhysicsScene，确认 articulation 和四条 RevoluteJoint 被 PhysX 正确解析；
4. 执行短时间步进，验证无固定根、无意外下落、Joint position 可读取；
5. 人工检查坐标朝向、3DGS 外观、五个 Mesh 归属以及四个旋转轴；
6. 再对 Joint 限位和正方向做业务确认，并接入调整后的 recorder/semantic world module。

当前配置中的质量和惯量仍是采集用途占位值，不能用于真实动力学结论。碰撞体没有构建，相机也没有构建；这与本阶段约定一致。

v01 尚未实现的碰撞生成、Joint Drive、非零初始 Joint 位置、资产内 PhysicsScene、多 Mesh 源等能力，构建器会显式报错，不会静默忽略对应配置。
