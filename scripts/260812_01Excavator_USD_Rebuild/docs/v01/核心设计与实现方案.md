# 挖掘机 USD 重建项目：核心设计与实现方案 v01

## 1. 文档目的

本文定义 `260812_01Excavator_USD_Rebuild` 项目 v01 的工程设计基线，内容包括：

- 项目背景、目标和非目标；
- 已确认的工程决策；
- 核心技术思路和构建数据流；
- 配置、工程代码和 USD 资产的结构层次；
- 模块划分和职责边界；
- 分阶段实施方案；
- 测试、验证和验收标准；
- 已知风险与处理原则。

配置字段的逐项含义见 `配置参数说明.md`，对象引用、覆盖和校验细则见 `配置关系与校验规则.md`。

## 2. 项目背景

现有 Fangshan 挖掘机资产由多份 3D Gaussian Splatting PLY、一个组合 Mesh、若干物理 Link、关节和语义信息组成。旧工具链经过多次人工处理和后续修正，存在以下工程问题：

- 输入、输出路径和 Prim 路径散落在脚本中；
- Link、Joint、Mesh、3DGS 部件数量和命名具有项目特化；
- 坐标转正、Mesh 处理、关节标定和 USD 组装由不同脚本完成；
- 旧 Joint 几何与当前源资产同源，但需要经过一次性坐标迁移和 Mesh 验证后才能成为新模型的独立标定数据；
- 直接复用旧 USD 会形成旧目录和旧 Prim 路径依赖；
- 缺少统一的配置解析、结果审计和自动验证机制。

本项目不继续修改旧资产，而是基于原始 PLY、Mesh 和独立标定数据，构建一套新的、配置驱动的挖掘机 USD 生产工具。旧 USD 只允许在本次 Fangshan 旧模型转新模型时参与一次性 Joint 数据迁移；迁移结果固化后，长期构建链不再读取旧模型。

## 3. 已确认的工程决策

### 3.1 正式执行环境

正式构建脚本运行在远端 Isaac Sim 自带的 Python/Kit 环境中，因为最终流程需要使用 Isaac Sim/Omniverse 提供的 USD、PhysX、语义以及 Gaussian Importer 能力。

配置解析、数学工具和不依赖 Kit 的单元测试应尽量保持为标准 Python 模块，以便本地快速验证；真正写 USD、调用 Isaac Sim 扩展和执行运行时验证的阶段在远端完成。

### 3.2 允许测试 Gaussian PLY Importer

正式实现前允许调用和测试远端 Isaac Sim 当前版本的 Gaussian PLY Importer。必须确认：

- Importer 是否存在稳定的 Python、Kit Command 或扩展调用入口；
- 导入后生成的 Prim 类型和 Schema；
- SH、opacity、scale、rotation 等 PLY 属性如何映射；
- 是否支持批量、无 UI、可重复执行；
- 父 Xform 能否正确影响 Gaussian 渲染；
- 如果必须烘焙变换，orientation 和方向相关 SH 应如何处理。

在试验完成前，不自行假定 NVIDIA Gaussian USD Schema，也不编写未经验证的私有转换逻辑。

### 3.3 实际 PLY 映射先生成候选配置

实施时扫描远端目录：

```text
/root/gpufree-data/stage_material_set/
  excavator_module_set/sim_Fangshan_01/
  mechanic_parts_set/ply_parts/
```

根据文件名、PLY 属性、空间包围盒、旧资产语义和 Link 运动关系，整理候选配置：

- 每个 PLY 的稳定 ID 和真实路径；
- 建议所属 Link；
- 建议 Prim 名称；
- 建议语义标签；
- 用于 Mesh 拆分的 Gaussian 参考关系；
- 映射依据和不确定项。

候选配置只作为讨论稿。用户确认或修改前，不将建议映射作为正式构建事实。

### 3.4 构建范围

v01 构建：

- 任意数量的 3DGS 部件；
- 任意数量的 Mesh Source 和逻辑 Mesh 部件；
- 任意数量的刚体 Link；
- 任意数量的 RevoluteJoint；
- 浮动式 articulation；
- 可配置语义标签；
- 最低限度的采集用物理占位属性；
- 分层 USD、解析配置和验证报告。

相机和其他 Sensor 不属于资产构建范围。

### 3.5 目标坐标系

默认目标坐标系为：

- 原点：履带 OBB 几何中心；
- Local `+X`：挖掘机前方，指向铲斗方向；
- Local `+Z`：挖掘机上方；
- Local `+Y`：由右手系确定的侧方向；
- Stage Up Axis：`Z`；
- Stage 单位：米，`metersPerUnit=1.0`。

参考部件、旋转求解方式、显式矩阵和附加偏移允许通过配置覆盖。

### 3.6 Mesh 策略

尽可能把 Mesh 纳入新资产，但不影响 3DGS 显示：

- 默认 `visibility=invisible`；
- 默认 `purpose=proxy`；
- v01 默认不创建碰撞体；
- Mesh 随所属 Link 运动；
- Mesh 用于关节标定、几何对齐、调试和未来扩展。

### 3.7 关节策略

Fangshan v01 的四条关节旋转线优先复用旧模型中已经建立且内部自洽的 Joint 几何关系，但不直接复制旧 `localPos0/1`、`localRot0/1`。采用以下一次性迁移：

1. 从旧 Joint 的两端局部帧恢复旧模型坐标中的世界 `center` 和 `axis`；
2. 去除旧 Mesh/3DGS 子 Prim 的公共视觉变换，换算到当前原始 PLY/Mesh 数值坐标；
3. 验证旧五部件 Mesh 与当前组合 Mesh 的同源性、旧 3DGS 与当前 PLY 的同源性；
4. 用当前 Mesh 铰接结构检查中心位置和轴线方向；
5. 将确认值写入新 `joint_calibration.json`，记录旧文件摘要、迁移工具版本、坐标变换和误差；
6. 迁移完成后，正常构建器只读取新标定文件，不再读取旧 USD。

该迁移只服务于这一次 Fangshan 旧模型转新模型，不是每次构建阶段，也不是面向其他资产的默认能力。对没有可信旧 Joint 的资产，仍可使用“人工选择 Mesh 圆弧顶点 + 数学拟合”的半自动标定方式。

无论采用旧关系迁移还是 Mesh 拟合，几何本身都不能唯一确定：

- 轴的正负方向；
- 机械零位；
- 允许转动范围；
- 与旧轨迹兼容的角度符号约定。

这些运动约定通过主配置显式提供并记录来源。Fangshan 首次迁移应尽量保持旧 body0/body1 顺序、轴正方向、零位和限位，以兼容既有 Joint position 符号约定。

### 3.8 物理策略

当前采集项目不要求真实动力学，因此 v01：

- 不反演真实质量、重心和惯量；
- 不生成真实碰撞体；
- 不实现液压系统或执行器动力学；
- 不创建 Angular Drive；
- 只写入 articulation 初始化和当前校验所需的正质量、正惯量等占位属性。

占位属性统一标记为 `capture_placeholder`，不得用于真实动力学结论。

### 3.9 浮动模式

v01 默认生成浮动式挖掘机：

- 不创建世界固定关节；
- ArticulationRootAPI 放在配置指定的根刚体 Link；
- Link 为非运动学刚体；
- 根位置和姿态可由采集程序直接设置；
- 采集项目配置需要同步允许 floating base。

## 4. 核心目标

### 4.1 完全配置驱动

Python 源码不得硬编码：

- 输入和输出路径；
- 根 Prim、Default Prim 和节点路径；
- Link、Joint、Mesh、3DGS 数量；
- PLY、Mesh 到 Link 的映射；
- Joint 的 body0/body1；
- 关节中心、轴、方向、限位和零位；
- Mesh 显示、purpose 和碰撞策略；
- 语义标签；
- 物理占位数值；
- USD 分层和输出文件名。

同一套构建器通过更换 JSON 配置适配其他同类挖掘机资产。

### 4.2 新资产独立可用

生产构建不读取、不 sublayer、不 reference 旧 `Excavator_Fangshan_01.usda`。旧资产只在独立迁移命令中读取一次，用于生成新关节标定文件和迁移证据；产物经确认后，迁移命令退出正式依赖图，正常构建不得自动回退到旧 USD。

最终输出目录整体移动后，入口 USD 仍应通过相对路径找到全部子资产。

### 4.3 统一坐标变换

3DGS、Mesh、关节中心和关节轴必须使用同一个源到目标变换。禁止对各类资产分别增加未记录的“目测修正”。

公共变换及求解依据必须写入解析配置和验证报告。

### 4.4 保持 3DGS 信息和效果

构建前后应保证：

- Splat 数量一致；
- Renderer 所需属性完整；
- opacity、scale、rotation 和 SH 不无故丢失；
- 转正后空间外形正确；
- 固定视角 A/B 渲染无不可接受退化；
- 隐藏 Mesh 不遮挡 Gaussian。

### 4.5 正确的 articulation 拓扑

默认实例是：

```text
track → cab → boom → arm → bucket
```

这只是配置实例，不是程序约束。构建器应支持配置声明的 chain 或 tree，并保证 Joint 两端解析到有效刚体 Link。

### 4.6 可审计和可复现

每次构建都必须能够回答：

- 使用了哪些输入文件和摘要；
- 解析了哪些路径和 Prim；
- 各 Gaussian、Mesh 属于哪个 Link；
- Joint body0/body1 最终指向哪个刚体；
- 使用了什么公共坐标变换；
- Mesh 如何拆分，是否存在歧义；
- 关节数据来自哪里；
- 哪些物理属性是占位值；
- 哪些检查通过、警告或失败。

### 4.7 缺少关键数据时停止

构建器不得通过文件顺序、近似名称或空间关系静默补齐以下内容：

- PLY 的 Link 归属；
- Joint body0/body1；
- 关节中心和轴；
- 关节轴正方向、零位和限位；
- Mesh 数值单位；
- 歧义 Mesh 分量归属；
- 冲突的 Prim 路径。

## 5. 非目标与边界

v01 不负责：

- 相机、激光雷达和其他 Sensor；
- 真实碰撞体制作；
- 真实质量、重心、惯量计算；
- 液压和执行器动力学；
- 自动运动规划；
- 无人工介入的关节识别；
- 旧采集项目全部脚本的同步重构；
- 通用机器人描述格式转换；
- 对所有 Isaac Sim 版本提供兼容承诺。

后续需要真实动力学时，应新增独立 physics profile、碰撞层和标定数据，不能在 `capture_placeholder` 上直接叠加未经验证的数值。

## 6. 核心技术思路

### 6.1 配置是用户意图的唯一来源

项目接收两类配置：

```text
build_config.json
├── 路径和 Stage
├── 坐标策略
├── Gaussian / Mesh / Link
├── Articulation / Joint
├── 物理和语义
└── 输出与校验

joint_calibration.json
├── 源 Mesh 和坐标系
├── 关节中心与轴
├── 选点信息
├── 拟合误差
└── 标定来源
```

构建器不得修改源配置，而应输出包含继承值、规范化路径、完整 Prim 和派生结果的 `resolved_build_config.json`。

### 6.2 Link 是结构中心

```text
Gaussian part ─ link_id ─┐
                         ├─ Link / RigidBody
Mesh part ───── link_id ─┘
                              ↑
                              └─ Joint body0/body1（直接引用 Link Xform）
```

Gaussian 和 Mesh 是 Link 下的几何；Joint 的 `physics:body0` 和 `physics:body1` 实际连接带 `RigidBodyAPI` 的 Link Xform。Fangshan 正式配置在配置层也直接引用 Link：

```text
body1 = link:boom
→ links[boom].prim_path = Links/boom
→ /Excavator/Links/boom
→ physics:body1
```

Mesh 部件通过 `link_id` 独立归属 Link，并由关节标定/验证记录的 `source_mesh_part_ids` 指定几何检查对象。这样 Joint 拓扑不依赖 Mesh 是否显示、替换或重新拆分。

通用解析器可以保留 `mesh_part → link_id → Link` 的兼容能力，但它不是 Fangshan 正式配置的推荐形式，解析结果也永远不能把 Joint relationship 写到可视 Mesh Prim。

### 6.3 先解析配置，后处理重型资产

流水线首先完成：

1. JSON 版本、类型和未知字段检查；
2. 默认值继承；
3. 路径规范化；
4. ID 索引；
5. 部件到 Link 的解析；
6. Joint body 到 Link Xform 的解析；
7. 完整 Prim 路径生成；
8. articulation 图检查；
9. 输入输出冲突检查。

配置无效时不打开重型资产、不调用 Importer，也不创建正式输出。

### 6.4 使用唯一公共坐标变换

基本变换为：

```text
p_target = R × (s × p_source - origin) + offset
axis_target = normalize(R × axis_source)
```

其中：

- `s`：输入对象显式配置的单位比例；
- `origin`：履带 OBB 中心或配置指定原点；
- `R`：自动求得或显式输入的公共旋转；
- `offset`：配置的目标偏移。

平移不作用于关节轴。Gaussian orientation、Mesh normal 等方向量必须按照数据定义正确转换。

### 6.5 视觉层与物理层分离

视觉、Mesh 和物理信息分别输出，再由入口 Stage 组合。这样能够：

- 单独检查 3DGS；
- 单独检查 Mesh 拆分；
- 修改关节而不重新导入所有 PLY；
- 替换 Gaussian 而不破坏刚体拓扑；
- 后续增加真实 physics overlay。

### 6.6 一次性迁移、几何验证与 Joint 构建分离

一次性旧 Joint 迁移工具只负责本次 Fangshan 转换：

- 读取旧 Link Xform 和 Joint 局部帧；
- 恢复旧世界关节中心和轴；
- 反解旧视觉子 Prim 公共变换；
- 将旋转线换算到当前源 Mesh 数值坐标；
- 验证旧/新几何同源性；
- 输出带输入摘要、变换和残差的迁移候选标定文件。

Mesh 几何验证工具负责：

- 检查迁移中心是否位于相邻部件铰接区域；
- 检查迁移轴是否穿过对应轴孔或圆弧结构；
- 可选拟合圆弧平面、圆心、法向轴、半径和误差；
- 输出迁移值与拟合值之间的中心距离和轴夹角；
- 对差异超阈值的 Joint 停止并要求人工确认。

USD 构建器负责：

- 只读取已经确认的新 `joint_calibration.json`，不读取旧 USD；
- 应用轴方向约定；
- 应用公共变换；
- 计算两端局部关节帧；
- 写 Joint、限位和初始角。

### 6.7 自动推断必须可解释

允许自动求解的结果必须记录依据：

- OBB 中心和轴；
- PCA 特征值和主方向；
- 前向、上向参考对象；
- Mesh 分量到候选点云的距离；
- Joint 圆和平面拟合误差。

推断出现歧义时停止，由用户补充或修订配置。

## 8. 模块设计

### 8.1 `config`：配置系统

建议文件：

```text
config/
├── models.py
├── loader.py
├── resolver.py
└── validator.py
```

职责：

- 加载 JSON 并检查版本；
- 转换为类型明确的数据模型；
- 合并 Gaussian、Mesh 和 Physics Profile 默认值；
- 解析相对路径和环境变量；
- 建立 ID 索引；
- 生成完整 Prim 路径；
- 解析 Mesh → Link 和 Joint body → Link Xform；Fangshan 正式配置要求 Joint body 直接引用 Link；
- 校验 articulation 图；
- 输出 resolved config。

约束：该模块不依赖 Isaac Sim；严格模式不接受未知字段，不使用数组位置或模糊名称建立关系。

### 8.2 `input`：输入资产检查

建议文件：

```text
input/
├── ply_inspector.py
├── mesh_inspector.py
└── manifest.py
```

职责：

- 扫描远端候选 PLY；
- 读取 PLY Header 和属性 Schema；
- 统计 Splat 数量、包围盒和异常值；
- 检查 Mesh Stage、Prim、顶点、面和 Primvar；
- 计算 Mesh 连通分量；
- 计算输入文件摘要；
- 生成输入清单和 PLY 候选映射报告。

候选阶段可依据文件名和空间位置提出建议，但必须标为未确认，不能直接进入生产配置。

### 8.3 `coordinates`：公共坐标求解

建议文件：

```text
coordinates/
├── obb.py
├── orientation_solver.py
└── transform.py
```

职责：

- 计算履带 OBB 中心；
- 用 PCA 估计主要方向和最薄方向；
- 用铲斗、驾驶室、动臂等参考确定正负方向；
- 生成右手正交旋转矩阵；
- 支持显式矩阵覆盖；
- 转换 point、vector、normal、quaternion 和 Xform；
- 输出坐标诊断数据。

关键校验：矩阵有限、正交、行列式接近 `+1`；履带中心接近原点；铲斗位于 `+X`；上部结构位于 `+Z`。

### 8.4 `gaussian`：3DGS 导入和转换

建议文件：

```text
gaussian/
├── importer.py
├── transformer.py
└── gaussian_validator.py
```

职责：

- 封装远端 Isaac Sim Gaussian Importer；
- 按配置导入任意数量 PLY；
- 记录导入前后属性 Schema；
- 放入指定 Link 和 Prim；
- 应用公共坐标策略；
- 添加语义；
- 写独立 Gaussian USD；
- 校验 Splat 数量和关键属性。

Importer 采用适配器设计，使版本差异集中在一个模块。

#### 必做 A/B 试验

比较两种转正方式：

1. 父 Xform：保持 Gaussian 内部属性不变，用上层 Xform 表达转正；
2. 烘焙：重写 position 和 orientation，并按 Renderer 约定处理方向相关属性。

比较 Splat 数量、属性集合、包围盒、多视角 RGB、透明度、边缘表现、性能和语义输出。试验结果决定 Fangshan 正式配置，不在设计阶段猜测。

### 8.5 `mesh`：Mesh 拆分和写出

建议文件：

```text
mesh/
├── component_splitter.py
├── component_classifier.py
└── mesh_writer.py
```

职责：

1. 读取源顶点、面和 Primvar；
2. 按面连接关系计算连通分量；
3. 为目标 Mesh 合并参考 Gaussian 点集；
4. 计算分量到候选参考点云的距离；
5. 将整个分量分给一个逻辑 Mesh；
6. 对歧义和未分配分量报错；
7. 重建顶点和面索引；
8. 重映射 vertex、varying、uniform、faceVarying 数据；
9. 保留可支持的材质；
10. 应用公共变换并写 USD。

禁止逐顶点分类后直接切面的实现，避免运动部件边界发生拓扑撕裂。

### 8.6 `joints`：关节标定与构建

建议文件：

```text
joints/
├── calibration_loader.py
├── body_resolver.py
├── geometry_validator.py
└── joint_builder.py
```

单独提供 `tools/migrate_fangshan_joint_frames.py`。这是只运行一次的迁移工具，负责：

- 读取明确指定并校验摘要的旧 Fangshan USD；
- 提取旧 Link Xform、Joint body、localPos/localRot 和轴约定；
- 恢复旧模型坐标中的关节世界中心和轴；
- 反解旧视觉子 Prim 公共变换；
- 输出当前源 Mesh 数值坐标中的中心和轴；
- 保存旧/新 Mesh 与 3DGS 同源性检查、变换矩阵和数值残差；
- 生成新标定文件候选，不直接参与正式 USD 构建。

该工具不在 `pipeline.py` 的正常阶段列表中，也不能在标定缺失时被构建器自动调用。迁移产物确认入库后，后续重建不再需要旧 USD。

对迁移结果进行 Mesh 几何验证，或为其他没有可信旧 Joint 的资产标定时，使用 `tools/blender_joint_calibrator.py`：

- 加载源 Mesh；
- 保存人工选择的圆弧顶点；
- 转换到标定坐标系；
- SVD 拟合平面；
- 最小二乘拟合圆心；
- 输出法向轴、半径、覆盖角和误差；
- 可视化中心、轴线和拟合圆；
- 比较迁移旋转线与 Mesh 拟合旋转线；
- 更新关节标定 JSON 的验证结果或生成独立标定结果。

Joint 构建器负责：

- 将 body0/body1 直接解析为带 `RigidBodyAPI` 的 Link Xform；
- 读取或覆盖中心和轴；
- 检查标定/验证 Mesh 与两端 Link 的一致性；
- 应用 `axis_sign` 和公共变换；
- 将 RevoluteJoint Local X 对齐目标轴；
- 根据两端 Link 初始世界矩阵计算 LocalPos0/1、LocalRot0/1；
- 写入限位和初始角；
- 默认不应用 Angular Drive。

### 8.7 `usd`：USD 组装

建议文件：

```text
usd/
├── link_builder.py
├── articulation_builder.py
├── semantic_builder.py
└── layer_composer.py
```

职责：

- 创建根 Prim、Links 和 Joints Scope；
- 创建兄弟 Link Xform；
- 应用 RigidBodyAPI、MassAPI 和占位 profile；
- 创建 RevoluteJoint；
- 在根刚体应用 ArticulationRootAPI；
- 设置 Default Prim、Up Axis、metersPerUnit 和 Model Kind；
- 写入语义；
- 组合视觉、Mesh、物理和入口层；
- 生成相对引用。

可复用资产默认不创建 PhysicsScene。需要独立运行时，额外生成 standalone wrapper，由场景持有 PhysicsScene。

### 8.8 `validation`：验证和报告

建议文件：

```text
validation/
├── stage_validator.py
├── articulation_validator.py
├── visual_validator.py
└── report_writer.py
```

职责：

- Stage 元数据和 Default Prim 检查；
- 资产引用可解析性；
- Prim 路径和 Schema 检查；
- articulation 图检查；
- RigidBody、Mass 和 Joint 属性检查；
- Gaussian 数量和属性检查；
- Mesh 面完整性检查；
- Mesh/3DGS 包围盒和对齐检查；
- 语义标签检查；
- 输出机器可读报告和摘要。

### 8.9 `pipeline`：流程编排

`pipeline.py` 只负责调用模块和管理阶段状态，不承载具体数学或 USD 业务逻辑。

阶段名建议为：

```text
config
inspect_inputs
coordinates
gaussian
mesh
joints
compose
validate
```

`dry_run`、`stop_after_phase`、临时输出和失败清理在此统一管理。

## 10. 分阶段实施方案

### 阶段 0：远端技术勘察和最小试验

目标：消除 Gaussian Importer 和 3DGS 变换方式的不确定性。

任务：

1. 确认 Isaac Sim 版本和 Python/Kit 启动方式；
2. 检查 Gaussian 相关扩展；
3. 查找 Importer 命令、Python API 或扩展入口；
4. 选取代表性 PLY 做自动化导入；
5. 记录输出 Prim 类型、Schema 和属性；
6. 测试父 Xform 对 Gaussian 渲染的影响；
7. 测试烘焙 position/orientation；
8. 形成 A/B 报告和适配器接口结论。

产出：远端环境清单、Importer 最小调用原型、测试 USD、转正策略报告。

### 阶段 1：扫描输入并生成候选配置

目标：建立实际 PLY、Mesh 和旧数据的只读清单。

任务：

1. 扫描 `ply_parts` 全部 PLY；
2. 解析 Header、属性、Splat 数量和包围盒；
3. 检查 Mesh Prim、单位和连通分量；
4. 读取旧资产语义和关节数据作为对照；
5. 生成 PLY → Link 候选映射；
6. 生成候选语义标签和 Mesh 参考关系；
7. 单独列出不确定项。

产出：`input_asset_manifest.json`、`fangshan_build_config.candidate.json` 和候选映射说明。

完成条件：用户确认或修改映射后形成正式配置基线。

### 阶段 2：配置基础设施

目标：建立配置执行层，不生成正式 USD。

任务：实现数据模型、Schema、默认值、路径、ID、Prim、Joint body 到 Link Xform、articulation 图、dry-run 和 resolved config。

测试重点：动态数量、重复 ID/路径、缺失 Link、Link body 直接引用、兼容的 Mesh body 间接引用、非刚体 Xform 拒绝、floating/fixed 冲突、非法单位、轴和限位。

### 阶段 3：输入检查和坐标求解

目标：以只读方式验证实际数据并求统一变换。

任务：实现 PLY/Mesh Inspector、OBB、PCA、方向判定、显式矩阵和坐标调试 Stage。

完成条件：履带中心、前方和上方通过数值及人工可视检查。

### 阶段 4：3DGS 导入和转换

目标：可靠构建任意数量 Gaussian 部件。

任务：完成 Importer 适配器，批量导入 PLY，应用阶段 0 确定的变换方式，组织 Link/Prim，写语义和独立 USD，并校验属性。

完成条件：空间方向、多视角渲染和语义输出通过验证。

### 阶段 5：Mesh 拆分和转换

目标：不依赖旧五部件 Mesh，直接从源 Mesh 生成逻辑部件。

任务：计算连通分量，建立 Gaussian 参考索引，分类分量，处理歧义，重建拓扑和 Primvar，应用公共变换并生成调试层。

完成条件：每个源面恰好输出一次，无拓扑撕裂，目标 Mesh 与 Gaussian 对齐。

### 阶段 6：一次性 Joint 迁移与 Mesh 几何验证

目标：把旧模型中可信的四条 Joint 旋转线一次性迁移为新模型独立、可审计的标定文件；Mesh 拟合负责验证而不是默认替换旧关系。

任务：

1. 实现独立的 Fangshan 迁移命令，读取旧 Link/Joint 帧并恢复旧世界中心和轴；
2. 反解旧视觉子 Prim 公共变换，换算到当前源 Mesh 数值坐标；
3. 校验旧五部件 Mesh 与当前组合 Mesh 顶点同源，旧 3DGS 与当前 PLY 同源；
4. 将迁移中心、轴、body 顺序、轴方向、零位和限位来源写入新标定/迁移报告；
5. 用 Mesh 铰接区域、圆弧或轴孔检查中心距离、轴夹角和结构合理性；
6. 只对超出阈值的 Joint 进行人工复核或重新拟合；
7. 确认后固化新 `joint_calibration.json`，并从正常构建依赖中移除旧 USD。

完成条件：所有正式 Joint 具备有效中心和轴；迁移与 Mesh 验证通过阈值或有人工接受说明；在移走旧 USD 后，标定校验和后续构建仍可独立完成。

### 阶段 7：Link、Joint 和 Articulation

目标：构建可在 Isaac Sim 初始化和控制的浮动 articulation。

任务：创建带 RigidBodyAPI 的 Link Xform；将 Joint body0/body1 直接写到这些 Link Xform；根据新标定文件创建 Joint 局部帧、限位和 ArticulationRoot；不读取旧 USD，不创建固定关节和 Angular Drive。

完成条件：根 Link 可移动，各 Joint 围绕正确中心和轴转动，零位不跳变。

### 阶段 8：分层组合、语义和输出

目标：形成可搬移、可复用、可审计的最终资产。

任务：输出各层和入口、设置 Stage 元数据、写语义、相对引用、调试 Stage、resolved config 和报告。

完成条件：移动输出目录后入口仍能解析所有内部资产。

### 阶段 9：采集项目接入验证

目标：验证 Joint Position Recorder 和 Semantic World 后续接入条件。

任务：生成 floating base 候选配置，更新根、Link、Joint、语义路径，测试根姿态、Joint position 和语义输出。

修改采集项目源码属于独立实施范围，需要另行确认。

## 12. 验收标准

### 12.1 配置和独立性

1. 更改根 Prim 只修改配置；
2. 增删 Gaussian、Mesh、Link 或 Joint 只修改数组；
3. Fangshan Joint 在配置和最终 USD 中均直接指向带 RigidBodyAPI 的 Link Xform；
4. 一次性迁移产物确认后删除或移走旧 USD，新标定校验、新构建和新资产仍可用；
5. 输出不包含旧路径或绝对输入引用；
6. 所有派生值进入 resolved config。

### 12.2 坐标和几何

1. 履带 OBB 中心位于目标原点允许误差内；
2. 前方向为 `+X`，上方向为 `+Z`；
3. Mesh、3DGS 和 Joint 使用同一变换；
4. Mesh 与 Gaussian 包围盒、轮廓和关节区域对齐。

具体容差在实际输入检查后写入正式配置，不在设计阶段猜测。

### 12.3 3DGS

1. 每个启用 PLY 对应一个配置目标部件；
2. 输入输出 Splat 数量一致；
3. 关键属性无非预期丢失；
4. 数值有限；
5. 多视角 A/B 渲染无不可接受退化；
6. 语义标签与配置一致。

### 12.4 Mesh

1. 每个源面恰好分配一次；
2. 不存在跨 Link 撕裂面；
3. 顶点、面和 Primvar 索引合法；
4. 歧义分量明确报告；
5. 隐藏 Mesh 不影响 Gaussian 渲染；
6. Mesh 随所属 Link 正确运动。

### 12.5 Joint 和 Articulation

1. Joint 两端直接解析为不同且有效的刚体 Link Xform，最终 relationship 不指向 Mesh；
2. 数量和拓扑符合配置；
3. 零位加载无部件跳变；
4. Joint 围绕经一次性迁移并通过 Mesh 验证的中心和轴转动；
5. 限位与配置一致；
6. 无意外 Angular Drive；
7. 无世界固定关节；
8. 根刚体可设置位置和姿态；
9. articulation 在 Isaac Sim 成功初始化。

### 12.6 输出和审计

1. 内部资产引用全部为相对路径；
2. 输出目录搬移后仍可加载；
3. 报告包含输入摘要、公共变换、部件映射、Mesh 分类和 Joint 最终数据；
4. 占位物理属性明确标识；
5. 构建失败不留下可被误认为成功结果的入口文件。

## 13. 风险和应对

### 13.1 Gaussian Importer 没有稳定自动化入口

先完成阶段 0，将版本相关逻辑封装在 importer adapter。若只有 UI Command，则评估 Kit Command 或扩展接口；替代方案必须经最小数据验证，不能猜测 Schema。

### 13.2 3DGS 烘焙旋转影响 SH

对父 Xform 和烘焙模式做多视角 A/B 对比。仅在明确属性语义后转换方向相关 SH，优先选择渲染正确且数据损失最小的方案。

### 13.3 Mesh 元数据单位与数值尺度矛盾

配置强制填写 `units_to_meters`，并用 Mesh/Gaussian 包围盒比值验证；不只依据 `metersPerUnit` 自动缩放。

### 13.4 大量 Mesh 碎片分类歧义

按连通分量整体分类，输出候选距离和调试颜色；严格模式遇到歧义停止，后续可扩展显式分量分配表。

### 13.5 旧局部帧不能直接复制，圆弧拟合也不能确定角度约定

旧 `localPos/localRot` 依赖旧 Link 和视觉坐标关系，必须先恢复世界旋转线，再反解旧视觉变换并换算到当前源坐标；禁止原样复制。Mesh 圆弧拟合作为迁移值的独立几何验证。`axis_sign`、零位和限位优先保持旧运动约定并由人工确认，不能仅凭圆弧拟合自动决定。

### 13.6 一次性迁移被误放入生产依赖

迁移工具使用独立命令、独立输入参数和独立报告，不注册为正常 pipeline 阶段。正式构建配置和输出不得记录旧 USD 路径；构建器不得在新标定缺失时自动读取旧模型。集成测试应在旧 USD 不可访问的条件下完成一次完整重建。

### 13.7 浮动根不代表真实动力学

明确 v01 是直接根姿态和 Joint position 控制的采集资产。默认可关闭重力；需要真实自由运动时新增真实 physics overlay。

### 13.8 Isaac Sim 版本差异

记录 Isaac Sim、扩展和构建器版本；将 Kit/Schema 调用集中封装；集成测试固定在目标远端环境执行。

### 13.9 配置自由度导致非法组合

使用严格 Schema、引用解析、图校验和 dry-run；对不支持的组合显式失败，不承诺所有字段任意组合都合理。

## 14. 构建报告最低内容

`build_validation_report.json` 至少包含：

- 规范化输入与输出路径；
- 启用 Link、Joint、Mesh、Gaussian 清单；
- 每个部件的最终 Prim 和 Link；
- 公共变换及求解诊断；
- Gaussian 输入输出数量和属性；

- 语义标签清单；
- 占位物理属性清单；

## 17. 变更记录

### 2026-08-12：Fangshan 正式构建实现闭环

- Fangshan 正式构建采用父 Xform 表达 Gaussian 公共坐标变换，保持局部 position、orientation 和球谐属性不变；Mesh 顶点/法线与 Joint 几何直接输出到同一目标坐标。
