# v04 当前完成内容、Omniverse/Isaac 接口与下一阶段目标

## 用户问题

当前做完了哪些事情，用到了omniverse或者isaac的哪些接口和模块，接下来要做哪些事情，下一阶段的目标是什么？

## 回答

当前完成的是一个“可运行、可验证的 v04 MVP”：已经能从独立 Studio 编排项目，由 Supervisor 启动独立 headless Isaac Runtime，并完成 Realtime/Path Tracing 的 RGB 与语义采集。

整体链路为：

```text
Studio
→ ProjectDefinition
→ Validator
→ JobCompiler
→ Same-host Supervisor
→ Headless Runtime
→ Replicator/RTX
→ Atomic Writer + Ledger
```

## 一、当前已经完成的事情

### 1. 独立 Semantic Capture Studio

已经建立独立 Omniverse Kit 应用，不依赖先打开完整 Isaac Sim GUI。

当前支持：

- 新建、打开、保存、另存为 `.swproject`。
- 打开 USD Stage。
- 搜索 Prim。
- 选择 Camera Prim。
- 自动读取 USD Camera 参数。
- 添加、复制、启停和删除相机配置。
- 创建 Full Scene 和 Include Paths 隔离场景。
- 配置“传感器 × 场景变体 × 输出模态”。
- 编译不可变 JobSpec。
- 提交、查询、停止和恢复任务。
- `Run headless & exit`：提交后关闭 Studio。
- `Run + monitor`：保留 Studio 查看状态。

Studio 只负责编辑，不创建 Isaac World，也不使用 Replicator 采集。

### 2. 项目与配置系统

已经完成：

- 严格 Schema 模型。
- 未知字段和拼写错误拒绝。
- 项目原子保存。
- 内容寻址 revision。
- 项目修改不影响已编译任务。
- JobSpec 内容摘要和完整性校验。
- Stage、Motion 和 Output 路径解析。
- 相机参数来源记录：

```text
stage
override
default
```

多个针孔相机只需要增加多个 `SensorDefinition`，不需要修改 Coordinator。

### 3. 插件架构

当前已经实现三类插件接口：

- SensorPlugin
- VariantStrategy
- ModalityPlugin

已实现插件：

| 类型 | 已实现 |
|---|---|
| Sensor | Pinhole Camera |
| Variant | Full Scene、Include Paths |
| Modality | RGB、Semantic ID、Semantic Color |

Coordinator 已经移除了针孔相机和 RGB/语义编码的具体类型判断。以后增加新传感器，需要实现并注册插件，但不需要修改主采集流程。

### 4. Headless Runtime

已经实现：

- ABI-safe Isaac Python 启动。
- 磁盘、GPU、libpython 预检查。
- Headless SimulationApp 生命周期。
- USD Stage 加载和等待。
- Stage 打开后应用、回读渲染设置。
- Realtime 与 Path Tracing。
- Replicator Render Product。
- RGB 和语义分割 Annotator。
- 语义-only 场景不读取、不保存 RGB。
- Session Layer 场景可见性切换。
- CSV articulation motion。
- 显式 absolute-seek 能力声明。
- 非 seek 轨迹顺序 replay。
- 原子 capture group。
- Ledger 断点恢复。
- 输出文件完整性检查。
- 清晰的 completed、failed、cancelled 状态。

### 5. Supervisor

已经实现：

- 独立 Runtime 子进程。
- Studio 退出后 Runtime 继续运行。
- PID 和进程启动 token。
- GPU 文件锁。
- 状态、帧进度、心跳、日志。
- 优雅停止。
- cancelled/failed 任务恢复。
- 已提交帧跳过。
- Supervisor 与 Runtime 独立日志。

真实验证中，任务在 15/200 时停止，随后恢复至 200/200，首帧哈希保持不变，Ledger 没有重复。

### 6. 测试结果

- 本地纯 Python：38/38 通过。
- 云端 Isaac Python：38/38 通过。
- 独立 Kit Studio extension/window：启动成功。
- Realtime：采集成功。
- Path Tracing：采集成功。
- Full Scene：RGB、Semantic ID、Semantic Color 正确。
- Excavator Only：只有两种语义输出，没有 RGB。
- 云端没有残留 Runtime 或 Studio 进程。
- 可执行代码没有旧项目引用。

## 二、使用了哪些 Omniverse/Isaac 模块

### Omniverse Kit Studio

| 模块/API | 用途 |
|---|---|
| `omni.ext.IExt` | Studio extension 生命周期 |
| `omni.ui` | Window、按钮、输入框、折叠面板 |
| `omni.kit.app` | Kit 更新循环、异步等待、退出 Studio |
| `omni.usd` | 打开 Stage、等待加载、获取 Stage、Prim 选择 |
| `omni.kit.viewport.window` | 轻量 USD Viewport |
| `omni.kit.window.stage` | 标准 Stage 窗口 |
| `omni.kit.window.property` | USD 属性界面 |
| `omni.hydra.rtx` | Studio Viewport 的 RTX 显示 |
| `omni.materialx.libs` | 材质加载支持 |

当前 Studio 比完整 Isaac Sim GUI 轻，但不是纯 CPU OpenUSD 查看器，因为 Viewport 仍加载 Kit、Hydra 和 RTX。

Studio 中没有启动：

- `isaacsim.SimulationApp`
- Isaac World
- Replicator
- Articulation
- 正式 Render Product

这些只存在于 headless Runtime。

### OpenUSD/PXR

| 模块/API | 用途 |
|---|---|
| `pxr.Usd.Stage` | 遍历 Stage |
| `pxr.UsdGeom.Camera` | 读取焦距、光圈、裁剪范围、投影 |
| `pxr.UsdGeom.Xformable` | 读取 Camera Transform |
| `pxr.UsdGeom.Imageable` | 读取和设置 Visibility |
| `pxr.Sdf.Layer.CreateAnonymous` | 创建临时 Session 子层 |
| Session Layer/EditTarget | 隔离场景，不修改源 USD |

### Headless Isaac Sim

| 模块/API | 用途 |
|---|---|
| `isaacsim.SimulationApp` | 创建和关闭 headless Isaac Runtime |
| `SimulationApp.update()` | 驱动 Kit、USD、渲染和物理更新 |
| `SimulationApp.reset_render_settings()` | Stage 加载后重置渲染设置 |
| `isaacsim.core.prims.SingleArticulation` | CSV 驱动关节和根位姿 |
| `omni.timeline` | 设置时间、播放、暂停和同步物理步 |

### Replicator 与 RTX

| 模块/API | 用途 |
|---|---|
| `omni.replicator.core` | 传感器采集 |
| `rep.create.render_product()` | 基于 Camera Prim 创建 Render Product |
| `rep.AnnotatorRegistry.get_annotator("rgb")` | RGB |
| `semantic_segmentation` Annotator | 无损 Semantic ID |
| `rep.orchestrator.step()` | 执行一次正式采集 |
| `rep.orchestrator.wait_until_complete()` | 等待 GPU 输出完成 |
| `carb.settings` | 应用和回读 Path Tracing/RTX 配置 |

## 三、当前尚未完成的部分

目前最大的问题不是采集内核，而是 Studio 的生产可用性还不完整。

### 1. 缺少三个关键配置面板

当前还没有可视化的：

- Render Profile 面板
- Capture Schedule 面板
- Motion/Trajectory 面板

因此现在无法只靠 UI 设置：

- Realtime/Path Tracing。
- 分辨率。
- SPP、subframes、bounce、warmup。
- start frame、frame count、capture FPS。
- CSV trajectory。
- articulation Prim 和关节映射。
- absolute seek 策略。

这些目前需要通过示例项目或 Python API 修改。

### 2. 相机 override 尚未完全应用

当前：

- USD Stage 中的相机内参会自动使用。
- `resolution` override 会被 Runtime 消费。
- 焦距、光圈、裁剪范围等 override 会保存到 JobSpec，但尚未在 Runtime 中写入临时 Session Layer。

下一步需要实现 Camera Authoring Adapter，使 override 真正影响采集，同时仍不修改源 USD。

### 3. Studio UI 仍属于功能型 MVP

还需要改进：

- 真正的 Prim Tree，而不只是搜索结果文本。
- 传感器列表/表格。
- 传感器参数来源的清晰展示。
- 模态矩阵复选框。
- Render/Capture 配置控件。
- 项目脏状态提示。
- Preflight 汇总页面。
- Job 历史列表。
- 输出目录快捷打开。
- 语义图/RGB 缩略图预览。
- 更好的错误提示。

### 4. 长时间 Path Tracing 还没有充分验证

当前通过的是最小 smoke，并不能证明数万帧完全稳定。

还需要验证：

- 720p/1080p。
- 更高 SPP。
- 数百至数千帧。
- 多相机。
- 多变体。
- 中途停止和恢复。
- 显存变化。
- GPU page fault。
- 长时间无提交检测。
- 输出空间估算。

### 5. 还没有真实鱼眼和 LiDAR 驱动

当前只完成扩展接口。

尚未完成：

- Fisheye Camera Plugin。
- LiDAR Plugin。
- Multi-camera Rig Plugin。
- Depth、Normal、Instance Segmentation、Point Cloud 等模态。

### 6. Supervisor 还不是常驻服务

当前 Supervisor 是文件状态 + CLI/Application Service。

它可以让 Runtime 在 Studio 退出后继续运行，但还不是一个常驻守护进程。因此下一阶段需要考虑：

- 独立 Supervisor daemon。
- 主动监控进程和心跳。
- 超时自动终止。
- 自动失败摘要。
- Job 队列。
- GPU 排队。
- 崩溃后自动或人工确认恢复。

## 四、推荐的下一阶段目标

建议把下一阶段定义为：

> v04.1 Production Workflow：让用户完全通过 Studio 配置并启动一个真实长任务，不需要手工修改 JSON 或 Python。

核心验收标准是：

```text
打开 USD
→ 选择相机
→ 配置场景
→ 配置模态
→ 配置渲染
→ 配置帧数和轨迹
→ Preflight
→ 提交并退出 Studio
→ CLI/Studio 查看状态
→ 中断后恢复
```

整个过程不需要编辑配置文件。

### 第一优先级：补齐 Studio 配置闭环

实现：

1. Render Profile 面板。
2. Capture Schedule 面板。
3. Motion/Trajectory 面板。
4. Semantic Profile 面板。
5. 真正的 Modality Matrix。
6. Preflight 汇总和预计输出空间。
7. Job 历史与 Resume 界面。

### 第二优先级：完整相机 override

实现临时 Camera Session Layer：

- 焦距。
- 光圈。
- clipping range。
- projection。
- transform。
- per-sensor resolution。

并在 metadata 中同时记录 Stage 原值和实际生效值。

### 第三优先级：长任务工程化

- 分段 worker。
- Segment 状态。
- 长时间无进度检测。
- 自动失败识别。
- GPU/显存监控。
- Path Tracing 长跑。
- 精确 ETA。
- 输出容量估算。

### 第四优先级：新增传感器

等生产工作流稳定后，建议按顺序增加：

1. 多针孔相机配置验证。
2. 鱼眼相机。
3. Depth/Normal。
4. LiDAR/Point Cloud。
5. Multi-camera Rig。

现在最合理的下一步不是马上做 LiDAR，而是先补齐 Render、Capture、Motion 三个 Studio 面板，使当前已经跑通的采集能力真正做到易用、可复用、无需手改配置。
