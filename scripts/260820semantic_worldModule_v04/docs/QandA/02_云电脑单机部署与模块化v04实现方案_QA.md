# Semantic World Module v04：云电脑单机部署与模块化实现方案问答

> 记录日期：2026-08-20  
> 文档类型：完整问答记录  
> 主题：确定独立 Omniverse Kit Studio、云电脑单机部署、同机 Headless Runtime 与模块化实现方案

## 用户问题

### 选中的方案上下文

- “Omniverse Kit 独立应用”
- “LocalRunner 在本机运行 Headless Isaac。SshRunner 适合当前云电脑：使用 SSH 公钥连接”
- “阶段三：远端工作流”

### 用户补充与调整

1. 选择 Omniverse Kit 独立应用模式。
2. 当前不需要 LocalRunner/SshRunner 的本地与远端二选一方案，预期脚本项目的全部内容都在云电脑上运行。
3. 当前不需要远端工作流。
4. 这套项目的各个部分和功能要尽量模块化，方便之后修改、改进和增加新功能。
5. 在总结部分以模块化链路的角度简要概述。
6. 根据以上要求更新实现方案。

## Codex 回答

更新后的 v04 方案将采用“云电脑单机部署、Studio 与 Headless Runtime 分进程运行”的模式。当前版本不实现本地/远端二选一，不引入 SSH Runner，也不设计远端工作流，但保留清晰的模块边界，方便未来扩展。

## 一、产品定位调整

### Semantic Capture Studio

确定采用独立的 Omniverse Kit 应用，不作为 Isaac Sim GUI 插件。

主要负责：

- 轻量加载和查看 USD Stage。
- 浏览 Prim 层级。
- 从 Stage 中选择相机、激光雷达等传感器 Prim。
- 配置每个传感器的采集模态。
- 配置 Full Scene、Excavator Only 等采集场景。
- 配置 Path Tracing 参数、采集频率和输出目录。
- 校验配置并生成可复用项目。
- 提交 Headless 采集任务和查看运行状态。

Studio 只承担编辑、预览、校验和任务编排，不负责正式数据采集。

### Semantic Capture Runtime

基于 v03 的可靠采集内核继续升级，负责：

- Headless 启动 Isaac Sim。
- 加载 USD、轨迹和语义配置。
- 创建传感器和 Render Product。
- 控制场景变体。
- 执行 Path Tracing。
- 输出 RGB、Semantic ID、Semantic Color 等数据。
- 断点续采、分段执行和运行记录。

### Semantic Capture Supervisor

新增同机任务管理模块，负责：

- 在云电脑上启动 Headless Runtime 子进程。
- 传递不可变任务配置快照。
- 管理 PID、状态、日志和退出码。
- 防止重复启动同一任务。
- 处理异常退出和断点续采。
- 管理 GPU 独占或资源锁。

当前不再区分 `LocalRunner` 和 `SshRunner`。Studio、Supervisor、Runtime、USD、配置和输出都位于同一台云电脑，Supervisor 直接启动同机 Headless 进程。

## 三、核心设计原则

### 1. 编辑环境与采集环境分离

Studio 和 Runtime 是两个独立进程：

- Studio 使用轻量 Kit 应用提供交互。
- Runtime 使用 Headless Isaac Sim 完成采集。
- Studio 退出后，Runtime 仍然可以继续运行。
- Runtime 崩溃不会直接破坏 Studio 项目文件。
- Runtime 不读取 UI 临时状态，只读取正式任务快照。

这样既能提供较好的配置体验，也不会让正式采集依赖 GUI。

### 2. 项目配置与任务快照分离

用户编辑的是可复用的项目配置，例如：

```text
excavator_capture.swproject/
├─ project.json
├─ stage.json
├─ sensors.json
├─ variants.json
├─ modalities.json
├─ render.json
├─ motion.json
├─ semantics.json
└─ jobs/
   └─ job_20260820_001/
      ├─ job_spec.json
      ├─ status.json
      └─ logs/
```

提交任务时，Compiler 将当前项目编译为不可变的 `job_spec.json`。

这样可以保证：

- 修改项目不会影响正在执行的任务。
- 每次采集都有准确的参数记录。
- 旧任务能够复现。
- 失败任务可以根据原快照续采。
- 项目可以另存为模板并轻量修改。

### 3. UI 不直接控制 Runtime 内部对象

UI 只修改领域模型：

```text
UI 操作
  ↓
ProjectModel
  ↓
Validator
  ↓
JobCompiler
  ↓
JobSpec
  ↓
Headless Runtime
```

UI 不直接创建 Replicator Annotator，不直接控制 Isaac World，也不直接写输出图片。这能避免界面代码与采集实现紧密耦合。

## 四、模块化层次架构

### 第一层：Kit Application Shell

负责：

- Studio 启动和关闭。
- 窗口布局和菜单。
- Extension 生命周期。
- 项目打开、保存和另存为。

它只组织界面，不包含传感器和采集逻辑。

### 第二层：USD Stage Access

负责：

- 打开和关闭 USD Stage。
- 遍历 Prim。
- 读取相机、材质、语义、灯光和层级信息。
- 监听 Stage 变更。
- 提供 Prim 搜索和过滤。

输出统一的 `StageIndex`，避免其他模块反复遍历 Stage。

### 第三层：Viewport 与选择系统

负责：

- 轻量 USD 预览。
- Prim 拾取。
- 相机视锥显示。
- 传感器图标和辅助线显示。
- 场景变体预览。

正式采集开始后，Viewport 可以停止刷新或直接关闭 Studio，以减少 GPU 占用。

### 第四层：Project Domain Model

定义稳定的数据模型：

- `Project`
- `StageReference`
- `SensorDefinition`
- `VariantDefinition`
- `ModalityDefinition`
- `RenderProfile`
- `CaptureSchedule`
- `MotionSource`
- `SemanticProfile`
- `OutputPolicy`

UI、校验器、编译器和 Runtime 都围绕这些模型交互。

### 第五层：传感器插件系统

每类传感器作为独立插件：

```text
SensorPlugin
├─ PinholeCameraPlugin
├─ FisheyeCameraPlugin
├─ LidarPlugin
└─ MultiCameraRigPlugin
```

插件负责：

- 判断某个 Prim 是否可作为该类传感器。
- 从 USD Prim 自动读取参数。
- 提供专属配置面板。
- 声明支持的采集模态。
- 将编辑配置编译为 Runtime 配置。
- 在 Runtime 中创建对应 Driver。

以后增加鱼眼相机或新型激光雷达，不修改主采集链路，只增加插件和注册信息。

### 第六层：场景变体模块

统一表达不同传感器对应的采集场景：

```text
VariantStrategy
├─ FullSceneVariant
├─ IncludePathsVariant
├─ ExcludePathsVariant
├─ SemanticFilterVariant
└─ CustomVariant
```

变体配置包括：

- 包含的 Prim。
- 排除的 Prim。
- 必须保护的传感器路径。
- 每个传感器在该变体下启用的模态。
- 灯光、环境和辅助对象的保留规则。

变体模块只控制 USD Session Layer，不修改原始 USD。

### 第七层：模态注册系统

模态作为独立能力注册：

```text
ModalityPlugin
├─ RgbModality
├─ SemanticIdModality
├─ SemanticColorModality
├─ DepthModality
├─ NormalsModality
└─ PointCloudModality
```

它负责声明：

- 支持哪些传感器。
- Runtime 使用哪个 Annotator。
- 输出数据类型。
- 文件格式。
- 可视化转换方式。
- 元数据结构。

传感器、场景变体和模态是三个相互独立的维度。

### 第八层：校验与编译模块

Validator 在启动采集前检查：

- USD 文件是否存在。
- Prim Path 是否有效。
- 传感器类型是否匹配。
- 模态是否受该传感器支持。
- 变体是否会隐藏传感器或灯光。
- 输出目录是否有足够空间。
- Path Tracing 配置是否完整。
- 轨迹和采集时长是否匹配。
- 语义映射是否存在冲突。

Compiler 将项目模型转换为 Runtime 唯一认可的 `JobSpec`。

### 第九层：任务管理模块

当前只提供同机 Supervisor，不提供 Runner 选择：

```text
JobSupervisor
├─ submit(job_spec)
├─ start(job_id)
├─ stop(job_id)
├─ status(job_id)
├─ resume(job_id)
└─ read_logs(job_id)
```

未来如果确实需要跨机器运行，可以在这一边界增加远端实现，但当前版本不编写 SSH 上传、同步和远端执行逻辑。

### 第十层：Headless Runtime

Runtime 内部继续模块化：

```text
Runtime Bootstrap
  ↓
Stage Loader
  ↓
Motion Controller
  ↓
Variant Controller
  ↓
Sensor Registry
  ↓
Capture Coordinator
  ↓
Output Writer
  ↓
Checkpoint Ledger
```

每一层只通过明确接口交互，不让传感器 Driver 自己控制整个 World，也不让 Output Writer 理解 Isaac Sim 场景对象。

### 第十一层：输出与可观测性

负责：

- 原子帧写入。
- 分段提交。
- 帧账本。
- 断点恢复。
- 运行状态。
- 性能统计。
- 错误诊断。
- 配置快照。

输出结构由任务定义生成，避免不同传感器各自随意创建目录。

## 五、云电脑运行时的性能策略

虽然 Studio 和 Runtime 都部署在云电脑，但不建议正式采集时持续渲染 Studio Viewport。

推荐提供两种提交行为：

- “提交并进入监控模式”：停止 Viewport，只保留低频文本状态。
- “提交并退出 Studio”：Supervisor 接管任务，Studio 完全退出。

监控信息通过读取状态文件、日志和账本获得，不打开 Isaac Sim GUI，也不读取正式采集 Render Product。

因此正式采集仍然是完全 Headless 的。

## 六、更新后的实现阶段

### 阶段一：项目内核与配置协议

实现：

- Project Domain Model。
- 配置 Schema。
- 项目保存和加载。
- JobSpec 编译器。
- Validator。
- 插件注册协议。

这个阶段先固定模块之间的数据契约。

### 阶段二：独立 Kit Studio MVP

实现：

- 独立 Omniverse Kit 应用。
- USD Stage Tree。
- 轻量 Viewport。
- Prim 选择。
- 传感器配置。
- 场景变体配置。
- 模态选择。
- 项目保存和重新打开。

### 阶段三：云端同机 Headless 工作流

原来的“远端工作流”阶段取消，替换为云电脑同机运行。

实现：

- Same-host Supervisor。
- Headless 子进程启动。
- GPU 资源锁。
- 日志和状态读取。
- 任务停止与恢复。
- Studio 监控模式。
- Studio 退出后任务继续运行。

不实现：

- SSH 连接。
- 文件上传和下载。
- 本机与云端路径映射。
- 远端机器列表。
- SshRunner。
- 跨机器任务分发。

### 阶段四：Runtime 与 v03 能力整合

实现：

- v03 配置到 JobSpec 的迁移。
- Path Tracing 稳定启动。
- 传感器插件化。
- 变体插件化。
- 模态插件化。
- 分段与绝对位置快跳。
- 原子写入和断点续采。

### 阶段五：扩展能力

按需要增加：

- 鱼眼相机。
- 多针孔相机阵列。
- 激光雷达。
- 深度图和法线图。
- 项目模板。
- 配置版本迁移。
- 批量任务。
- 数据集检查器。

## 七、预期使用流程

1. 用户通过云电脑桌面启动 Semantic Capture Studio。
2. 新建项目或打开已有 `.swproject`。
3. 选择云电脑上的 USD Stage。
4. Studio 扫描 Stage 并建立 Prim 索引。
5. 用户选择相机或其他传感器 Prim。
6. 插件自动读取 USD 中已有的相机参数。
7. 用户选择每个传感器对应的场景变体。
8. 用户为每个“传感器 × 场景变体”选择采集模态。
9. 设置轨迹、帧率、Path Tracing 和输出目录。
10. Validator 检查配置。
11. Compiler 生成不可变 JobSpec。
12. Supervisor 在同一台云电脑启动 Headless Runtime。
13. Studio 停止 Viewport 并进入监控模式，或者直接退出。
14. Runtime 独立完成采集、记录日志和断点信息。
15. 用户重新打开 Studio 查看结果或基于原项目轻量修改。
16. 修改后的配置保存为新版本，再次提交任务。

## 模块化链路总结

```text
USD Stage
  ↓
Stage Access / StageIndex
  ↓
Project Domain Model
  ↓
传感器插件 + 场景变体插件 + 模态插件
  ↓
Validator
  ↓
JobCompiler
  ↓
不可变 JobSpec
  ↓
同机 JobSupervisor
  ↓
Headless Isaac Runtime
  ↓
Sensor Driver / Capture Coordinator
  ↓
Output Writer / Checkpoint Ledger
  ↓
数据集、日志和运行状态
```

这条链路的核心是：上游负责描述“采集什么”，中间负责验证和编译，Runtime 负责“怎样稳定采集”，输出模块负责“怎样可靠保存”。各部分不跨层直接调用，未来新增传感器、模态、场景策略或任务启动方式时，只需要扩展对应模块。
