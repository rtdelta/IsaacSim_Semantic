### 先掌握 sensor_models

重点对象：

```text
PluginManifest
SensorCapabilities
RigDefinition
CaptureBatchKey
CaptureContext
TypedPayload
SensorSample
CalibrationSnapshot

```

需要明确：

- `TypedPayload` 是一份具体数据。
- `SensorSample` 是一个传感器在某个采集时刻的完整样本。
- `CaptureBatchKey` 表示一次同步组采集。
- `CalibrationSnapshot` 描述采集当时的标定状态。
- `SensorCapabilities` 描述插件“能做什么”。

### 再掌握 models

建议按这个内部顺序：

```text

→ SensorDefinition
→ VariantDefinition
→ ModalityDefinition
→ RenderProfile
→ CaptureSchedule
→ MotionSpec
→ SemanticProfile
→ OutputPolicy
→ ExecutionPolicy
→ ProjectDefinition
→ JobSpec
→ JobStatus
→ SegmentSpec
→ SegmentStatus
→ FrameLedgerEntry
```

务必能区分：

| 对象 | 含义 |
|---|---|
| `ProjectDefinition` | 可编辑项目 |
| `JobSpec` | 编译后不可变任务 |
| `SegmentSpec` | Job 中的一段 |
| `SensorSample` | 传感器某次采样结果 |
| `FrameLedgerEntry` | 某个 capture group 已完成的证据 |
| `BatchLedgerEntry` | 整个同步组已完成的证据 |

## 每层的固定学习方法

对每个源码文件都回答六个问题：

1. 它的输入是什么？
2. 它的输出是什么？
3. 它维护什么状态？
4. 它有哪些外部副作用？
5. 它可能抛出什么异常？
6. 谁调用它，它又调用谁？

每完成一层：

- 画一张小调用图。
- 运行对应测试。
- 修改一个参数观察行为。
- 故意制造一次失败。
- 不看源码复述关键对象和执行顺序。

最终你需要能从下面两个方向完整讲通：

```text
自底向上：
TypedPayload → SensorSample → Writer → Ledger → Coordinator → Worker → Job

自顶向下：
Studio → Project → JobSpec → Segment → SimulationApp → Replicator → Dataset
```

当你能独立追踪一个具体 `frame × sensor × variant` 从项目配置走到最终 PNG/NPY/PLY 和 Ledger 条目，并能解释失败恢复过程时，就算真正掌握了 v04。
