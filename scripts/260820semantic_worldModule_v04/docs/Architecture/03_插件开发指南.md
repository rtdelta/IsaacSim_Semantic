# v04.3 插件开发指南

## 插件发现与 Manifest

插件放在 `src/semantic_world_v04/plugins` 对应包内，并在模块末尾导出：

```python
PLUGIN_CLASSES = (MySensorPlugin,)
```

Loader 自动扫描包，不需要修改 Coordinator 或维护一份传感器条件分支。每个插件必须提供稳定 Manifest：

```python
def manifest(self):
    return PluginManifest(
        plugin_id="my_sensor",
        plugin_kind="sensor",
        plugin_version="1.0.0",
        display_name="My Sensor",
        definition_class=f"{__name__}:MySensorPlugin",
        runtime_requirements=("replicator",),
        supported_modalities=("rgb",),
    )
```

当前契约版本是 2。`plugin_id` 一旦进入项目文件便视为稳定数据标识；破坏性变化应提升插件版本并提供迁移，不得用同一版本静默改变语义。

## SensorPlugin v2

Sensor Plugin 负责配置期差异，重型 Isaac 调用留给 Driver：

```python
class MySensorPlugin:
    plugin_id = "my_sensor"

    def manifest(self): ...
    def capabilities(self): ...
    def parameter_schema(self): ...
    def matches_prim(self, prim): ...
    def extract_stage_parameters(self, prim): ...
    def supported_modalities(self): ...
    def validate(self, sensor, stage_index): ...
    def compile_runtime_payload(self, sensor, stage_index): ...
    def definition_from_prim(self, sensor_id, prim): ...
    def author_runtime_overrides(self, stage, sensor): ...
    def create_runtime_driver(self, sensor, *, resolution, modalities): ...
```

`capabilities()` 至少要明确 payload kind、time model、trigger domain、同步模式、Renderer 兼容性、标定模型和 Runtime requirements。扫描窗口传感器必须设置 `requires_continuous_history=True`，否则 Runtime 不会为它开启连续采集时钟。

`parameter_schema()` 使用项目内置的 JSON Schema 子集。Studio 据此显示参数结构，Controller 与 Compiler 会拒绝未知参数、错误类型、非法 enum、范围和数组长度。Stage 原值不受 override Schema 的未知字段限制；严格校验对象是用户显式 override。

参数合并顺序固定为：

```text
Stage values → plugin defaults → explicit overrides → effective Runtime readback
```

每个值的来源记录在 `parameter_sources`。`author_runtime_overrides` 只能把来源为 `override` 的已知字段写入该传感器的匿名 Session Layer，不能修改根 Layer。

## Runtime Driver

Driver 最小接口：

- `sensor_id`、`sensor`、`backend_id`
- `capture_trigger_key`
- 可选 `requires_continuous_history` 和 `output_resolution`
- `initialize(stage)`
- `trigger_capture(rt_subframes)`
- `read_sample(requested_modalities, capture_context)`
- `calibration_snapshot()`
- `close()`

推荐让 `read_sample` 返回：

```python
SensorSample(
    sensor_id="sensor_01",
    timestamp=context.capture_timestamp,
    modality_payloads={
        "my_modality": TypedPayload(
            kind="dense_array",
            data=array,
            dtype="float32",
            shape=(height, width),
            unit="meter",
            coordinate_frame="sensor",
        )
    },
    calibration_snapshot=calibration,
    sequence_metadata={...},
)
```

相同 `capture_trigger_key` 在同一采集边界只触发一次。不要在 Driver 内全局修改 `capture_on_play`；该开关由 `SensorCaptureClock` 汇总全部插件时间模型后统一管理。

Kit、USD、Isaac 和 NumPy/GPU import 应放在 Runtime 方法内部。插件模块被普通 Python 的 Studio/Compiler 导入时不得创建 GPU 对象。

## ModalityPlugin

Modality Plugin 接收通用 payload 并负责格式：

```python
class MyModalityPlugin:
    plugin_id = "my_modality"
    output_extension = ".npy"
    media_type = "application/x-npy"

    def manifest(self): ...
    def validate_options(self, options): ...
    def encode_runtime(self, payload, context):
        return encoded_bytes, metadata_fields
```

原始数据与可视化数据应使用不同 modality ID。例如：

- `depth_linear` → float NPY；`depth_color` → PNG。
- `surface_normal` → float NPY；`surface_normal_color` → PNG。
- `point_cloud` → NPZ；`point_cloud_ply` → PLY。

编码后仍需经过 `validate_encoded_artifact`，至少检查文件头、dtype、shape、有限值和点数。不要只检查“文件存在且非空”。

## VariantStrategy 与 Rig

VariantStrategy 将 `VariantDefinition` 变为 `VisibilityPlan`。传感器及祖先路径必须受到保护，所有可见性意见只写 Session Layer。

Rig 不是传感器插件。它是项目级的同步关系：多个成员共享仿真步和批次时间戳，Atomic Batch Writer 只有在全体成员产物通过校验后才追加 Batch Ledger。新 Driver 只需正确声明 trigger domain 与时间模型即可进入 Rig，无需实现专用 Rig 代码。

## 新传感器落地清单

1. 在目标 Isaac 部署运行 `scripts/capability_probe.py`，确认 Prim Schema、扩展、Annotator 和 Renderer。
2. 实现 Manifest、Capability、parameter schema、Prim 匹配和 Stage 参数提取。
3. 实现真实 Driver、TypedPayload 和 CalibrationSnapshot；不允许用假数据冒充支持。
4. 按需增加 Modality Plugin、编码器和内容校验器。
5. 导出 `PLUGIN_CLASSES`，让 Loader 自动发现。
6. 添加普通 Python 契约/Schema/编码/恢复测试。
7. 在云端做最小真实 headless、Realtime、Path Tracing 和多 Segment 验证。
8. 更新 Capability/限制和数据格式文档。

Event Camera、Radar 等后续类型应主要修改插件、Driver、Encoder 和测试；如果必须在 Coordinator 中出现具体传感器 ID，说明契约仍缺少一项通用能力，应先扩展契约。
