# ADR：v04.3 云端鱼眼与 LiDAR 后端

- 状态：Accepted
- 日期：2026-08-25
- 目标部署：Isaac Sim 6.0.1-rc.7 / Kit 110.1.2

## 决策

鱼眼相机使用 USD 原生 `OmniLensDistortionOpenCvFisheyeAPI`，由 Camera Render Product 和 Replicator 图像 Annotator 输出。配置以 Prim Path 为入口，默认读取 `cx/cy/fx/fy/k1..k4/imageSize`；用户只填写显式 override。

LiDAR 使用 `OmniLidar` 与 `isaacsim.sensors.experimental.rtx` 的 Stage 模型，Runtime 通过 `isaacsim.sensors.rtx.nodes` 注册 `IsaacExtractRTXSensorPointCloud`，输出 device array 并归一化为 NumPy。NPZ 是保留字段的原始数据格式，PLY 是通用可视化/交换格式。

旋转 LiDAR 采用 `scan_window` 时间模型并声明连续历史。Runtime 统一开启 `capture_on_play`，Segment 采用 `replay_from_zero`，不把一次 Replicator step 的空数组当成有效扫描。

## 未采用方案

- 不使用后处理把普通针孔图扭曲成“原生鱼眼”；这种方法可作为未来独立 backend，但不能冒充当前原生后端。
- 不使用已在当前部署缺失/弃用的 `RtxSensorCpuIsaacCreateRTXLidarScanBuffer`。
- 不在 Coordinator 中添加 `if fisheye` 或 `if lidar`；时间差异通过 Capability 和 Driver 属性表达。
- 不允许空点云写入 Ledger，也不静默切换到假数据或不同 backend。

## 后果

优点是输出后端、投影、扫描模型和版本均可审计，新增传感器仍走统一主链路。代价是 RTX LiDAR 必须参与连续时间线调度，混合任务吞吐低于纯相机任务；动态运动效应还依赖部署的 Motion BVH 能力。

机器可读探测结果保存在云端 `v04_3_validation_20260825/capability_report.json`，详细实测结果见同日 v04.3 验证报告。
