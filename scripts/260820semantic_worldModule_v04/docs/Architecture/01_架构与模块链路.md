# v04 架构与模块链路

## 核心目标

v04 把“任务编辑”“任务编排”和“正式采集”彻底分开：Studio 是轻量 USD 任务编辑器，Job Runner 是不加载 Kit 的分段编排器，Segment Worker 是 headless 采集内核，Supervisor 只管理同机 Job Runner。任务以可复用项目保存，修改时编辑项目并重新编译 JobSpec，不需要重新手工选择整套内容。

## 单向依赖

```text
Kit Studio UI
      ↓
StudioController / Application Service
      ↓
Core Models ─ ProjectRepository ─ Validator ─ JobCompiler
      ↓                                  ↓
Stage Adapter / Plugin Registry       immutable JobSpec
                                         ↓
SameHostSupervisor → Job Runner → Segment Planner
                                ↓
                    ABI-safe Segment Worker 000
                                ↓ 完成并退出
                    ABI-safe Segment Worker 001
                                ↓
Stage → Motion → Variant → Capture Clock → Sync Group → SensorSample
      → Modality → Atomic Batch Writer → Frame/Batch Ledger
```

Core、Project、Compiler 和插件描述层均可在没有 `omni`、`pxr`、`isaacsim` 的普通 Python 中导入。Kit/Isaac import 只出现在 Stage adapter 或 Runtime 的延迟调用中。

## 各层职责

### Core

定义严格模型、协议、结构化错误和采集组进度计算。未知字段、非法 ID 和不兼容 Schema 会立即失败。

### Project

把可编辑项目保存为内容寻址 revision。`project.json` 原子切换到完整 revision，因此不会看到半写入项目。旧 JobSpec 单独保留，不受后续项目编辑污染。

### Stage

`OmniStageService` 只负责打开/关闭 USD、等待加载和构建 `StageIndex`。扫描过程不创建 Isaac World 或 Replicator。索引包含路径、类型、父子关系、可见性、相机属性、变换和语义属性摘要。

Runtime 中的传感器参数覆盖和场景可见性分别拥有匿名 Session Layer。两者职责独立，均只对当前 Stage 生命周期有效；清理时保留 layer 引用并清空内容，避免 Hydra 消费 USD notice 时出现悬空 layer。

### Plugin

- Plugin Loader：扫描插件包中的 `PLUGIN_CLASSES`，自动构建注册表并检查 Manifest、契约版本与重复 ID。
- SensorPlugin：声明 Manifest、Capability、参数 Schema、Prim 匹配、Stage 参数提取、支持模态、校验和 Runtime driver 创建。
- VariantStrategy：把配置转换为 visibility plan。
- ModalityPlugin：校验并把带 dtype、shape、单位和坐标系的 TypedPayload 编码为目标文件。

Coordinator 只调用协议，不判断针孔、鱼眼或 LiDAR 类型。多个针孔相机是同一插件的多个配置实例；增加实例不改主链路。当前真实插件为 `pinhole_camera`、`fisheye_camera` 和 `rtx_lidar`。

SensorPlugin 还负责把本类型的显式覆盖写入当前 Session edit target。Driver 初始化后回读组合 Stage 的最终参数，Coordinator 将 Stage 原值、配置值、来源和有效值写入任务快照与逐帧元数据。

### Studio

独立 Kit experience 提供 Viewport 和编辑面板。UI 回调只调用 `StudioController`，不直接拼 Runtime 配置。Studio 不承担正式采集。

生产配置通过 Sensor Catalog、兼容 Prim 发现、插件参数 Schema、Effective Preview、Rig Editor、Render、Capture、Long-job Execution、Motion、Semantic 和通用 Modality Matrix 面板写回严格模型。Preflight 汇总 Validator/Capability 结果、传感器/变体数量、capture group、预计文件数与保守空间；Job History 从项目和输出根读取已编译/已提交任务。Studio 还可从磁盘查看 Segment 历史、GPU/ETA 和失败报告。

### Supervisor

保存 JobSpec 和初始状态，以 argv 列表安全启动独立 Job Runner；保存 PID 与进程启动 token，避免陈旧 PID；维护状态、日志、停止和恢复。Stop 会先终止 Job Runner，再按 Segment 的 PID/token 处理可能仍活跃的 Worker。

### Job Runner

纯编排模块，不导入 `omni`、`pxr` 或 `isaacsim`。它验证 JobSpec、生成确定性 `segment_plan.json`，以 Ledger 和文件完整性判断每段是否已完成，然后逐段启动独立 Worker。Runner 监视进程、心跳和提交进度，采样 GPU telemetry；Worker 异常、启动超时或无进度时停止任务并生成 `failure_report.json`，不会无限自动重试。

### Segment Worker / Runtime

执行顺序固定为：

1. 校验 JobSpec digest、SegmentSpec、路径、磁盘、GPU 与 libpython。
2. 创建 headless SimulationApp。
3. 打开并等待 Stage。
4. reset、应用并回读渲染配置。
5. 在独立 Session Layer 写传感器覆盖，构造 Motion、Variant 和 Sensor driver，并回读有效参数。
6. Capture Clock 汇总插件时间模型；瞬时相机使用边界触发，扫描窗口传感器在时间线播放期间持续接收 Replicator tick。
7. 按 `motion_positioning` 定位 Segment 起点，重置渲染历史并 warmup；需要连续历史的 Segment 强制从零回放。
8. 只处理 Segment 的半开帧区间；按 Sync Group 共享仿真步和采集时间戳，Driver 返回 `SensorSample`。
9. Modality Plugin 编码后先做内容校验；Atomic Batch Writer 完整提交成员，再追加 Frame Ledger 与 Batch Ledger。
10. 独立 heartbeat 线程更新 Segment 状态，最终校验本段并关闭所有 Kit/Replicator 资源。

## Schema v2 与兼容

v04.3 项目和新 JobSpec 使用 Schema v2，增加插件版本、backend、同步组和 Rig。Repository 可读取 v1 项目，先按原始内容校验 revision digest，再迁移到内存 v2；旧传感器默认成为单成员同步组。首次保存迁移项目时会保留 `project.schema_v1.backup.json`。v1 JobSpec 仍可读取和验证，不会原地改写。

## 同步与输出语义

`RigDefinition` 把多个传感器绑定到同一 Sync Group。一次采集边界只按 trigger domain 触发一次；同组成员共享 `simulation_step`、`simulation_time` 和 `capture_timestamp`。只有成员产物全部编码并验证后才写 Batch Ledger 完成标记。单传感器也是单成员同步组，因此恢复逻辑不需要特例。

图像、数组和点云走同一 `SensorSample → TypedPayload → ModalityPlugin` 链路。原始值与可视化值分开保存：例如 depth NPY 与 depth color PNG、point cloud NPZ 与 PLY。每个传感器保存独立标定快照，Rig 另存成员标定集合。

## Headless 与性能边界

`Run headless & exit` 是生产路径：Supervisor 启动 Job Runner 后，Studio 退出，不再占用 GPU。Job Runner 本身不创建 Kit/RTX，只在当前 Segment 生命周期内存在一个 headless Worker。`Run + monitor` 是调试路径，会保留 Kit Viewport，可能与 Worker 争用显存和渲染资源。

## 当前边界

- 已实现 Pinhole、OpenCV Fisheye、RTX LiDAR 真实 headless Driver，以及 RGB、语义、depth、normal、instance 和 point-cloud 模态。
- Isaac Sim 6 的旋转 LiDAR 依赖连续 Replicator 调度；它会增加时间线推进阶段的渲染成本，不会静默退化成瞬时快照。
- 当前 `include_paths` 与所有传感器 override 使用匿名 Session Layer，不修改源 USD。
- Rig 当前支持 `same_simulation_step + all_or_retry`；更严格的硬件触发误差模型尚未实现。
- 绝对 CSV motion 支持 seek；LiDAR Segment 为保存扫描历史会采用 `replay_from_zero`。真实运动畸变精度仍取决于 Motion BVH 和传感器模型能力。
