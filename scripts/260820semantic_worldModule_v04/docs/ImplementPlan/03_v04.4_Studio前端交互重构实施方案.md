# v04.4 Studio 前端交互重构实施方案

## 1. 文档状态

- 阶段：v04.4
- 状态：已实现并通过云端集成验证
- 日期：2026-08-27
- 范围：Semantic Capture Studio 前端交互、项目编辑体验和运行前配置流程
- 不在本阶段范围：修改既有 Headless Runtime、传感器 Driver、Job Runner、Supervisor 和 Ledger 核心语义

## 2. 核心目标

本阶段不只是在当前长滚动面板上增加按钮，而是把 Studio 从“按内部模块罗列参数”重构成“按用户完成任务的顺序组织”。目标是让用户通过可视化选择、复选框、预设和自动发现完成大部分配置，尽量不再手工输入 Plugin ID、Prim Path、Variant ID 和 Modality 字符串。

更新后的核心链路是：

```text
可视化打开项目
→ 自动加载 USD
→ 勾选已有传感器
→ 可视化创建 Variant
→ 为每个 Sensor × Variant 独立勾选输出文件
→ 默认使用 Path Tracing 正式质量
→ 查看采集摘要
→ Headless 运行
```

底层继续保持现有模块化插件、Variant、Project、JobSpec、Supervisor 和 Headless Runtime 架构。本阶段变化主要集中在 Studio 的信息组织、交互组件和 UI-neutral Application Service 的适配。

## 3. 输出模态交互调整

### 3.1 全部输出平铺

不使用“Depth 勾选后再选择输出格式”的二级交互，也不把原始数据与可视化结果捆绑。所有实际输出均作为独立选项平铺显示。

相机基础输出区域提供五个独立选项：

| UI 选项 | Runtime 模态 | 输出文件 |
|---|---|---|
| RGB | `rgb` | PNG |
| Depth Data | `depth_linear` | NPY 原始深度 |
| Depth Color | `depth_color` | PNG 彩色预览 |
| Semantic ID | `semantic_id` | NPY 语义 ID |
| Semantic Color | `semantic_color` | PNG 语义可视化 |

新的采集矩阵示例：

| 场景变体 | 启用 | RGB | Depth NPY | Depth Color | Semantic ID | Semantic Color |
|---|---:|---:|---:|---:|---:|---:|
| Full Scene | ☑ | ☑ | ☐ | ☐ | ☑ | ☑ |
| Excavator Only | ☑ | ☑ | ☐ | ☐ | ☑ | ☑ |
| Front Teeth Only | ☐ | ☐ | ☐ | ☐ | ☐ | ☐ |

交互规则：

- 每个复选框独立控制一个实际 Runtime 模态；
- 不存在隐藏的二级选择；
- 不自动把原始数据和预览图捆绑；
- 取消一个选项不会影响其他选项；
- UI 直接显示输出格式，减少歧义；
- `启用` 控制该传感器是否采集对应 Variant；
- Variant 已启用但没有选择任何模态时，立即显示错误；
- 插件不支持的输出显示为禁用状态，而不是等到 Preflight 才报错。

例如：

```text
☑ RGB                  PNG
☑ Depth Data           NPY
☐ Depth Color          PNG
☑ Semantic ID          NPY
☑ Semantic Color       PNG
```

### 3.2 更多输出

Surface Normal、Instance ID 等继续放在 `更多输出` 折叠区域，展开后也全部平铺：

```text
☐ Surface Normal Data
☐ Surface Normal Color
☐ Instance ID
☐ Instance Color
```

“更多输出”只是 UI 折叠，不产生额外绑定关系。

### 3.3 批量输出预设

保留批量预设，但预设只负责批量勾选。使用后所有选项仍可独立修改：

```text
[RGB + 语义]
→ RGB
→ Semantic ID
→ Semantic Color

[深度完整输出]
→ Depth Data
→ Depth Color

[全部常用输出]
→ RGB
→ Depth Data
→ Depth Color
→ Semantic ID
→ Semantic Color

[仅语义]
→ Semantic ID
→ Semantic Color
```

预设不会把这些选项绑定为不可拆分的组合。

## 4. Render 默认策略

### 4.1 默认预设

新建项目时，Render Preset 默认选中：

```text
Path Tracing 正式质量
```

不再默认使用 Realtime 或快速检查。

建议的预设区域：

```text
渲染预设

● Path Tracing 正式质量
○ Path Tracing 快速验证
○ Realtime 快速验证
○ 自定义

当前设置：
PathTracing · 1280×720 · Denoiser On
[查看详细参数]
```

### 4.2 预设行为规则

1. 新建项目默认选择 `Path Tracing 正式质量`。
2. 编译出的 JobSpec 默认使用 `PathTracing`。
3. 打开旧项目时保留旧项目保存的渲染参数，不强制覆盖。
4. 用户修改正式质量参数后，界面状态变成 `自定义`。
5. 用户可以一键恢复 `Path Tracing 正式质量`。
6. Realtime 仍作为可选的快速诊断预设，但不是默认值。
7. Review 页面必须显示实际渲染器、分辨率、SPP、反弹次数和预计耗时。
8. 不允许为了提高速度在后台自动降级成 Realtime。

正式质量的具体 SPP、分辨率、反弹次数和 Denoiser 参数应保存在独立的预设配置中，避免硬编码在 UI 组件里。后续经过远端性能测试后，可以修改预设参数而不重写界面。

## 6. 项目打开和路径选择

### 6.1 项目入口

Studio 启动后首先提供：

```text
新建项目
打开项目
最近使用
```

`打开项目` 不只增加普通文本路径按钮，而是打开远端云电脑文件系统中的可视化目录选择器。

### 6.2 `.swproject` 目录选择

因为 `.swproject` 是工程目录而不是单独文件，选择器应：

- 选择 `.swproject` 目录；
- 自动识别其中的 `project.json`；
- 隐藏 `.revisions` 等内部实现目录；
- 显示项目名称、USD 路径和最后修改时间；
- 记住上次打开的位置；
- 提供最近项目列表和常用目录快捷入口。

常用目录示例：

```text
/root/gpufree-data/semantic/projects
/root/gpufree-data/semantic/IsaacSim_Asset
/root/gpufree-data/semantic/output
```

### 6.3 其他路径选择器

| 字段 | 选择器 |
|---|---|
| Project directory | `.swproject` 目录选择器 |
| USD path | `.usd/.usda/.usdc` 文件选择器 |
| Output root | 目录选择器 |
| CSV source | `.csv` 文件选择器 |
| Semantic mapping | `.json/.yaml` 文件选择器 |

所有选择器访问云电脑 Linux 文件系统，不访问本地 Windows 文件系统。

## 7. Stage 与 Sensor 交互整合

普通用户不需要先理解 Stage，再理解 Sensor Plugin。打开 USD 后自动执行：

1. 加载 Stage；
2. 索引 Prim；
3. 自动发现所有兼容传感器；
4. 根据 USD Schema 自动判断传感器类型和插件；
5. 显示成可勾选列表。

建议界面：

```text
选择传感器

搜索：[ Camera________________ ]  类型：[全部 ▼]

☑ Boom Camera
  类型：OpenCV Pinhole Camera
  Prim：/Excavator_Fangshan_03/boom_prim/Camera
  状态：可用
  [在视口中定位] [查看参数]

☐ Rear Camera
  类型：Pinhole Camera
  Prim：/Excavator_Fangshan_03/rear/Camera
  状态：可用

☐ Roof Lidar
  类型：RTX LiDAR
  Prim：/World/Sensors/Lidar
  状态：可用
```

用户只负责勾选。插件 ID 由系统识别，Sensor ID 根据 Prim 名称自动生成，只有冲突或高级需求时才要求用户修改。

默认详情显示：

```text
参数来源：USD Stage
分辨率：1280 × 720
镜头模型：OpenCV Pinhole
内参：已读取
世界变换：已读取
```

只有点击 `覆盖参数` 后才展开 Overrides JSON 或结构化覆盖表单。

## 8. 场景 Variant 创建器

当前 `Variant ID + Include paths` 文本输入改为场景变体生成器。

点击：

```text
+ 新建场景变体
```

进入以下流程。

### 8.1 选择创建方式

```text
● 只显示选中的对象
○ 隐藏选中的对象
○ 完整场景副本
○ 高级路径配置
```

### 8.2 在 Stage 树选择对象

```text
搜索：[ Excavator____________ ]

☑ /Excavator_Fangshan_03
  ☐ track_prim
  ☐ boom_prim
  ☐ arm_prim
  ☐ bucket_prim

[使用当前 Viewport/Stage 选中对象]
```

用户不需要复制 Prim Path。

### 8.3 环境保留选项

```text
☑ 保留灯光
☐ 保留地面
☐ 保留天空
☑ 始终保留采集传感器
```

系统自动把必要对象加入 `protected_paths` 或等效配置，避免 RGB 任务因为灯光被隐藏而发黑。

### 8.4 自动命名

选择 `/Excavator_Fangshan_03` 后，自动建议：

```text
显示名称：Excavator Only
内部 ID：excavator_only
```

用户可以修改显示名称，但通常不需要手工创建合法 ID。

### 8.5 Variant 卡片与预览

```text
Full Scene
完整场景 · 系统默认
[预览]

Excavator Only
只显示：/Excavator_Fangshan_03
保留灯光：是
[预览] [复制] [编辑] [删除]
```

预览通过匿名 Session Layer 应用可见性，不修改源 USD。用户可以在正式采集前确认对象范围、灯光、相机保护和最终构图。

## 9. Sensor 与 Variant 的绑定

必须在 UI 概念上区分：

- Variant 存在：项目定义了一个场景状态；
- Sensor 使用 Variant：某个传感器是否需要在这个场景状态下采集。

Variant 页面只定义场景内容：

```text
Full Scene
Excavator Only
Front Teeth Only
```

采集内容页面决定绑定关系和输出：

```text
Boom Camera
├─ Full Scene          已启用
├─ Excavator Only      已启用
└─ Front Teeth Only    未启用
```

UI 显示明确的 `启用此场景变体` 开关，不使用“模态列表为空”作为用户不可见的启用状态。底层在不修改 Schema 的情况下，可以暂时继续把关闭状态映射为空模态列表。

## 10. 编辑状态和保存

删除普通模式中的以下反复操作：

```text
Load row
Apply row
Apply render profile
Apply capture schedule
Apply semantic profile
```

表单和复选框修改后立即更新内存编辑模型，顶部统一显示：

```text
My Semantic Capture    ● 有未保存修改    [撤销] [保存]
```

统一保存项目。`Apply` 只保留给会立即改变 Viewport 或 Runtime 临时状态的操作，例如 Variant 预览和传感器临时覆盖。

## 11. 实时校验和防错

### 11.1 传感器层

- 不兼容的模态复选框直接禁用；
- 相机 Prim 不存在时显示错误；
- 同一 Prim 重复添加时警告；
- 自动显示插件和镜头类型；
- Stage 参数读取失败时显示具体字段。

### 11.2 Variant 层

- 未选择对象时禁止创建 Include Variant；
- RGB 开启但灯光全部隐藏时显示警告；
- Prim Path 失效时立即标红；
- 传感器路径会被隐藏时自动保护并说明。

### 11.3 采集量估算

随配置变化实时更新：

```text
2 个传感器
3 个场景变体
5 个启用组合
100 帧
预计 500 个 Capture Group
预计 2,000 个文件
预计占用 18.4 GiB
```

以大臂相机任务为例。

### 12.1 打开项目

```text
打开项目…
→ 选择 my_capture.swproject
```

系统自动加载项目和 USD。

### 12.2 选择传感器

系统自动发现：

```text
☑ Boom Camera
  /Excavator_Fangshan_03/boom_prim/Camera
  OpenCV Pinhole · 1280×720
```

用户只勾选一次。

### 12.3 创建 Variant

项目已有 `Full Scene`。点击：

```text
+ 新建场景变体
→ 只显示选中对象
→ Stage 树勾选 Excavator_Fangshan_03
→ 保留灯光
→ 创建
```

自动得到 `Excavator Only`。

### 12.4 配置采集内容

选择 `Boom Camera`，配置：

| 场景 | 启用 | RGB | Depth NPY | Depth Color | Semantic ID | Semantic Color |
|---|---:|---:|---:|---:|---:|---:|
| Full Scene | ☑ | ☑ | ☐ | ☐ | ☑ | ☑ |
| Excavator Only | ☑ | ☑ | ☐ | ☐ | ☑ | ☑ |

### 12.5 渲染与帧数

新项目默认显示：

```text
Path Tracing 正式质量
```

用户调整帧数。只有需要快速诊断时，才主动切换到 `Realtime 快速验证`。

### 12.6 Review 与运行

```text
传感器：1
场景变体：2
启用采集组合：2

Full Scene：
  RGB PNG
  Semantic ID NPY
  Semantic Color PNG

Excavator Only：
  RGB PNG
  Semantic ID NPY
  Semantic Color PNG

Renderer：
  PathTracing · 正式质量

状态：
  可以运行
```

点击 `Run Headless` 后沿用现有 Compiler、Supervisor、Job Runner 和 Segment Worker 链路。

## 13. 实施重点与顺序

### 13.1 第一阶段：核心交互

1. Project、USD、Output、CSV 可视化路径选择器；
2. 最近项目入口；
3. Stage 自动加载和传感器自动发现；
4. 传感器勾选列表；
5. Variant 可视化创建器；
6. 明确的 `Sensor 是否启用某个 Variant` 开关；
7. 五个相机基础输出独立复选框；
8. Capability 驱动的更多输出；
9. 删除基本模式中的 `Load row/Apply row`；
10. Render Preset，默认 `Path Tracing 正式质量`；
11. Review 与自动 Preflight；
12. Basic/Advanced 模式分离。

### 13.2 第二阶段：Variant 体验

1. Stage 树选择器；
2. 从当前选择创建 Variant；
3. 自动生成 Variant ID；
4. 保留灯光、地面、天空选项；
5. Viewport Variant 预览；
6. Variant 复制和模板。

### 13.3 第三阶段：复用与质量保障

1. 输出、Variant、Render 预设；
2. 最近项目和项目模板；
3. 实时文件量、空间和 Capture Group 估算；
4. 内联校验；
5. 最终 Review 页面；
6. 更清晰的任务历史和输出浏览入口。

## 14. 模块边界

本阶段应保持以下边界：

```text
Kit UI Components
    ↓ 用户选择、复选框、预设、文件选择器
Studio View Model / Application Service
    ↓ 把 UI 状态映射为领域模型操作
ProjectDefinition / Plugin Capabilities
    ↓ 保存传感器、Variant、模态和渲染配置
JobCompiler
    ↓ 生成不可变 JobSpec
SameHostSupervisor
    ↓ 启动和监控任务
Headless Runtime
```

前端不得硬编码传感器 Driver 的运行逻辑。基础模态展示顺序可以由 Studio 定义，但是否支持必须来自 Plugin Capability。文件选择器、Variant 创建器、采集矩阵和 Render Preset 均应拆分成独立 UI 组件，避免再次形成单一超长 Extension 文件。

## 15. 验收标准

完成本阶段后，应满足：

1. 用户可以通过文件选择器打开 `.swproject`，无需手工输入项目路径；
2. 打开项目后能自动加载 USD 并发现已有传感器；
3. 用户不需要手工输入 `pinhole_camera` 等 Plugin ID；
4. 用户可以从 Stage 树或当前选择创建 Variant，无需手工复制 Prim Path；
5. 每个 Sensor × Variant 组合都有明确启用开关；
6. RGB、Depth NPY、Depth Color、Semantic ID、Semantic Color 是五个独立复选项；
7. UI 不再通过二级 Depth 下拉框控制两个输出；
8. 基本模式不需要输入模态字符串；
9. 新项目默认使用 `Path Tracing 正式质量`；
10. 打开旧项目不会覆盖其已保存的 Render 配置；
11. Review 页面能显示真实输出文件类型和实际渲染配置；
12. `Run Headless` 继续复用现有稳定的 Headless 执行链路；
13. 所有前端选择都能保存进 `.swproject` 并在重新打开后正确恢复；
14. Runtime 数据集目录、Ledger、断点恢复和输出格式保持兼容。

## 16. 总结

v04.4 的核心不是增加更多参数，而是把已有能力重新组织成低输入、可视化、可检查的任务流程：

```text
文件选择器
→ 自动 Stage 索引
→ 传感器自动发现与勾选
→ Variant 可视化生成
→ Sensor × Variant × 独立输出复选矩阵
→ Path Tracing 正式质量默认预设
→ Review / Preflight
→ Headless Runtime
```

该调整只改变 Studio 的用户体验和项目编辑入口，不破坏 v04.3 已完成的插件化传感器、不可变 JobSpec、分段执行、原子输出和断点恢复架构。
