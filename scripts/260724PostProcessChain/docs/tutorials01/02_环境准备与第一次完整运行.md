# 02 环境准备与第一次完整运行

本章先用两帧微型数据跑通整个链路。完成后，你将拥有一个可随时重置、便于调试的最小实验。

## 1. 环境要求

当前版本已在 Python 3.9.18 上通过完整测试，建议使用 Python 3.9 或更高版本。源码启用了延迟注解，因此其中的现代类型标注在该已验证版本可用。运行依赖只有：

- NumPy：读取和处理 `.npy` semantic 数组；
- Pillow：读取 RGB 尺寸和创建测试图片。

在项目根目录执行：

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

如果 PowerShell 阻止激活脚本，可只对当前进程临时放开：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

也可以不激活，后续把 `python` 换成 `.\.venv\Scripts\python.exe`。

## 2. 先运行项目测试

```powershell
python -m unittest discover -s . -p "test_*.py" -v
```

当前版本应发现并通过 10 个测试。测试成功说明：

- Python 能导入项目；
- NumPy 与 Pillow 可用；
- 两个模块的核心算法通过；
- 单进程、多进程、断点续跑和命令行入口通过。

测试通过不代表你的业务数据一定正确，但能把“环境/代码问题”和“数据/配置问题”分开。

## 3. 生成两帧微型输入

以下命令会在项目根目录创建 `tutorial_work/input`。它不会修改正式配置。

```powershell
@'
import json
from pathlib import Path

import numpy as np
from PIL import Image

root = Path("tutorial_work/input")
rgb_dir = root / "rgb"
semantic_dir = root / "semantic_id"
rgb_dir.mkdir(parents=True, exist_ok=True)
semantic_dir.mkdir(parents=True, exist_ok=True)

colors = {
    1: (255, 80, 80),
    2: (255, 180, 60),
    3: (255, 255, 80),
    4: (80, 220, 120),
    5: (80, 160, 255),
}

def write_frame(frame_id, visible_ids):
    semantic = np.zeros((48, 64), dtype=np.uint16)
    rgb = np.zeros((48, 64, 3), dtype=np.uint8)
    for index, semantic_id in enumerate(visible_ids):
        left = 4 + index * 11
        top = 12 + index % 2
        semantic[top:top + 12, left:left + 7] = semantic_id
        rgb[top:top + 12, left:left + 7] = colors[semantic_id]
    np.save(semantic_dir / f"semantic_id_{frame_id}.npy", semantic)
    Image.fromarray(rgb).save(rgb_dir / f"rgb_{frame_id}.png")

write_frame("0000", [1, 2, 3, 4, 5])
write_frame("0001", [1, 2, 3, 4])  # 故意缺少 tooth_5

mapping = {
    "schema_version": 1,
    "dataset_dtype": "uint16",
    "classes": [
        {"id": value, "label": f"tooth_{value}"}
        for value in range(1, 6)
    ],
}
(root / "semantic_mapping.json").write_text(
    json.dumps(mapping, ensure_ascii=False, indent=2) + "\n",
    encoding="utf-8",
)
print(root.resolve())
'@ | python -
```

得到：

```text
tutorial_work/input/
├─ rgb/
│  ├─ rgb_0000.png
│  └─ rgb_0001.png
├─ semantic_id/
│  ├─ semantic_id_0000.npy
│  └─ semantic_id_0001.npy
└─ semantic_mapping.json
```

第 0 帧有五个斗齿标签；第 1 帧故意缺少 `tooth_5`，用于观察集合框模块的排除策略。

## 4. 创建教程总配置

新建 `tutorial_work/orchestrator.demo.json`，内容如下：

```json
{
  "schema_version": 1,
  "inputs": {
    "rgb_dir": "input/rgb",
    "semantic_dir": "input/semantic_id",
    "semantic_mapping": "input/semantic_mapping.json"
  },
  "output_root": "output/run_001",
  "execution": {
    "workers": 1,
    "max_in_flight": 1,
    "overwrite": false,
    "on_frame_error": "continue"
  },
  "output": {
    "image_mode": "hardlink_or_copy",
    "write_manifest": true
  },
  "modules": [
    {
      "id": "tooth_boxes",
      "type": "semantic_yolo_boxes",
      "enabled": true,
      "config": "../postprocess_chain/modules/semantic_yolo_boxes/semantic_yolo_boxes.json",
      "depends_on": []
    },
    {
      "id": "tooth_group",
      "type": "tooth_group_yolo",
      "enabled": true,
      "config": "../postprocess_chain/modules/tooth_group_yolo/tooth_group_yolo.json",
      "depends_on": ["tooth_boxes"]
    }
  ]
}
```

这里所有相对路径都以 `tutorial_work` 为基准，因为总配置文件就在该目录。

第一次练习使用 `workers=1`，这样错误顺序最容易理解。确认结果后再改成多进程。

## 5. 运行

```powershell
python run_pipeline.py --config tutorial_work\orchestrator.demo.json
$LASTEXITCODE
```

预期终端摘要：

```text
post-process chain completed
discovered frames: 2
completed frames: 2
failed frames: 0
tooth_boxes: written=2, ... boxes=9
tooth_group: written=1, ... excluded=1, ... boxes=1
```

退出码应为 `0`。这里的 `excluded=1` 不是错误：第 1 帧缺少配置的端部
`tooth_5`，集合框模块按 `exclude_frame` 主动不输出这一帧。

## 6. 检查结果

```text
tutorial_work/output/run_001/
├─ manifest.json
├─ summary.json
└─ modules/
   ├─ tooth_boxes/
   │  ├─ classes.txt
   │  ├─ rgb_0000.png
   │  ├─ rgb_0000.txt
   │  ├─ rgb_0001.png
   │  └─ rgb_0001.txt
   └─ tooth_group/
      ├─ classes.txt
      ├─ rgb_0000.png
      └─ rgb_0000.txt
```

观察标签：

```powershell
Get-Content tutorial_work\output\run_001\modules\tooth_boxes\rgb_0000.txt
Get-Content tutorial_work\output\run_001\modules\tooth_group\rgb_0000.txt
Get-Content tutorial_work\output\run_001\summary.json
```

`tooth_boxes/rgb_0000.txt` 应有 5 行，且每行 class ID 都是 `0`；第 1 帧应有 4 行。
`tooth_group` 中没有 `rgb_0001.*`，因为这一帧被排除，而不是被写成负样本。

## 7. 验证断点续跑

原样再次运行：

```powershell
python run_pipeline.py --config tutorial_work\orchestrator.demo.json
```

这次 `summary.json` 中：

- `tooth_boxes.skipped` 应为 2；
- `tooth_group.skipped` 应为 1；
- `tooth_group.excluded` 仍为 1。

上游虽然不重写已有标签，仍会重新计算 `SemanticBoxSet`，因为下游需要这个只存在于内存中的中间产物。

## 8. 验证多进程

把配置改为：

```json
"workers": 2,
"max_in_flight": 2
```

再运行。已有输出会显示为 `skipped`，结果应仍然成功。这同时验证模块实例能被多进程序列化。

## 常见问题

### `ModuleNotFoundError`

确认终端当前目录是项目根目录，而不是工作区根目录或 `docs` 目录。

### `RGB directory does not exist`

相对路径按总配置所在目录解析。检查实际解析基准是否为 `tutorial_work`。

### `semantic label ... is absent from mapping`

模块默认使用 `tooth_1` 到 `tooth_5`。mapping 必须逐字包含这些名称。

### 旧输出与新配置冲突

如果修改了模块配置，使用新的 `output_root`；学习阶段最清楚的做法是把
`run_001` 改为 `run_002`。
