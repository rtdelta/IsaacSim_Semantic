# 11 真实数据实战与掌握清单

本章使用当前工作区已有的 499 帧 Fangshan 数据：

```text
WORKSPACE_ROOT/output/
└─ Sim_FangShan_02_manual_02_native_60hz_10fps_499f_20260715_01/
```

已检查到：

```text
rgb/                    499 个 rgb_*.png
semantic_id/            499 个 semantic_id_*.npy
semantic_mapping.json
```

mapping 使用：

```text
tooth_01, tooth_02, tooth_03, tooth_04, tooth_05
```

而项目默认模块配置使用：

```text
tooth_1, tooth_2, tooth_3, tooth_4, tooth_5
```

因此不能直接复用默认模块 JSON，必须创建数据集专用配置。

## 1. 实战目录

在项目根目录创建：

```text
tutorial_work/fangshan02/
├─ orchestrator.json
├─ semantic_boxes.json
├─ tooth_group.json
└─ output/
```

不要修改 `configs/orchestrator.example.json`，也不要覆盖内置模块默认配置。

## 5. 第一阶段：标签试跑

```powershell
python run_pipeline.py --config tutorial_work\fangshan02\orchestrator.json
$LASTEXITCODE
```

第一阶段故意使用：

```json
"workers": 1,
"image_mode": "none"
```

目标是先验证：

- 499 帧能完整配对；
- label 命名正确；
- 没有 dtype/shape 错误；
- 两模块 metrics 合理；
- 输出标签可解析。

检查：

```powershell
Get-Content tutorial_work\fangshan02\output\run_001_labels_only\summary.json
Get-Content tutorial_work\fangshan02\output\run_001_labels_only\manifest.json
Test-Path tutorial_work\fangshan02\output\run_001_labels_only\errors.jsonl
```

不要预设每帧都有五齿或集合框。遮挡、出画和小 mask 都可能造成缺失；应结合 semantic_color 或 RGB 抽查判断是否合理。

## 7. 抽查一帧 YOLO 框

以下脚本从正式输出读取第一张图和标签，画框到
`tutorial_work/fangshan02/review_rgb_0000.png`：

```powershell
@'
from pathlib import Path

from PIL import Image, ImageDraw

module_dir = Path(
    "tutorial_work/fangshan02/output/run_002_formal/modules/tooth_boxes"
)
image_path = module_dir / "rgb_0000.png"
label_path = module_dir / "rgb_0000.txt"
output_path = Path("tutorial_work/fangshan02/review_rgb_0000.png")

image = Image.open(image_path).convert("RGB")
draw = ImageDraw.Draw(image)
width, height = image.size

for line in label_path.read_text(encoding="utf-8").splitlines():
    class_id, xc, yc, bw, bh = line.split()
    xc, yc, bw, bh = map(float, (xc, yc, bw, bh))
    left = (xc - bw / 2) * width
    top = (yc - bh / 2) * height
    right = (xc + bw / 2) * width
    bottom = (yc + bh / 2) * height
    draw.rectangle((left, top, right, bottom), outline="red", width=3)
    draw.text((left, top), class_id, fill="yellow")

image.save(output_path)
print(output_path.resolve())
'@ | python -
```

至少抽查：

- 五齿都可见的帧；
- 一个端部遮挡的帧；
- 小 mask 临界帧；
- 相机运动的不同阶段；
- 集合框被排除的帧；
- 单齿框跨度异常大的帧。

## 8. 用 metrics 做数据体检

关注单齿模块：

```text
boxes
small_masks
missing_masks
```

关注集合模块：

```text
written
excluded
missing_endpoints
```

建议计算：

```text
平均单齿框数 = tooth_boxes.boxes / completed_frames
集合保留率   = tooth_group.written / completed_frames
端点缺失率   = missing_endpoints / completed_frames
```

这些指标没有统一“正确值”，要与相机视角和遮挡设计对照。突然偏离历史批次时，应先检查 mapping、相机和 semantic 标签。

## 10. 对接新版采集目录时

上游采集可能按场景变体输出：

```text
full_scene_excavator_rgb/
full_scene_excavator_semantic/semantic_id/
excavator_only_rgb/
excavator_only_semantic/semantic_id/
semantic_mapping.json
```

本项目不关心目录名本身，只关心总配置是否分别指向：

- 一组 `rgb_*.png`；
- 与之同 frame ID 的 `semantic_id_*.npy`；
- 对应 mapping。

全场景 RGB 必须配全场景 semantic；孤立挖掘机 RGB 必须配孤立 semantic。不要跨变体混配。

## 11. 下游训练前还缺什么

当前 `flat_yolo` 布局把图片、标签和 `classes.txt` 放在同一模块目录。许多训练框架期望：

```text
images/train/
labels/train/
images/val/
labels/val/
data.yaml
```

本项目当前不负责：

- train/val/test 切分；
- 平铺目录重组；
- `data.yaml`；
- 数据增强；
- 训练。

应在审计本项目输出后，另写可重复的打包步骤。切分要按轨迹/场景防止相邻帧泄漏，不能只随机打散高度相似的连续帧。
