## 2. 推荐搜索命令

列出项目文件：

```powershell
rg --files
```

找配置字段：

```powershell
rg -n "max_in_flight|missing_policy|source_artifact" .
```

找状态产生位置：

```powershell
rg -n '"written"|"skipped"|"excluded"|"blocked"' postprocess_chain
```

找模块注册：

```powershell
rg -n "register_module" postprocess_chain
```

只列测试：

```powershell
rg --files -g "test_*.py"
```

## 4. 术语表

### artifact

当前帧内、当前 worker 内由上游模块发布给下游的内存对象。完整引用为
`<module_id>.<artifact_name>`，不跨帧持久化。

### blocked

模块的计算依赖没有 ready，因此本模块未执行。通常是上游 `process_frame` 失败。

### bounding box / bbox

包围目标像素的矩形。本项目使用像素半开区间。

### computationally ready

模块 `process_frame` 已成功返回且 artifacts 已发布。它不保证上游 YOLO 文件一定写出成功。

### config fingerprint

用于防止输出目录混入不同 mapping/模块业务配置的 SHA-256。它不是输入文件内容哈希。

### disposition

模块对当前帧的处理意图：`write` 或 `exclude`。

### endpoint

集合框算法选中的两个端部 `SemanticBox`。

### exclude

该帧不进入某模块的数据集。不是空标签，也不是错误。

### flat_yolo

当前唯一输出布局：模块目录中平铺图片、同名 `.txt` 和 `classes.txt`。

### frame ID

从 `rgb_` 与 `.png` 之间、或 `semantic_id_` 与 `.npy` 之间提取的字符串，用于帧配对。

### hard link

同一文件系统上多个目录项引用同一文件数据。当前默认图片模式优先使用它。

### mapping

描述 semantic label 与整数 semantic ID 对应关系的 JSON。

### mask

semantic 数组中等于某目标 ID 的像素集合。

### max in flight

进程池中已提交但尚未回收的最大帧任务数，不是 worker 数。

### metric

模块返回并在 summary 中跨帧累加的整数业务计数。

### NPY

NumPy 原生数组文件。当前 semantic 输入必须是二维且不使用 pickle。

### PixelBox

`[left, top, right, bottom)` 半开像素框。

### semantic ID

semantic 数组中的整数类别值。

### semantic label

mapping 中人可读的语义名称，例如 `tooth_01`。

### stable topological order

满足依赖关系的模块顺序；多个模块同时就绪时保留配置数组的原相对顺序。

### YOLO class

训练数据中的检测类别，由 `classes.txt` 行号表示。多个 semantic label 可映射到同一 YOLO class。

## 5. 状态速查

| 状态 | 是否写新标签 | 是否可算成功帧 | 下游计算是否一定 blocked |
| --- | --- | --- | --- |
| `written` | 是 | 是 | 否 |
| `skipped` | 否，复用已有 | 是 | 否 |
| `excluded` | 否 | 是 | 否 |
| `success` | 否，annotation=None | 是 | 否 |
| `error`：process | 否 | 否 | 是，若依赖它 |
| `error`：write | 写出失败 | 否 | 否，artifact 已 ready |
| `blocked` | 否 | 否 | 其下游也可能继续 blocked |

## 6. 退出码速查

| 退出码 | 含义 |
| --- | --- |
| `0` | 所有已发现帧无错误 |
| `1` | 至少一帧失败或 blocked |
| `2` | 配置、启动或其他未处理全局异常 |
| `130` | 用户中断 |

## 7. 当前设计限制

知道限制也是掌握的一部分：

- 只发现平铺、固定命名的 PNG/NPY；
- frame ID 按字符串排序；
- semantic label 是整图一个框，不拆连通域；
- 集合框只使用两个端点；
- 只支持 `flat_yolo`；
- 模块基类默认要求至少一个 YOLO class；
- artifact 不持久化；
- 指纹不包含输入帧内容；
- 没有 train/val/test 切分和训练配置；
- 没有专用部署脚本；
- 多进程 fail-fast 不立即取消 pending 任务。

这些不是隐藏 bug，而是当前项目边界。需求超出边界时，应新增经过测试的能力。

## 9. 最后一张心智图

```text
配置层：声明“数据在哪里、模块是谁、谁依赖谁”
   │
   ▼
调度层：校验、排序、发现帧、并行、汇总
   │
   ▼
帧上下文：一帧只加载一次，模块共享
   │
   ▼
业务模块：输入 FrameContext/artifact，返回 ModuleResult
   │
   ▼
输出层：统一校验 YOLO、原子写出、续跑
   │
   ▼
审计层：manifest + summary + errors
```

当你能从任一错误或需求沿这张图定位到对应层和源码文件，就真正掌握了当前项目。
