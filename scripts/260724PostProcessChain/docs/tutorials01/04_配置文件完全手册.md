# 04 配置文件完全手册

项目采用两级配置：

```text
总调度器 JSON
├─ 输入、输出、并行、模块启停和依赖
├─ 指向 semantic_yolo_boxes 的业务 JSON
└─ 指向 tooth_group_yolo 的业务 JSON
```

这样修改业务阈值不会污染调度参数，也让不同模块保持独立。

## 1. 路径解析的总原则

总配置中的以下路径都相对“总配置所在目录”：

- `inputs.rgb_dir`
- `inputs.semantic_dir`
- `inputs.semantic_mapping`
- `output_root`
- 每个模块的 `config`

模块配置的 `output.directory` 则相对总配置解析出的 `output_root`。

终端当前目录只影响 Python 能否导入项目，不改变 JSON 的相对路径基准。

## 2. 总调度器完整结构

```json
{
  "schema_version": 1,
  "inputs": {
    "rgb_dir": "...",
    "semantic_dir": "...",
    "semantic_mapping": "..."
  },
  "output_root": "...",
  "execution": {
    "workers": 8,
    "max_in_flight": 16,
    "overwrite": false,
    "on_frame_error": "continue"
  },
  "output": {
    "image_mode": "hardlink_or_copy",
    "write_manifest": true
  },
  "modules": []
}
```

项目严格拒绝未知字段。拼错字段不会被静默忽略，而会立即报错。

### 2.1 顶层字段

| 字段 | 必需 | 规则 |
| --- | --- | --- |
| `schema_version` | 是 | 当前只能是 `1` |
| `inputs` | 是 | 必须是对象 |
| `output_root` | 是 | 输出根目录 |
| `execution` | 是 | 必须是对象，内部字段可用默认值 |
| `output` | 是 | 必须是对象，内部字段可用默认值 |
| `modules` | 是 | 非空数组 |

### 2.2 `inputs`

| 字段 | 规则 |
| --- | --- |
| `rgb_dir` | 启动时必须是已存在目录 |
| `semantic_dir` | 启动时必须是已存在目录 |
| `semantic_mapping` | 启动时必须是已存在文件 |

`output_root` 不能与 RGB/semantic 输入目录相同，也不能互相包含。例如不能把输出放进 `rgb_dir/processed`，也不能把整个输入放在输出目录下面。这能避免后处理结果被误当成下一次输入。

### 2.3 `execution`

| 字段 | 默认值 | 约束与含义 |
| --- | --- | --- |
| `workers` | `min(CPU数, 8)` | 至少 1；进程数量 |
| `max_in_flight` | `workers * 2` | 至少为 `workers`；同时已提交但未回收的帧数上限 |
| `overwrite` | `false` | 是否重写已有标签并清理应排除的旧帧 |
| `on_frame_error` | `continue` | `continue` 或 `fail_fast` |

`max_in_flight` 是背压参数，不是 worker 数。它防止一次把全部帧都提交给进程池。调试时使用：

```json
"workers": 1,
"max_in_flight": 1
```

批量运行的起点可用：

```json
"workers": 8,
"max_in_flight": 16
```

`fail_fast` 在单进程下遇到第一帧错误立即停止；多进程下停止继续提交，但已经提交的任务仍可能完成。

### 2.4 `output`

| 字段 | 默认值 | 可选值 |
| --- | --- | --- |
| `image_mode` | `hardlink_or_copy` | `hardlink_or_copy`、`copy`、`none` |
| `write_manifest` | `true` | 布尔值 |

图片模式：

- `hardlink_or_copy`：先尝试硬链接，跨磁盘或文件系统不支持时复制；
- `copy`：总是复制，最直观但占更多空间；
- `none`：只写标签，不向模块目录物化图片。

`none` 适合算法调试或已有统一图片目录的训练流程，但此时模块输出本身不是完整的“图片 + 标签”数据集。

### 2.5 `modules`

每项格式：

```json
{
  "id": "tooth_boxes",
  "type": "semantic_yolo_boxes",
  "enabled": true,
  "config": "../postprocess_chain/modules/semantic_yolo_boxes/semantic_yolo_boxes.json",
  "depends_on": []
}
```

| 字段 | 必需 | 含义 |
| --- | --- | --- |
| `id` | 是 | 本次流水线中的实例名，也成为 artifact 命名空间 |
| `type` | 是 | 注册的 Python 模块类型 |
| `enabled` | 否 | 默认 `true` |
| `config` | 是 | 业务配置路径 |
| `depends_on` | 否 | 默认空数组 |

规则：

- ID 不能重复；
- 依赖不能重复、不能指向自身；
- 依赖必须存在且启用；
- 依赖图不能成环；
- 所有启用模块的输出目录不能相同；
- 禁用上游而启用依赖它的下游会在启动阶段失败。

数组书写顺序只在多个模块同为“就绪”时用作稳定排序。真正的先后由依赖关系决定。

## 3. `semantic_yolo_boxes` 配置

```json
{
  "schema_version": 1,
  "output": {
    "directory": "modules/tooth_boxes",
    "layout": "flat_yolo"
  },
  "min_pixels": 10,
  "targets": [
    {
      "yolo_id": 0,
      "yolo_name": "tooth",
      "semantic_labels": [
        "tooth_1",
        "tooth_2",
        "tooth_3",
        "tooth_4",
        "tooth_5"
      ]
    }
  ]
}
```

### 3.1 输出

- `directory` 必须是相对路径；
- 解析后必须仍在 `output_root` 内，不能用 `..` 逃逸；
- `layout` 当前只支持 `flat_yolo`。

### 3.2 `min_pixels`

默认 `10`，至少 `1`。某 label 的真实 semantic 像素数小于它时，不写 YOLO detection；恰好等于阈值会保留。

重要：小框仍保留在发布给下游的 `SemanticBoxSet` 中。下游有自己的阈值。

### 3.3 `targets`

每个 target 表示一个 YOLO class：

```json
{
  "yolo_id": 0,
  "yolo_name": "tooth",
  "semantic_labels": ["tooth_1", "tooth_2"]
}
```

规则：

- targets 非空；
- `yolo_id` 从 0 开始连续，不能是 `0, 2`；
- ID 和 name 都不能重复；
- semantic label 在整个模块配置中不能重复分配；
- 每个 semantic label 必须存在于全局 mapping；
- 一个 target 可接收多个 semantic label。

多类别示例：

```json
"targets": [
  {
    "yolo_id": 0,
    "yolo_name": "tooth",
    "semantic_labels": ["tooth_1", "tooth_2"]
  },
  {
    "yolo_id": 1,
    "yolo_name": "bucket",
    "semantic_labels": ["bucket_noteeth"]
  }
]
```

对应 `classes.txt`：

```text
tooth
bucket
```

## 4. `tooth_group_yolo` 配置

```json
{
  "schema_version": 1,
  "source_artifact": "tooth_boxes.semantic_boxes",
  "output": {
    "directory": "modules/tooth_group",
    "layout": "flat_yolo"
  },
  "class": {
    "yolo_id": 0,
    "yolo_name": "tooth_group"
  },
  "endpoint_selector": {
    "type": "semantic_labels",
    "labels": ["tooth_1", "tooth_5"]
  },
  "min_pixels": 10,
  "missing_policy": "exclude_frame"
}
```

### 4.1 `source_artifact`

格式必须是：

```text
<上游模块id>.<产物名>
```

当前上游发布名为 `semantic_boxes`。如果总配置把上游 ID 改成
`my_boxes`，这里必须同步改为：

```json
"source_artifact": "my_boxes.semantic_boxes"
```

而且 `my_boxes` 必须出现在本模块的 `depends_on` 中。

### 4.2 单类别

当前集合模块只支持一个 YOLO class，因此 `class.yolo_id` 必须为 `0`。

### 4.3 端点选择器

精确物理标签：

```json
"endpoint_selector": {
  "type": "semantic_labels",
  "labels": ["tooth_1", "tooth_5"]
}
```

必须恰好配置两个不同 label。适合端部语义标签稳定的数据。

画面极值：

```json
"endpoint_selector": {
  "type": "image_extrema",
  "labels": ["tooth_1", "tooth_2", "tooth_3", "tooth_4", "tooth_5"]
}
```

至少两个不同候选 label。模块从当前可见且达到阈值的候选中选画面最左与最右框。

### 4.4 `min_pixels`

默认 `10`，至少 `1`。它独立于上游模块的阈值，因为下游读取的是包含小框的 artifact。

例如：

```text
上游 min_pixels = 20
下游 min_pixels = 10
```

一个 15 像素的斗齿不会进入上游 YOLO 标签，但仍可能成为集合框端点。这是当前设计允许的，不是矛盾。

### 4.5 `missing_policy`

| 值 | 端点不足时的行为 | 适用场景 |
| --- | --- | --- |
| `exclude_frame` | 不输出该帧 | 默认；避免错误负样本 |
| `empty_label` | 写空 `.txt` | 确认端点不足等价于“无目标”时 |
| `error` | 该模块报错 | 数据必须完整，缺失不可接受时 |
| `visible_extrema` | 从所有合格上游框回退选左右极值；仍不足则排除 | 端部标签可能出画但至少有两个可见齿时 |

`visible_extrema` 的回退范围是所有上游合格框，不局限于 selector 中的 labels。

## 5. 常见配置错误

### 改了模块 ID，却没改 artifact

```json
"id": "fangshan_boxes"
```

下游必须同步：

```json
"source_artifact": "fangshan_boxes.semantic_boxes",
"depends_on": ["fangshan_boxes"]
```

### 模块 label 与 mapping 不一致

mapping 是 `tooth_01`，默认模块配置是 `tooth_1`。必须创建一份数据集专用模块配置，不要指望自动转换。

### 两个模块共用输出目录

即使类别不同也会被拒绝，因为会覆盖 `classes.txt` 和同名帧标签。

### 修改参考模板

建议保留 `configs/orchestrator.example.json` 不动，为每个数据集创建独立总配置和独立 `output_root`。这使运行可复现，也减少覆盖错误。

## 6. 配置变更策略

推荐目录：

```text
tutorial_work/
├─ orchestrator.dataset_A.json
├─ semantic_boxes.dataset_A.json
├─ tooth_group.dataset_A.json
└─ output/
   └─ dataset_A_run_001/
```

把“数据集 label 差异”放入模块配置，把“输入路径和运行资源差异”放入总配置。

每次改变业务语义时使用新的输出目录，例如：

```text
run_001_exact_endpoints
run_002_visible_extrema
run_003_min_pixels_20
```
