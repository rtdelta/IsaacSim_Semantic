# NC-004 八种链路统一复跑与实际录包图片对照

日期：2026-10-12。依据用户指定的 `docs/QandA/20261012_v06与原生采集链路统计及图片对照方案_完整问答.md`。

## 核心目标

在同一 `combine_scene_16_terrain_fisheye.usda` 下依次运行八种已有配置，保存四路可直接查看的鱼眼 PNG，并比较采集成本、画面与实际交付数据的一致性。先完成静止公共输入的三轮统计。每轮每配置六组，共 24 次独立进程测试、144 个目标组、576 张目标图片。连续 PT 已知有对齐失败，本轮保留并复核该失败，不通过修改消息时间戳使其合格。

公共输入：四路 1920×1080 鱼眼、13 路 Instant LiDAR、相同安装位姿、根节点位置和旋转、受控关节零角、同一背景 DomeLight、曝光与光学坐标约定。源轨迹复制为新输入，各行采用首行整机位姿与安装版本，关节设为零。USD 原文件不改；必要渲染场景设置只写进进程内 Session 层。

## 矩阵

| ID | 配置 | 渲染与预算 | 关键变量 |
|---|---|---|---|
| 01 | v06 冻结，逐组启停 | RT2，16 预热＋2 正式子帧 | gated 生命周期 |
| 02 | v06 冻结，常驻 | RT2，16＋2 | keepalive 生命周期 |
| 03 | 原生连续 RT2 | 原生应用逐帧更新；初始化预热 8 次 | 没有逐组 16＋2；不同质量预算 |
| 04 | 原生冻结 RT2，诊断门控 | RT2，16＋2 | 显式改接 NVIDIA Helper 的执行边 |
| 05 | 原生冻结 RT2，默认 Helper | RT2，16＋2 | 保留默认门控 |
| 06 | 原生冻结 PT，诊断门控 | 1024 总 SPP、每迭代 32、8 反弹 | 预热与正式各一次 SDK 调用，诊断改接 |
| 07 | 原生冻结 PT，默认 Helper | 同 06 | 保留默认门控 |
| 08 | 原生连续 PT | 一次 `run_async`、每图目标 1024 SPP | 原生子帧调度，检查录包与最终载荷对齐 |

RT2 的实际名称是 `RealTimePathTracing`，AA=3、DLSS=2、帧生成关闭。PT 采用独立累积设置，关闭自适应采样和时间去噪，开启空间 OptiX 去噪。总 SPP 是渲染器预算加原生调度完成证据，不是硬件射线计数。冻结 PT 两次调用可能复用或重置累积，因此不能宣称实际执行了两倍射线。

不把本轮矩阵宣称为预算、姿态、Multi-tick 的完整交叉实验；子帧/SPP 扫描、运动或安装改变属于后续独立实验。

## 执行与保存

1. 核对已登记实例身份、根 USD 哈希、空闲 GPU、磁盘和已有 Kit 进程。
2. 保存旧项目源码哈希及 ZIP。v06 使用 `single06_lab/frozen_runtime` 的保留基线；原生代码复制到本项目三套独立 engine 中，不在运行时调用旧原生项目。
3. 按配置顺序独立进程执行，上一项 Kit、录包进程退出后才启动下一项。三轮起始顺序旋转，减少固定先后顺序的影响；不清磁盘、着色器或驱动缓存。
4. 采集阶段禁用额外 RGB PNG 导出。连续 PT 为观察原生最终完成保留 BasicWriter 的 CameraParams，未额外保存 RGB。
5. 录包结束后用 ROS 标准反序列化解码实际 MCAP。原始 CompressedImage 的无损 PNG 原样保存，原生 rgb8 无损编码 PNG。图像内容 SHA-256、物理时间、消息时间、接收时间、相机参数、实际 TF 与关节数据单独保存。
6. 按相同轮次、组号和方向比较。只有数据校验成功且位姿、内参对齐的图像参与正式比较。连续 PT 的诊断载荷关联保留原始消息时间，不进入有效数据排名。
7. 输出逐组 `timing.csv`、逐轮 `comparison.csv`、配置聚合、警告分类、图像差异、并排样图和可离线打开的 HTML 索引。图片导出耗时不计入采集计时。
8. 完成后核对旧源码未改、场景根文件未改、实验自有进程退出，传输自生成证据并验证哈希。

## 耗时与资源边界

- SDK 调用：v06 `render_wait`；原生冻结 `warm_s + formal_s`。都包含 SDK 等待和回调工作，不是纯 GPU kernel 时间。
- 完整观察组：v06 从 `advance_clock` 起点到 `acquire` 完成；原生冻结从准备起点到 RGB/XYZ 观察完成。这两个范围包含的数据持有和验证工作不同。
- 连续 RT2：一帧应用更新时间，没有额外最终 RGB/XYZ 哈希观察，不能伪装成与冻结组相同的预算和工作量。
- 连续 PT：原生触发至观察完成的相邻范围可能重叠，不能把每组范围相加当作整轮耗时。应看原生 scenario 窗口及录包结果。
- capture 窗口、Kit/worker 整进程、控制器含校验总耗时分别记录。v06 capture 窗口包含写入尾部；原生 capture 窗口不包含最终排空和关闭录包。
- `frames.csv` 的 `bag_receive_stamp_ns` 是解码器早期命名，实际取自 `rosbag2_py.SequentialReader.read_next()` 返回的包内记录时间。它不是独立测得的网络接收墙钟，使用仿真时钟录包时也不是 Unix 墙钟。跨链路对齐使用消息 header 和组时间，不使用该字段计算网络延迟。
- GPU 利用率为全设备采样，不是 SM occupancy、Tensor Core 或 RT Core 的利用率。CPU 用 `/proc` 累计 ticks 差分，100% 表示一个 CPU 核。约 1 Hz 的样本不足以解释亚秒阶段，样本不足处留空。
- 显存是设备占用；RAM 是 Kit 进程 RSS。录包/编码进程的资源范围不同，单列且不假装统计了整机全部进程。
- 图片差异在解码后的 8-bit RGB 上计算。PSNR/MAE 仅表示与选定参考图的差异，不证明物理真实性或 PT 比 RT2 更准确。可视化缩略图不替代原始分辨率 PNG。

## 安全与回退
