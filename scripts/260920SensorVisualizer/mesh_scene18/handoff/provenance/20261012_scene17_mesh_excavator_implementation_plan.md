# 场景17挖掘机 mesh 替换实现方案

记录日期：2026-10-12。用户已授权保存完整方案并在远端实施。

## 1. 核心目标及用户明确的例外

以 `/root/gpufree-data/IsaacSim_Asset/combine_stage/combine_scene_17_terrain_fisheye.usda` 为基准，保留现有装配与控制结构，为五个挖掘机部件替换 mesh 几何，并生成独立的新场景。

铲斗直接采用完整带齿的 `bucket_only_full_teeth_mesh`，保留其全部几何，不要求与原来不带齿的 3DGS 铲斗内容一致。铲斗的安装原点、关节轴、角度零点和运动方式仍保持当前定义。

必须保持：整机世界位置、旋转和尺度基准；各部件坐标系原点、轴向、关节连接位置、角度零点与运动方向；全部雷达及相机的路径、参数、安装位置和姿态；场景17中用户摆放的物体、背景、灯光和其他设置；脚本控制与 TF 发布依赖的节点结构。

## 3. 坐标与尺寸处理

保留 `/World/Excavator`、五个 `*_link` 和 `Joints` 的现有定义。每个部件下面设置固定几何校正变换，将来源 mesh 坐标映射到当前部件坐标系。

```text
/World/Excavator
  boom_link                  # 保留部件原点和控制
    Visuals
      MeshAlignment          # mesh 到当前部件坐标系的固定校正
        Mesh                 # 网格、材质和 UV
```

世界中的 mesh = 当前部件世界变换 × mesh 到该部件坐标系的校正变换（列向量说明；USD Gf 行向量矩阵需对应转置）。

保留整机位置、旋转和缩放关系，不将部件原点重置为几何中心。优先依据历史变换记录恢复坐标映射，并以已有几何数据交叉核对；避免重复应用原始装配中的2.4倍缩放，不通过独立拉伸部件强行匹配包围盒。带齿铲斗以关节安装位置为对齐基准，新增铲齿导致边界改变是预期差异。

## 4. 资产组装

沿用当前挖掘机的关节、刚体、Articulation 和控制定义，只复用旧 mesh 文件的几何、材质、UV和贴图。引用独立部件时须保留有效的材质绑定与资产路径；不引入来源文件的相机、灯光或旧关节。

新场景明确替换旧几何引用，确保原3DGS部件不再参与渲染或雷达求交。全部传感器路径及挂载关系保持不变。不因视觉几何替换自动增加碰撞体或重新计算质量与惯量。

## 5. 执行顺序

1. 固定基准：记录场景17及直接依赖文件的版本、哈希，提取部件、关节、传感器配置，并保存可恢复基准。
2. 确定映射：核对五个 mesh 的单位、坐标、缩放和历史对齐依据，得到校正矩阵。无法由数据证明的部分明确记录，不能用猜测替代。
3. 组装资产：保留装配结构，接入 mesh、材质和依赖，保存来源及变换清单。
4. 派生场景：从场景17创建新文件，替换挖掘机几何，保留其余内容。
5. 静态检查：比较根节点、部件原点、关节、传感器和非挖掘机场景内容，输出数值一致性报告。
6. 运动检查：覆盖初始姿态、整机平移与旋转、各关节正负角度，验证无错误绕转、脱节或传感器漂移。数学变换验证与实际引擎运动测试分别报告。
7. 采集检查：使用已有采集链路进行少量图像、点云和TF验证；使用独立验证进程，不打断用户已有 GUI。若现有会话或资源不允许引擎验证，明确报告已完成项及未执行项。

## 6. 验收标准

- 必须一致：整机及部件坐标系、关节定义、传感器安装位姿、其余场景内容。
- 需要对齐验证：五部件尺寸、方向、安装位置和连接处；优先核对变换依据及几何特征，不只比外包围盒。
- 允许变化：完整铲齿，以及 mesh 与3DGS表示差异带来的表面细节、成像和雷达回波变化。
- 数据记录：保存每个来源文件、源 prim、目标 prim、校正矩阵、单位、原点和验证误差。浮点误差须量化。
- 本轮以资产替换和一致性为主；性能可顺带测量，但不承诺 mesh 一定更快。

## 7. 工具与操作边界

优先使用实例已有 Isaac USD Python API（Sdf、Usd、UsdGeom、Gf、UsdShade）及现有项目采集工具，不下载或升级外部依赖。所有远端操作使用已登记身份和审计工具，源代码、文档和验证报告保存在本地项目与远端对应项目目录。无需修改系统、驱动、桌面、SSH或运行环境。

回退方式：打开原场景17和原3DGS资产即可恢复原有资产方案；原文件不被替换。实施结果另存报告，不把计划中的检查写成已经完成。
