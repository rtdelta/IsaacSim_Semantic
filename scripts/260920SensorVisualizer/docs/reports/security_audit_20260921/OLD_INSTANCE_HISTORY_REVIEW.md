## 为什么支持“中木马”

9 月 20 日保留证据形成了以下相互印证的链路：

1. `/etc/ld.so.preload` 指向 `/usr/lib/.libproc.so`，进程映射确认其被实际载入。
2. 该库导出并替换 read、readdir/readdir64、socket、recvmsg 等接口。静态分析与本地复现实验确认它根据隐藏配置删除读取到的特定行。
3. 同一 psutil 字节码原始读取为 91,544 字节，普通读取仅 91,465 字节；被删的 79 字节使字节码反序列化失败。本地重建结果逐字节一致。
4. 配置隐藏了 `.dpkg-triggers-2890`、`polkitdl`、`nvidian-smi` 对应进程；后两者原可执行路径已删除但进程仍在运行。
5. `/etc/cron.d/apt-compat` 与 `/etc/rc.local` 包含调用隐藏程序的条目，重启后相关进程仍存在。rc.local 是否实际由平台调用未单独验证。
6. 曾观察到隐藏进程连接 `95.179.165.83:443`、`172.67.215.27:2082`。这些是历史调查指标，不能据此确定攻击者身份、恶意软件家族或外传内容。

这超出了普通 Python 包冲突或桌面组件损坏。资料外传与凭据被盗仍属未确定事项，未取得可证明具体文件被传出的证据。

## 需要承认的安全不足

1. 多数工作以 root 执行，第三方包或自编脚本一旦出问题，影响范围大。pip --target 只改变落盘位置，没有降权。
2. 早期部分 SSH 连接接受首次见到的主机密钥，包括同项目其他任务的 AutoAddPolicy；这弱于预先核对可信指纹。
3. 用户提供的密码被用于一次性连接代码、本地环境变量及工具调用。原始会话/工具记录本身因此也是敏感载体；不能把“没有写入正式源码”说成“密码从未留痕”。本复盘不复制其值，也没有证据证明第三方拿到这些记录。
4. 早期迁移侧重传输完整性和可运行性，没有做全面可信性认证。保留代码/依赖与资产一起迁移有传播受污染文件的潜在风险，不能单凭哈希一致排除。
5. GDB 参数干预应明确归为诊断实验；虽然现有记录限定了进程和目录，但不能声称这种实验对运行稳定性零风险。

这些是流程风险与证据边界，不是已证明的入侵链。
