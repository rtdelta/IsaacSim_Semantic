**读取异常的证据链**

1. ELF 动态符号确认库导出并替换 `read`、`close`、`readdir`、`readdir64`、`socket`、`recvmsg`。
2. 静态反汇编显示 `read` 从真实系统调用取得内容后，按隐藏列表匹配“8 位地址编码加冒号”，再按换行边界移除命中内容。相关主体位于 ELF 地址 `0x1f20`，行过滤分支约为 `0x2218–0x2337`。这个分支没有把输入严格限定为网络状态文本，二进制字节码也可能命中。
3. 配置 `/dev/shm/.dbus_sess` 保存编码后的地址列表；静态代码中的解码方式能得到包括 `0100007F` 在内的六项。`0100007F` 是 `/proc/net/tcp` 格式下的 127.0.0.1。这里只在本地解码数据，未执行库代码。
4. psutil 源码的说明文字包含以下一行，共 79 字节（含缩进和换行）：

```text
        "0000000000000000FFFF00000100007F:9E49" -> ("::ffff:127.0.0.1", 40521)
```

5. 普通读取时，源码和对应字节码都恰好失去这一行。它是源码中的文档字符串内容；删除源码这一行不等于删除可执行语句，但从已经编译的字节码里移除同样字节会破坏其内部序列化结构。
6. 只使用已保存的原始字节和配置，在本地重建过滤结果。两份文件重建后的全部字节与旧实例普通读取结果完全一致，不只是大小相等。
