# Isaac Sim 原生逐帧采集与 MCAP 记录对照方案

日期：2026-10-11  
状态：方案存档，尚未执行本方案的测试。

## 1. 核心目标

建立一条独立、尽可能使用 Isaac Sim 官方接口的采集基线。在同一 USDA 场景、同一批传感器和相同渲染质量下，逐帧生成数据并记录为 MCAP，观察原生链路的速度、卡顿和 CPU/GPU 负载变化。

通过对照回答：重复 NVRTC 编译、CUDA 模块链接和加载、CPU/GPU 间歇高占用，在脱离项目自定义框架后是否仍然存在；项目框架额外引入了哪些成本。

原生链路作为独立对照保留，不预设它一定更快。

## 2. 测试边界

- 使用与现有基线相同的 USDA 及资产引用，运行前记录实际文件路径和版本。
- 保持传感器数量、安装位姿、扫描配置、相机分辨率、渲染模式和画质设置一致。
- 使用官方原生更新、传感器生成和发布接口。
- 不经过项目自定义的采集票据、复杂状态机、逐组启停、共享内存传输和自定义录制框架。
- 仅保留必要的场景加载、接口配置、启动和结束控制。
- 独立保存测试脚本、输出和日志，保留现有项目代码及旧场景。
- 优先使用已有工具；不从外部下载、安装或更新依赖。确有缺失时单独列出并请求同意。

## 3. 核心数据链路

```text
同一 USDA 场景及传感器
            ↓
Isaac Sim 原生逐帧更新与传感器渲染
            ↓
官方 ROS 2 Bridge 发布点云、图像、参数、TF、Clock
            ↓
标准 rosbag2 + MCAP 存储插件
            ↓
MCAP 数据包及录制元数据
```

MCAP 保存交给 ROS 2 的标准录制工具。该方案包含 ROS 传输和录制开销，不能把整条链路视为完全发生在 Isaac 内部。

## 4. “同一个数据包”的定义

目标是数据内容和采集条件可比，不要求文件字节完全相同。

| 数据类别 | 对照要求 |
|---|---|
| 雷达点云 | 同一批雷达、扫描配置和坐标系；记录实际字段、消息频率及点数 |
| 鱼眼图像 | 同一批相机、安装位姿、分辨率和画质；明确图像编码方式 |
| 相机参数 | 尽量记录标定及投影相关参数，核对原生消息能表达的范围 |
| TF | 对照相同的参考坐标系和父子关系，核对方向及位姿 |
| 仿真时钟 | 记录真实仿真时间，核对消息时间戳的来源和语义 |

原生逐帧采集的时间推进、同步、采样频率及消息字段可能与现有项目不同。测试必须逐项报告差异；原生接口无法覆盖的自定义字段需列为缺项，不能默认为已等价。

逐帧采集也不自动意味着每个渲染帧都有每一种传感器的新数据。应核对实际原生传感器节拍，区分新采样与重复或旧数据。

## 5. 实施顺序

1. 核实同一场景和基线配置，形成最小对照清单。
2. 核实已有 ROS 2 Bridge、发布节点、rosbag2 和 MCAP 插件是否可用。
3. 建立最小原生发布配置；检查点云、图像、参数、TF 和 Clock 的消息内容及时间戳。
4. 使用原生逐帧运行和标准 rosbag2 记录 MCAP，不引入现有自定义调度框架。
5. 结束录制并确认文件正常关闭；在采集链路之外检查话题、消息数、时间跨度和数据内容。
6. 与现有基线对照，分别说明采集条件、原生执行成本和输出链路成本。

为区分瓶颈，条件允许时分开测量：原生渲染、原生渲染加 ROS 发布、原生渲染加 ROS 发布及 MCAP 录制。各阶段保持相同场景和传感器配置。

## 6. 日志与对照指标

- 启动、首帧、稳态采集及结束阶段的耗时。
- 仿真时间跨度、真实时间跨度、有效消息频率、消息数量及点数。
- 主线程及进程 CPU、GPU 利用率、内存和显存变化。
- NVRTC 编译、CUDA 链接及模块加载/卸载是否在稳态反复出现。
- 原生渲染、ROS 发布和 MCAP 录制各自引入的开销。
- 错误、警告、录制丢失迹象和时间戳或位姿异常。

优先沿用已有系统采样与分析工具。原生追踪会引入额外开销，普通性能测量与追踪测量分开报告。采集后的检查不参与逐帧执行。

对比时同时报告画质、运动条件、仿真倍率和采样频率差异，不能以少采数据或减少渲染工作量制造表面上的速度提升。

## 7. 预期产出

- 一套独立的最小原生采集配置与启动说明。
- 原生链路生成的 MCAP 包及话题、消息和时间统计。
- 与项目基线的配置差异表及性能对照报告。
- 有证据支持的成本归因，以及尚不能确定的问题。
