**我理解你后续的目标是：建立一套完整对照目录，把各链路按统一条件依次复跑，直接打开图片比较画质，同时查看耗时和资源表现。**图像以独立PNG文件保存，无需解包MCAP才能查看。PNG本身仍是二进制文件，但属于可直接打开的图片格式。

这个目标可行，建议这样组织：

1. **先固定公共输入。**同一USD、四路相机、分辨率、灯光、曝光、姿态序列和传感器参数；每项实验记录自己改变的参数。
2. **逐个独立进程运行。**先完成并退出当前链路，再启动下一条，避免GPU竞争和上一轮渲染历史影响。
3. **统一从采集后的MCAP导出无损PNG。**这样看到的图片就是实际交付数据；导出放在性能测量结束后，避免PNG编码干扰采集速度。额外原生Writer图片可单独作为诊断证据。
4. **保存相同结构的结果。**例如：

```text
comparison/
  01_v06_gated/
    images/front/、back/、left/、right/
    config.json
    frames.csv       # 图像编号、时间戳、姿态、有效性
    timing.csv
    validation.json
    logs/
    bag/
  02_v06_keepalive/
  …
  comparison.csv
```

5. **同时比较画质与成本。**记录渲染耗时、整组耗时、整轮耗时；图片按相同姿态并排查看。不同子帧/SPP预算分别列出，不混成一个“原生速度”。

目前已有不少独立PNG和跨链路样图，主要欠缺统一目录与完整复跑。⑧需要先解决对齐失败；否则只能产出诊断图片，不能作为合格数据参加比较。本轮只核对和分析，没有启动复跑或修改代码。
