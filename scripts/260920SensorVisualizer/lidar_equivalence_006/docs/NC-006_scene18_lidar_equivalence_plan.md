# NC-006：Scene18 自制与原生链路点云一致性测试方案

日期：2026-10-13。下面完整保存用户确认的上一轮方案。

**一、核心目标**

需要依次回答三个问题：

1. **差异是否仍然存在？**在 scene18 中，自制链路与原生冻结链路是否仍出现 NZ3 近距离点数量明显不同。
2. **差异首次出现在哪里？**是在 RTX 射线命中结果、点云提取、CPU 数据复制，还是 ROS 消息与 MCAP 保存阶段。
3. **差异对应什么实际几何？**多出或缺失的点落在车体、雷达外壳、地面还是其他物体上，进而判断哪种结果符合场景。

最终应得到“**具体环节＋触发条件＋可重复证据**”，不能只停留在点数不同。

**二、固定测试条件**

| 项目 | 本轮约定 |
|---|---|
| 场景 | scene18，保留原文件 |
| 挖掘机姿态 | 使用场景加载后的基准姿态，记录整机矩阵与实际关节角；不擅自把所有关节设为绝对 0° |
| 运动 | 整机、关节和传感器安装位姿全程不动，速度清零 |
| 渲染 | 双方统一 RT2，16 个预热子帧＋2 个正式子帧 |
| 传感器 | 保留相同的 13 路雷达及四路相机，避免先改变工作负载 |
| 雷达参数 | 对照最终生效的参数，包括距离、射线方向与原点、输出坐标系、噪声和遮挡排除设置 |
| 输出选择 | 按正式采集结果匹配，不能继续简单选择“同时间戳的第一条消息” |

每组可以在组间推进统一的仿真步数；**正式渲染期间冻结时间与姿态**。双方初始化与步进历史也要记录并尽量一致。

**三、测试按三个阶段推进**

**第一阶段：复现差异，同时测量各自的重复性。**

比较自制 single06 常驻链路与原生默认 Helper 冻结链路。先各采集少量静止组，并独立重启重复三轮。

优先分析：

- `MyNZ3_left`：历史差异最大。
- `MyNZ3_right`：第二个明显差异样本。
- `MyNZ3_front`、`MyAiry_left`：作为差异较小的对照。

同时比较“自制与自制”“原生与原生”。这样才能区分跨链路差异与链路自身波动，避免把随机变化当成实现错误。

**第二阶段：沿数据链路找到第一个分歧点。**

按下面的顺序留下点数、哈希、时间与源结果标识：

```text
RTX 原始传感器结果
    ↓
点云提取结果
    ↓
CPU 独立副本
    ↓
ROS PointCloud2
    ↓
MCAP 解码结果
```

关键实验是：**让两种提取方式观察同一个传感器、同一次原始输出**，而不是分别渲染后直接比较。

如果当前 SDK 无法直接暴露原始结果或扫描编号，就明确标注证据缺口，不能用时间戳代替证明。诊断接口也先验证不会改变原有输出。

判断方式：

- 原始命中已经不同：查场景同步、射线状态和参数。
- 原始结果相同，提取后不同：查提取配置、执行顺序与缓冲区。
- 提取相同，保存后不同：查复制、消息布局及录包选择。

**第三阶段：把差异点映射回 mesh。**

将两边点云转换到同一个世界坐标系，重点查看两米以内的差异：

- 哪些表面只被一条链路采到；
- 是否出现穿过外壳、落在物体内部的点；
- 是射线方向不同，还是同方向上的返回距离不同。

优先按射线／发射器标识配对；无法取得时，再用空间邻近比较辅助定位。**不直接按数组行号比较，也不把“点更多”当成更正确。**

**四、本轮完成标准**

本轮首先完成“是否复现、差异在哪一层”的定位。只有在同次原始输出、确定性条件满足时，才要求严格字节一致；跨次扫描存在噪声时，应依据重复性基线判断差异。

若 scene18 不再出现明显差异，也只能说明问题在这一全 mesh 工况下未复现，**不能直接据此认定旧问题就是 3DGS 导致的**。后续再通过单变量对照追查。
