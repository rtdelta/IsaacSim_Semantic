# NC-002 实验决策与解释边界

本文件记录执行时发现的限制；编号实现方案的原文不覆盖、不删改。

1. 旧 `native_capture_baseline`、`v06`、`single06_lab` 的源码在执行前备份。每次部署验证旧源码哈希，新实验仅写入 `native_capture_quality_002` 与其输出目录；USD 改动仅在匿名 Session 层。
2. 默认 ROS Helper 的连续运行，与 `delta_time=0` 的 Replicator 显式采集不是直接等价的。多次失败测试显示：渲染观察接口返回新图像，标准 MCAP 的传感器消息却仍停留在初始化阶段。失败包全部保留，不计入有效吞吐。
3. 冻结诊断版本保留 NVIDIA 原生渲染、提取、RGB 转换、ROS 发布节点，以及 `ros2 bag record`。在本实验 Session 图中，把 21 条依赖仿真步进的门控连接改接到其原生上游完成信号，13 路点云发布接到原生提取器完成信号。既不替换点数组、指针或消息时间戳，也不增加 Python 传感器 Writer、自定义 MCAP 编码或旧项目运行时。
4. 改接版本应称“原生节点冻结适配诊断”，不能称为“未经修改的默认 Helper 链路”。矩阵中的 `control` 不改任何门控，后续已经通过四路图像、13路点云及全部位姿/时间戳检查。**门控改接不必需，最终默认配置恢复 `bypass_native_simulation_gate=false`。** 前面的子帧/SPP扫描使用了诊断改接，要单独标明，不能伪称全部来自默认 Helper。
5. 资源常驻、显式采集拥有者和 CPU 观察接口的组合，已在三组静止/关节跳变/传感器旋转测试中通过新消息检查。这个组合结果不单独证明每项改动都必不可少。
6. 冻结时使用原生时间轴 `set_auto_update(False)`，而非不断触发暂停/停止的资源生命周期。组间恢复自动推进 6 个物理步；正式渲染调用 `step_async(delta_time=0, pause_timeline=False)`，采集期间检查仿真时钟与 USD 位姿不变。
7. 检查包括：21 个传感器/标定话题在当前原生时间戳有消息；4 路 RGB 字节一致；13 路 XYZ 字节一致；相机与 LiDAR 的渲染位姿匹配；关节数值、18 条 TF 的数值与父子关系匹配；不同组时间戳不同。源帧编号仍未由适配器暴露，不能伪造为额外证据。
8. `PathTracing` 的 `totalSpp` 是请求的累积上限，`spp=32` 是每次渲染迭代的请求值。两个 SDK 调用可能复用或重置累积，不能把调用数简单乘以上限并声称这是实际执行的射线数。报告记录两次调用成本及 SDK 名义迭代数。
9. `ready_scope_s` 是组间物理推进及两次 SDK 渲染调用返回的时间；它不是每组 MCAP 落盘确认。读取、哈希与 PNG 样例编码用于诊断，单独计时，排除于该作用域，但计入整轮实验墙钟。正式轮次对照关掉额外PNG导出，并另记 `payload_observed_scope_s`。Native ROS 为无损 Image，旧链路为 PNG CompressedImage，重复消息数也不同，整轮存储成本不直接等价。
10. Nsight 测试包含额外观测开销，不参与普通速度排名；NVTX 区分预热、正式渲染和观察导出。GPU 活动时间、API 包含等待的墙钟、NVML 利用率、SM 指标不能互相代替。
11. RT 16 子帧和 PT 1024 SPP 都只是渲染参考，不是真实世界画质真值。实验不自动修改正式项目质量参数。
12. 两轮名称包含 `trace` 的早期测试实际未启动 Nsight：启动器中缺省命令行布尔值覆盖了配置的 `trace=true`。这些轮次只保留普通采集证据，不作为底层追踪。已修正参数优先级，并要求 SQLite 同时包含有效 NVTX 窗口和 GPU_METRICS 才标记 `profile_capture_verified=true`。20261012_032227 的默认 Helper 轮次满足该检查。
13. Nsight 的 Vulkan 工作区间可能跨过等待、队列空闲和观察导出；区间并集不能当作有效执行单元忙碌时间。例如RT导出阶段区间仍覆盖整个阶段，但SMs Active仅约2%。报告同时给出设备计数器，不将区间长度换算为SM利用率。
14. PT 64 SPP的后两轮图像亮度与参考存在明显差异；第一轮差异较小。旧扫描未逐组记录所有曝光/内部累积状态，无法把差异全部归因于采样噪声。后续默认参考记录了相机曝光及全局后处理设置，但不能用后续设置反证早期扫描每组状态。
15. 三轮静止姿态对照中，原生与旧链路的位姿、鱼眼标定通过数值对齐。它们没有做到逐像素相同输出、完全相同初始化/累积重置，也没有做到相同消息数量和存储负载，因此只比较标注清楚的阶段作用域，不宣称纯调度加速倍数。

未下载、安装或更新外部工具；只使用现有 Isaac、ROS、NumPy、Pillow、MCAP、Nsight 和项目已有 SSH 工具。
