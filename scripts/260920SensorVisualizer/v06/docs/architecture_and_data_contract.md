# v06 架构与数据契约

## 进程与控制路径

```text
浏览器 HTML/CSS/JS
    → loopback HTTP / Python 标准库网页服务
    → Unix Socket / 有界控制队列
    → Isaac 交互进程主线程
        输入 → 规定运动积分 → Articulation/PhysX → USD/参考帧 → 状态与轨迹
    → 网页状态与命令回执

网页采集管理器
    → 独立正式采集 Isaac 进程
        源快照 → 原生时间推进 → 应用姿态 → 冻结 → RTX 渲染 → 完成回执
        → 来源时间和渲染矩阵校验 → 独立 CPU 数据
    → mmap 槽位 / 代数编号
    → 独立记录进程 / 后台编码线程
        PNG → ROS 2 消息 → CDR → MCAP；可选发布至 RViz
```

交互进程不创建正式传感器 RenderProduct，保留既定预览画质。USD/Kit/PhysX 对象仍由 Isaac 主线程操作，网页和编码线程不能直接调用它们。

## 坐标系与工程回转角约定

当前业务默认 cab 相对 track 的回转角为 0°，角度来源是工程假设。业务参考系 `swing_coordinate` 等效于 track 参考系，`swing_horizontal_coordinate` 等效于其水平参考系；名称沿用既有 TF 和 MCAP 接口。该等效关系不改变实际 cab 与 track 刚体原点的安装偏移。

水平参考系与整机参考系同原点，Z 与世界 Z 同向，X 由整机参考 X 轴的水平投影确定，Y 按右手系确定。WASD 的前后左右沿当前水平轴，随整机航向更新；它们既不是世界固定 X/Y，也不是启动后冻结的方向。水平系保留原点高度，不进行接地投影。

v06 的运动代码保持启动时的 swing 原生角度；这本身不保证该角度对应工程零位。后续 single0602 将增加资产零位映射和运行读回核验，具体定义见 [single0602 坐标系契约](../single0602Headless/docs/CoordinateFrames.md)。其新键位与模式切换规则属于新版本方案，不代表本 v06 已改变运行行为。

## 新的主线程优化

`robot/motion_update.py` 使用精确脏状态比较：根姿态、关节角与原生时钟均未改变，才允许跳过原生姿态写入。原生时钟改变强制刷新；复位使缓存失效。根姿态和关节独立更新，不用近似误差阈值吞掉小运动。

`robot/articulation_motion.py` 预先计算固定安装关系的逆矩阵、复用零速度数组，参考帧矩阵不变时不重复写 USD。一条网页复合运动消息的多次原生写入合并到末尾；控制状态仍按原有顺序处理。正式采集不启用姿态缓存，保留每组应用姿态和验证的流程。

`control_ipc.py` 发布不可再修改的状态代。通用 publish 仍做独立复制，但在锁外构造；查询线程只拿状态引用，JSON 序列化在锁外完成。轻量交互路径通过 publish_owned 转移对象所有权；运行状态、安装和元数据代在发布后不修改，统计列表显式复制。它不是跨进程共享 Python 对象，也不是 GPU 零拷贝。

键盘消息不再单独构造完整状态；网页约 10 Hz 状态发布保留，命令回执仍及时更新。实时采集的 snapshot 请求只返回完成采集所需的快照、会话与心跳，不重复携带 512 条回执和整套元数据。

主线程单次更新最多处理 16 条消息，并设置 2 ms 协作预算。预算在两条命令之间检查，不能抢占已经进入的 PhysX/RTX 原生调用，因此不是 2 ms 硬实时保证。命令顺序、失败回执、有界队列继续保留。

## 采集与调度

三种模式的数据语义保持：offline 重放完整时间网格；live_latest 允许跳过旧网格并记录跳过数量；live_complete 根据完整轨迹排队，不能静默丢组。

RenderProduct、完成 ticket 和 mmap 槽位仍按既有所有权规则管理。正式组固定姿态及原生时间，等待所有传感器回调，逐路检查源时钟和渲染矩阵。编码和写盘只接收独立 CPU 数组，晚回调不能转交给下一组。槽位只有记录进程确认对应组和代数编号后才能复用。失败和停止在安全边界排空。

新增可配置组边界让步：只在完整组已交给记录管线后执行，最多 100 ms；可要求交互进程心跳新鲜。默认 0，不强行牺牲吞吐。它是任务级协作，不能打断当前 Vulkan/RTX 提交，也不能保证消除所有长帧。CPU nice 可设 0..10，默认 0；其作用范围是 Linux CPU 调度，不是 GPU 优先级。

`os.nice` 在 Linux 实际作用于调用线程，随后创建的记录子进程/线程可继承；已经创建的其他 Kit 原生工作线程不保证一起改变。没有对所有引擎线程实施系统级实时调度。

采集管理器保留跨网页重启的进程锁和任务登记；设备参数在启动前核验，并记录请求的 UUID。单卡两个 Isaac 进程共享 GPU；双卡可显式分配交互卡和采集卡。必须用原生追踪及设备进程记录核实真实执行位置，不能把编号设置成功视作已完成双卡隔离。

完成数据写盘、任务 PID/argv 的运行判定、继承采集锁的释放是三个独立状态。恢复任务在前两者看起来完成而锁仍忙时显示 `releasing_resources` / `cleanup_pending`。此时网页复位/退出受保护，下一任务在读取源或启动轨迹前拒绝；不会忽略锁或强制抢占。确认资源已释放后才允许下一轮。

## 日志与时钟

交互控制事件保存在 output/runtime/control_events.jsonl。可选交互诊断复用 RunDiagnostics 和 ResourceSampler，增加同步主线程阶段的墙钟和线程 CPU 时间、采样明细与慢帧完整阶段列表。每个阶段计数与近期样本有界，不记录图像、完整环境变量或认证信息。

同实例 monotonic_ns 用于性能关联；仿真秒/纳秒用于数据采样；UTC 仅用于人类查阅。嵌套 span 是包含时间，跨 await 的同线程 CPU 时间可能包括其他回调，不应相加。nvidia-smi 是整卡低频采样，不能解释为某个函数的精确 GPU 利用率。

关键新增模块：hot_path_metrics.py、internal_scheduling.py、robot/motion_update.py。诊断、追踪、编码、ROS、mmap 模块复用逻辑，但运行包只引用 sensor_visualizer_v06；对照工具才动态加载 v05 基线。
