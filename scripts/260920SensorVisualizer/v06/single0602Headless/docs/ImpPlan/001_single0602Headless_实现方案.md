# single0602Headless 实现方案

更新日期：2026-10-15（北京时间）。版本：001。阶段：已实现并完成短程验收，模块对照见 [实现状态](../ImplementationStatus.md)，实测结果见 [验证记录](../Testing.md)。本文保留原设计及验收要求。

后续修订：用户已确认以 1× 为交互目标、取消 `<=0.1` 限制、继续逐帧位置设置及物理速度清零、原生 Stop 结束当前文件。[002 连续交互改进方案](002_连续交互改进方案.md) 已实施，本文关于规定运动时钟、网页独立 Play/Pause 及 Stop 的旧规则被其取代。连续交互的实际验证及性能以当前 [验证记录](../Testing.md) 为准；以下内容保留为 001 历史设计。

single0602 保留网页设置和 Isaac GUI 交互，先记录完整轨迹，再使用独立 Headless Isaac 进程沿轨迹离线采集。正式采集复用 v06 自制 keepalive 链路。坐标系遵循 [坐标系与键盘运动契约](../CoordinateFrames.md)：cab–track 回转角按工程假设保持 0°，WASD 沿当前 `swing_horizontal_coordinate` 移动。

## 核心目标

1. 网页继续提供整机参数、关节 Direct/Target/Periodic、传感器安装位姿、轨迹录制与导入导出、采集参数和任务状态。
2. 网页启用键盘模式后，Isaac 三维视口可控制整机平移、姿态和三个工作装置关节。
3. 同一次轨迹录制中，网页可反复关闭、开启键盘模式。切换保持当前姿态、会话、轨迹文件和轨迹时间连续。
4. 轨迹关闭并排空后，Headless 进程独立完成 keepalive 离线重放、正式采集和后台保存；交互窗口可在此之前退出。
5. 检查每组传感器输出的时间、位姿、状态和保存结果，分别报告完整性、画质、交互延迟与实际采集速度。

Headless 描述正式离线采集阶段；录轨迹阶段保留 GUI。single0601 的连续采集、物理 PRE/POST 采样及单 Kit 正式采集调度不作为本版采集主路线。

## 坐标系决策

业务名称继续为 `world → swing_horizontal_coordinate → swing_coordinate → sensors`。`swing_coordinate` 等效于 track 业务参考系，水平系等效于 track 的水平参考系，不新增同义 TF 节点。

WASD 使用每步当前水平系：整机转向后，前后左右随新航向变化；俯仰、横滚不会让 WASD 沿斜坡法向升降。Z/X 始终沿世界 Z。Q/E 改变整机航向，不操作 cab–track 回转关节。

本决策取代前一轮讨论中的“世界固定 X/Y 或启动时冻结水平轴待选”状态。v06 已有的航向换算可保留，首版重点核验其与 `HorizontalFrame` 一致，而不是改成世界固定轴。

## cab 与 track 回转角

首版不提供独立 cab 回转按键。初始化时定位 swing 角色 DOF，读取资产零位映射，确认工程 `q_cab_track=0` 对应的原生角度，并在本项目临时运行状态中保持该角度。读回核验应覆盖初始化、整机运动、模式切换和离线每组状态。

适用资产的原生零位映射若未声明，启动应给出明确原因，不能把任意启动角当作零位。对已声明的零位，可在载入阶段设置并在正式录制前完成同步；轨迹和采集 metadata 同时保存 `assumed_zero`、零位映射与原生读回值。

当前 v06 `_command_angles` 保留启动 swing 角度。因此，移植时必须处理“保持启动角”与“保持已声明工程零角”的差别，不能只增加网页说明。

## 键盘与统一运动更新

键位按 [坐标契约](../CoordinateFrames.md) 实现：W/S 前后，A/D 左右，Z/X 升降，Q/E 航向，R/F 横滚，T/G 俯仰，U/J 大臂，I/K 小臂，O/L 铲斗。前后对向键抵消，水平斜移归一化，关节及倾斜遵守限位。

原生和保留的网页键盘入口共用一份映射、速度和模式状态。按键事件只更新按下集合，按住运动不依赖系统 KEY_REPEAT 频率。输入前端之间发生焦点切换时先清空旧来源，再允许新来源接管，不合并残留按键驱动同一自由度。

交互阶段沿用 v06 的规定运动时钟和有界步长，不将其改写为 single0601 连续采集的物理时钟。主线程每次更新按以下顺序执行：

```text
检查生命周期与焦点
→ 处理有界控制队列及模式命令
→ 从本步开始状态计算 H
→ 积分整机和关节一次
→ 写入 Articulation 并同步参考系
→ 实际读回根姿态及关节状态
→ 提交轨迹与网页状态
```

网页 Play/Pause 仍控制规定运动；原生 Timeline 与离线采集时钟各自按既有职责工作。状态界面明确显示控制时间，不把墙钟或交互预览原生时间当作正式传感器采样时间。

## 网页与键盘模式切换

键盘模式默认关闭，网页参数可持续编辑。只有执行 Apply、Execute 等明确命令才改变运动；编辑草稿不清键或改变姿态。

| 操作 | 控制器行为 | 轨迹行为 |
| --- | --- | --- |
| 开启键盘模式 | 清空各来源按键，停止此前自动运动，按实际读回状态建立控制基准 | 保留同一录制与时间，记录模式事件 |
| 关闭键盘模式 | 清键并保持当前整机和关节姿态，等待网页显式运动命令 | 继续记录；Play 状态下静止区间仍计时 |
| 再次开启 | 从最新姿态接续，旧按键不自动恢复 | 不复位、不另开轨迹 |
| 键盘开启时执行网页运动命令 | 清键，提升控制代号，应用网页命令；再次键控需新的按下事件 | 同一轨迹保存应用后状态；直接跳变标记为 direct |
| 修改键盘速度 | 校验后原子应用配置并清键，等待新的按下事件 | 记录配置事件 |
| 失焦、文本输入阻塞、Pause 或 Hold | 清键；Pause 停止控制时钟，Hold 保持姿态 | 不隐式关闭轨迹 |
| 显式结束轨迹 | 清键并保持姿态，排空写入后返回完成回执 | 完成当前文件并标记完整 |

每次模式或控制来源交接递增 `input_epoch`。输入消息携带 epoch 和来源序号，控制器拒绝旧代输入，关闭模式时到达的运动按键不能留待重启后生效。重新获得焦点后必须有新的 KEY_PRESS，单独 KEY_REPEAT 不恢复被清除的按键。

开关及速度先完整校验再提交。网页以 Isaac 已应用回执显示最终开关状态，不能只显示浏览器乐观状态。旧 F8 直接修改本地开关的路径需归一到同一模式处理入口；若保留快捷键，必须经过同一清键、epoch 和网页状态回执规则。

网页与 Isaac 的连接状态、视口是否获得焦点、键盘模式是否启用分别显示。浏览器断开只清理该浏览器输入来源；Isaac 原生按键仍按视口焦点和引擎模式决定是否生效。网页刷新后先读取引擎状态，不重置正在录制的会话。

## 轨迹记录与兼容

状态轨迹保存世界位置、四元数、三个工作装置实际关节角、安装 revision、时间、序号及直接跳变标记；swing 工程假设及原生零位、读回信息进入版本化元数据与核验记录。

按键、模式切换、配置变更和命令来源保存为控制事件，不作为离线运动重建的输入。离线直接使用完整状态，连续区间采用位置与关节插值、四元数 SLERP；direct 或安装 revision 边界按既有规则处理。

轨迹使用有界后台写入，过载显式失败，不静默丢状态。结束录制必须等待排空完成，`recording_complete=true` 后才允许正式离线采集。Play 时关闭键盘只造成保持姿态的时间段；Pause 时控制时间暂停，事件日志另保留单调时间用于解释操作顺序。

导入旧轨迹时核验坐标契约、资产来源、原点、关节映射和完整标记。已知可等价的旧轨迹显式迁移并保留来源；不通过禁用资产哈希或伪造契约版本解决不匹配。

## Headless 正式采集

默认使用现有 scene18 目标场景，具体路径、文件及依赖哈希在启动主机核验。加载轨迹后生成任务快照，后续交互修改不影响正在采集的轨迹和任务配置。

```json
{
  "mode": "offline",
  "capture": {
    "backend": "persistent_gated",
    "resource_policy": "keepalive"
  },
  "replay": {
    "mode": "offline"
  }
}
```

以上是固定链路的配置片段，完整任务还需指定已完成轨迹、场景、输出、传感器和渲染配置。移植时同步修改默认配置和网页生成任务的策略文件，因为旧 v06 默认 `resource_policy` 仍为 `gated`。

正式组依次执行：

```text
预留记录槽位
→ 按目标轨迹时间推进原生时钟
→ 应用完整姿态及安装状态
→ 固定姿态和原生时间
→ 必要预热
→ 正式渲染并等待全部传感器完成回执
→ 校验源时间、渲染位姿和组归属
→ 交付独立 CPU 数据
→ 后台 PNG、ROS2 CDR、MCAP 保存
```

keepalive 在健康采集组之间保留资源和更新；中间渲染丢弃，不当作正式样本。保留 v06 现有冻结、重试、必要预热和源缓冲所有权规则。首版不删减既有 16 个相机预热子帧与 2 个正式子帧的基线设置，不从 Headless 或 keepalive 推导实时采样性能。

Headless 进程不订阅原生键盘、不依赖交互 socket 提供状态，仅从已关闭轨迹取源。独立离线任务默认 `cooperative_yield_ms=0`，关闭组间对交互 owner 的心跳查询。网页可继续提供任务查询、暂停、恢复、停止与排空。任务完成、记录排空、进程退出和资源锁释放分别确认，资源未释放前不能启动下一任务。

## 实现顺序与验收

| 阶段 | 工作 | 验收重点 |
| --- | --- | --- |
| 1 | 建立独立运行包和默认任务策略 | 来源清单、独立配置与输出，明确 offline 与 keepalive |
| 2 | 接入坐标契约与 swing 零位 | 工程角假设、原生角读回、业务原点与固定安装偏移一致 |
| 3 | 更新键位和视口输入 | W/S、A/D 沿 H，Z/X 沿世界 Z，焦点及输入阻塞正确 |
| 4 | 完成模式交接和网页回执 | 至少 20 次交替开关；没有残留按键、瞬移或自动恢复运动 |
| 5 | 完成同一轨迹混合控制 | 网页与键盘交替，direct 边界、静止区间和时间连续 |
| 6 | Headless 离线采集与回读 | 关闭交互窗口后独立完成；计划组、时间、TF、关节和载荷对应 |
| 7 | 重复生命周期与交互测量 | Pause/Resume/Stop/Drain、刷新重连、输入至姿态延迟与最长停顿 |

坐标专项至少覆盖 heading 为 0°、90°、180°、-90°，带非零 pitch/roll 的 WASD，W+A 归一化、W+S 抵消，以及 W+Q 后运动方向逐步随航向改变。水平移动不增加世界 Z；Z/X 不引入水平位移；Q/E 不改变 cab–track 工程角。

模式专项覆盖按住键时关闭、关闭后残留 KEY_REPEAT、失焦后再聚焦、网页编辑输入框、旧 epoch 消息晚到和网页执行运动命令后重新键控。事件日志能解释每次清键原因及应用时刻。

本地纯逻辑检查与实际 Isaac 视口、Headless 和 MCAP 验证分别报告。具体位置和角度容差沿用对应资产与 v06 采集核验值，并在测试配置中记录；性能结论必须来自同条件实测。

## 设计时的实现差距

设计阶段确定的主要差距为新键位、启动回转零位核验、视口焦点要求、模式切换代号、统一网页回执、轨迹契约元数据以及新项目的 Headless keepalive 入口。这些项目现已实施，实际验证范围和仍未覆盖的长期测试以验证记录为准。

v06 的水平位移数学和水平参考系可直接作为基线；single0601 的输入队列与焦点检查可按接口移植。不能将它们已有的源码或历史测试报告当作 single0602 已实现、已验收的结果。
