# single0602Headless 连续交互改进方案

更新日期：2026-10-16（北京时间）。版本：002。状态：已实施，连续交互、Stop/重新绑定和新旧轨迹离线兼容已完成短程验证。实际倍率及测试边界见 [验证记录](../Testing.md)，模块对照见 [实现状态](../ImplementationStatus.md)。

本文替代 [001 实现方案](001_single0602Headless_实现方案.md) 中关于交互时钟、原生 Timeline、播放倍率、Stop 和录制生命周期的旧规则。坐标几何、键位、资产零位、完整状态轨迹及独立 Headless keepalive 采集继续遵循既有契约。

## 已确认的四项决策

| 决策 | 本次确定的规则 |
| --- | --- |
| 交互倍率 | 以 1× 为交互目标，取消此前 `<=0.1` 的配置校验和人为限速；不以离线采集吞吐限制 GUI 录轨迹速度 |
| 运动模型 | 延续逐帧离散位置设置；不加入碰撞、受力、接触响应、动力学控制或新的运动学求解器；物理线速度、角速度及关节速度保持零，不引入加速度状态或加速度积分 |
| 原生 Stop | 结束当前轨迹并排空文件；重新录制创建新文件，不跨 Stop 续写 |
| 其他运动对象 | 本轮不新增其状态记录；在 TODO 中持续跟踪对离线场景复现的影响 |

1× 表示原生仿真时间以接近墙钟的正常速度推进的目标。实际实时率仍需在目标场景和单卡上测量；出现负载不足时报告实测值，不把目标值显示为已达到，也不恢复旧的 0.1× 限制。

## 核心改进目标

1. Isaac 原生 Timeline 连续播放。原生面板与网页 Play/Pause 操作同一仿真状态，消除“点击 Play 又被程序暂停”的行为。
2. 键控开关只决定控制输入。关闭键控、Hold、失焦或输入框编辑时，挖机保持当前姿态，原生 Timeline 和场景继续运行。
3. 每个原生仿真步只计算一次新位置和关节角。网页和键盘共享同一个姿态写入入口，按原生步长结算，不再用墙钟乘旧倍率推动另一套运动时间。
4. 保持逐帧位置指定语义。每帧先得到目标位姿，再直接设置根位姿和关节位置，并清零物理速度；不通过速度、力矩、驱动器或接触求解产生本项目挖机的运动。
5. Play、Pause、Stop、Hold、键控开关和录制状态各有明确含义；用户主动 Stop 属于正常操作，不再因物理绑定释放而被归类为控制器故障。
6. 完整状态轨迹与 Headless 离线采集继续可用。按实际应用并读回的位姿记录，Stop 后旧文件完成，下一次 Start Trajectory 建立新文件。

## 运动和时间规则

### 原生时间与 1× 目标

- GUI 交互只采用原生仿真步长计算位移增量。墙钟用于延迟和实际实时率统计，不作为第二个运动积分来源。
- 删除 `interactive_runtime` 中每次更新主动暂停原生 Timeline 的分支；网页 Play/Pause 转为原生 Timeline 命令，网页状态从已应用的原生状态更新。
- 取消 `contracts.py` 的 `max_real_time_factor <= 0.1` 上限，并检查默认配置、网页状态、文案和相关测试中的旧假设。交互默认目标为 1×，不再在控制更新中额外乘 0.1。
- 不以粗暴裁剪长墙钟间隔补偿卡顿；依据真实原生步长推进。原生多步推进时按步处理，不将渲染帧与仿真步混为一谈。
- 新轨迹时间为录制开始后的原生仿真时间差；Pause 期间不增长，恢复后延续同一录制。单调墙钟只进入事件日志和性能统计。
- 原生时间回退、场景切换或重新初始化不得写入原有时间段，应结束当前录制；正常 Stop 采用下文的完成流程，异常情况保留明确原因。

### 离散位置与零速度

控制器计算的是下一帧位置、姿态和关节角。已有 `m/s`、`deg/s` 配置继续作为“单位仿真时间的位置或角度增量”，例如 `delta_p = step_rate * dt`，不转为物理速度命令，也不增加新的速度或加速度轨迹字段。

原有 Target、Periodic 和按住键产生的运动，均只生成离散位置序列。继续使用现有四元数、关节角、几何层级和参考系同步，不引入新的正逆运动学规划或真实物理响应。

每步维护根线速度、根角速度和关节速度为零。加速度按当前简化模型为零，不增加加速度计算或驱动；若接口没有独立加速度状态，不伪造一个可写的后端字段。验收读取后端已有速度字段，不能仅检查控制器的目标数组。

这里的“零速度、零加速度”描述本项目采用的物理状态约定。相邻帧位置存在跳变，按位置差分计算出的数学速度可能非零；不把这种差分速度当作后端物理速度，也不宣称移动轨迹的数学导数为零。

延续对本项目挖机关闭重力、碰撞及继承驱动力的会话层覆盖。连续播放后，必须实测自由根和关节是否漂移、约束求解是否覆盖位置；若需要在步末重新设置同一已计算位置及清零速度，应复用该步目标，不再次计算位移。

### 单一更新入口与顺序

应用更新回调负责收命令、焦点检查、状态回执和后台文件排空；运动结算绑定到经过验证的原生仿真步阶段。具体回调 API 和读写阶段先通过最小原型确定，不假定任意 app update 都对应一个物理步。

```text
处理 Timeline 事件、输入 epoch 和有界命令队列
→ 在有效原生仿真步获取 dt，读取本步开始状态
→ 按本步开始姿态计算 H，计算一次整机及关节位置增量
→ 直接写入根位姿、关节位置，清零物理速度
→ 同步部件和参考系；在已验证的步末阶段消除非预期漂移
→ 实际读回位姿及已有速度状态
→ 用同一已确认仿真时间提交轨迹及网页回执
```

Direct 命令也进入同一写入入口，并保持 `direct` 跳变标记。暂停时允许已有 Direct 设置，但不推进轨迹时间；同一时间的边界和顺序沿用明确的序号、事件和跳变规则。

必须消除 `motion.tick()`、GUI app update、图回调等路径重复推进控制器的可能性。每个仿真步允许必要的状态同步，位置增量只能计算一次。

## 操作语义与状态

| 操作 | 仿真与运动行为 | 录制行为 |
| --- | --- | --- |
| 原生或网页 Play | 同一个 Timeline 进入播放；按实际状态回执，不回压暂停 | 已开启录制则随原生时间推进；不自动开始录制 |
| 原生或网页 Pause | Timeline 暂停；清键，不再推进离散位置 | 文件保持开启，轨迹时间暂停；恢复后继续同一文件 |
| 键控开启/关闭 | 清键、递增 epoch、从实际位姿接管或 Hold；Timeline 不变 | 保留同一录制，记录控制来源事件；播放期间静止区间继续计时 |
| Hold、失焦、文本输入阻塞 | 停止相关控制输入并保持挖机姿态；Timeline 不变 | 不隐式结束录制 |
| End Trajectory | 按既有规则保持挖机姿态；Timeline 继续按当前状态运行 | 结束并排空当前文件，完成后才允许用于正式采集 |
| 原生或网页 Stop | 清键、取消待执行运动命令、结束本轮绑定；不自动重新 Play | 当前文件结束并排空；下次录制创建新 ID 和新目录 |
| Stop 后重新 Play | 等待新物理绑定可用，从实际状态重新同步，保持 Hold | 不恢复旧文件；需要显式 Start Trajectory 才创建新录制 |

Pause 后按住的旧键不自动恢复，必须产生新按下事件；Pause 前显式启动的网页 Target/Periodic 按暂停/恢复语义继续。Stop 会取消这些命令，下一轮不自动恢复。

网页分别呈现：仿真 `playing / paused / stopped / initializing`、键控开关及焦点、轨迹 `idle / recording / draining / complete / failed`。例如“仿真仍播放、挖机 Hold、轨迹正在录制”是合法状态，不再使用单个 `playing` 布尔值解释所有状态。

## Stop、绑定释放与文件完成

原生 Stop 会使当前物理绑定失效。处理应订阅实际 Timeline 生命周期，并区分预期的 Stop、重新绑定中的不可用状态及意外失效，避免在 Stop 后继续读取已释放的 Articulation。

1. 每个正常仿真步缓存最后一份已验证快照及时间。
2. Stop 事件立即禁止新的运动输入和录制样本，递增 epoch，取消旧命令，进入 `stopped / draining`。
3. 使用最后一份有效快照结束文件，记录 Stop 原因和末样本序号；不在 Stop 后补读姿态，不把回零后的状态追加到旧轨迹。
4. 后台写队列排空、元数据和哈希完成后才标记 `recording_complete=true`。写入失败仍保留失败状态，不能因用户正常 Stop 而忽略保存错误。
5. 下一次 Play 等待新绑定就绪并核验 swing 零位、同步实际姿态、重置缓存和控制基准。旧文件排空完成前禁止新录制，给出明确状态回执；下一次 Start Trajectory 创建新文件。

停止事件只关闭一次录制；网页 Stop、原生 Stop 与重复事件都使用同一幂等处理路径。进程被强制终止时仍保留“不完整”的真实结果，不将未排空文件标为完整。

## 轨迹和 Headless 兼容

- 新轨迹继续保存世界位置、四元数、实际关节角、安装 revision、序号及 direct 标记；不添加速度、角速度或加速度估计。
- 新增版本化交互时间语义，例如 `native_simulation_seconds`，记录原生时间起点、控制步序号、1× 目标与实测实时率统计。旧 `prescribed_control_simulation_seconds` 轨迹保留原始含义，不重新乘 10 或伪装为新时间基准。
- 导入和离线重放需显式识别两类时间语义；原有资产、坐标、零位和完整性校验继续执行。已有完整轨迹的离线功能需回归验证。
- 原生仿真步之间的普通位置变化仍按原有连续区间插值；显式 Direct 和安装 revision 边界维持跳变规则。逐帧位置设置本身不意味着将所有样本改为 `direct`。
- 独立 Headless 继续采用不可变轨迹快照、冻结组状态、keepalive、既有预热与正式子帧、后台保存和独立 MCAP 回读。GUI 1× 目标不要求 Headless 采集达到实时。
- 本轮完整性承诺覆盖挖机、传感器安装和既有采样状态。其他动态对象不进入本轮轨迹；其离线复现差异纳入 TODO。

| 阶段 | 主要修改位置 | 完成条件 |

| 2：统一仿真与输入 | `interactive_runtime.py`、`contracts.py`、`config/`、网页及原生 UI | 移除强制暂停及 0.1× 限制；Play/Pause 对齐，开关键控和 Hold 不暂停场景，默认目标 1× |

| 4：兼容与验收 | 离线导入/重放、测试工具、文档及部署清单 | 新旧完整轨迹与 MCAP 回读通过；更新实现状态及实测报告后再声明完成 |

### 验收重点

- 原生 Play 不再产生 `native_play_suppressed`，仿真时间持续前进；网页状态与原生面板一致。
- 挖机保持静止时仍可观察原生时间推进；用可丢弃测试场景中的独立运动标记核验其他对象不会因键控开关或 Hold 被暂停，不扩展正式轨迹字段。
- 至少 20 次键控切换，以及失焦、输入框编辑、KEY_REPEAT、旧 epoch 晚到，均无旧输入恢复、重复位移或额外暂停。
- 复测 0°、90°、180°、-90° 航向和非零倾斜，保持 WASD 水平系、Z/X 世界竖直、swing 零位及关节限位规则。
- 全根位姿和各关节变化时读回物理速度为零；记录实际数值误差与容差，不用轨迹差分代替物理速度读回。加速度不新增字段或估算。
- Pause/Resume 保留同一文件和非递减时间；正常 Stop 不报 `owner_failed`，旧文件完成，下一次 Play 无旧键或旧目标恢复，重新录制得到不同文件。
- Stop 发生在按键运动、网页运动、静止录制和排空期间均可正确结束；模拟写入失败时不得错误标为完整。
- 报告 1× 目标下的实际仿真时间/墙钟比、按键至姿态延迟、最长更新间隔和录制队列负载，不继承旧 0.1× 条件下的性能结论。
- 独立 Headless 的新轨迹回放和至少一份旧完整轨迹回归通过；组时间、TF、关节、传感器位姿、数据载荷及 Stop/Drain 均经独立回读。

## 可行性和实施关注点

目标可行，主要工作是改造时钟、写入阶段和生命周期，而非增加物理模型。已有的根位姿、关节位置直接设置、速度清零、实际快照和后台轨迹写入可作为基础。

实施时仍需验证三点：连续播放下 PhysX 不覆盖本项目指定姿态；原生仿真步与渲染/回读顺序一致；Stop 释放绑定时可靠结束并排空录制。这些属于实现验证事项，四项产品决策已明确，目前无须再由用户选择。

## 实施落点

- 交互运动只在 `SimulationEvent.PHYSICS_POST_STEP` 入口计算并直接写入一次完整位姿，随后清零速度、同步部件和读回。app update 只处理命令、焦点、生命周期和状态发布；本轮未增加墙钟驱动的第二套位置积分。
- 使用已安装 `omni.kit.loop` 的默认活动循环接口退出手动固定步长模式，并在交互进程关闭 `isaacsim.core.throttling/enable_manualmode`，防止扩展在每次 Play 时重新启用固定步进。播放期间额外核验活动循环与 app/native 时间增量；相关运行设置在关闭时恢复，正式采集入口保留原有固定步进。
- GUI 默认使用可关闭的 `interactive.async_rendering`，保持渲染与位置记录职责独立；关闭时先恢复同步渲染，再释放物理和会话层。正式 Headless 的同步冻结、预热与保存链路继续保留。
- 原生 Stop 通过缓存状态结束录制；最终结束原因、末样本和统计在写线程排空后并入元数据，避免主线程与写线程同时改写文件元数据。写入失败保留不完整状态。
