## 2. 假设与可区分预测

| 假设 | 对应预测 | 仍需防止的过度解释 |
|---|---|---|
| H-A：MyAiry 参数或资产构造参与触发 | 同入口下官方资产与 MyAiry 出现不同结果 | 不同资产的点数、发射器时序或噪声不可直接逐点比较 |
| H-I：共同的 API 使用方式/图结构参与触发 | 同资产下官方运行路径与低层入口出现差异 | 官方封装可能同时改变产品、annotator 和生命周期 |
| H-R：有效射线或几何状态已经偏旧 | 不同坐标表示中的物理距离均符合历史姿态候选 | 仅凭输出距离不能确定具体历史槽位或射线计算函数 |
| H-O：输出坐标/参考姿态处理引入差异 | 距离符合当前姿态，但方向或世界位置偏离，且依赖输出方式 | 输出开关也可能改变上游路径，不能只按属性名称归因 |
| H-C：累积或跨帧处理参与触发 | 仅改变累积设置后异常稳定变化 | 变成部分扫描、丢失旧点或输出频率改变不算同条件修复 |
| H-M：运动变换/历史消费参与触发 | Motion BVH 干预、非匀速输入或运动对象互换改变偏差规律 | 关闭功能通过可能降低仿真能力，不能直接作为生产方案 |

假设允许并存。所有候选先写出可观察预测；预测相同的候选先归为等价组，不能根据相同拟合结果强行选出一个机制。

## 3. 固定基础条件与资格

### 3.1 运行环境

先在 006 的已核验构建上执行：Isaac Sim `6.0.1-rc.7+release.42383.32955d8d.gl`、Kit `110.1.2+production.326809.f9bf0dda.gl`、单 NVIDIA L40。实际执行时重新登记构建、扩展、GPU、驱动和源码哈希，不把历史环境记录当作当前检查结果。

以 006 的有效 E 配置为起点：60 Hz 物理/loop/渲染推进，10 Hz tick，scanRateBaseHz=10，Instant=true，NONCOMPENSATED，累积开启，Multi-Tick、per-sensor TLAS、Motion BVH 开启，历史容量 64，异步渲染关闭。每轮在固定暖机结束、Timeline 正在运行的相同时点读回有效配置。

除明确指定的实验变量外，保持初始化、固定暖机、产品附着时点、CPU 输出和保存策略相同。不能把暂停后的 loop 状态用于替代采样态快照。

### 3.2 场景与运动

沿用非对称六面房间，内表面为 `x=-7/+10 m`、`y=-11/+8 m`、`z=-4/+6 m`，Z 向上。主轮传感器位置为世界原点，仅绕世界 Z 轴旋转，无运动父节点。

| 条件 | 初始 yaw | 运动 | 用途 |
|---|---:|---|---|
| S0 | 0° | 静止 | 静态、坐标与距离模型资格 |
| S5 | 5° | 静止 | 检查旋转方向、输出参考系及静态模型 |
| R6P | 0° | +6°/s 持续旋转 | 主定位条件，每物理步 0.1°、每扫描 0.6° |
| R3P | 0° | +3°/s 持续旋转 | 检查前一步/半步切换，每步 0.05°、每扫描 0.3° |

先使用 R6P 定位，再用 R3P 检查是否保留相同触发规律。反转、混合平移及 120 Hz 只作为明确触发的后续扩展。

### 3.3 必须延续的资格

- 实际推进为每 update 一个物理步，dt 与 1/60 s 相差不超过 2 ns；源 tick 实测间隔为 6 个物理步。
- 命令表与实际世界姿态一致：位置误差 ≤10 μm、旋转误差 ≤1e-6 rad；输入角增量误差 ≤2e-6 rad。
- 同事件 source/ref 时间可唯一关联同一物理步，差值 ≤2 ns；不按回调时刻、最近目标或几何最接近姿态配对。
- 每种资产、输出表示及新增 API 路径分别通过静态模型、解析与所有权资格。
- 缺失、重复、无法关联和 unknown 保留在计划分母；动态几何失败不构成测量资格失败。

## 4. T1：官方资产与 API 的交叉复现

### 4.1 四个组合

| 组合 | 资产 | 运行入口 | 主要比较 |
|---|---|---|---|
| A0 | 原 MyAiry_front | 006 独立原生入口的锁定版本/独立扩展 | 本轮重新采集的基线 |
| A1 | 原 MyAiry_front | 官方 Lidar/LidarSensor 路径 | 与 A0 检查 API/运行路径差异 |
| A2 | 安装版自带的一个官方示例资产 | 独立原生入口 | 与 A0 检查资产族差异 |
| A3 | 与 A2 完全相同的官方示例资产 | 官方 Lidar/LidarSensor 路径 | 与 A2 检查 API；建立官方组合复现 |

官方文档推荐使用 LidarSensor 管理运行时采集，并提供 GenericModelOutput 读取与 parser 示例。实际签名、字段和附着行为以安装构建核验。[官方采集路径](https://docs.isaacsim.omniverse.nvidia.com/6.0.1/sensors/isaacsim_sensors_rtx_lidar.html#how-to-collect-data-from-an-rtx-lidar)

### 4.2 资产选择与覆盖规则

优先选择安装环境已经可读的 `Example_Rotary` 或等价官方示例；开跑前锁定唯一资产、配置/variant、源文件及依赖哈希。若资产不在本地，将该分支标记为缺少前提，不在本次文档任务中下载或安装资源。

统一显式覆盖 Instant=true、tick=10、scanRateBaseHz=10、rangeAccuracyM=0、SENSOR/CARTESIAN/NONCOMPENSATED 和累积开启，保存覆盖前后值与有效读回。该组称为“官方示例资产的 Instant 诊断配置”，不能称为“官方出厂默认”。

其余发射器、扫描模式、偏置、修正、fireTimeNs、模型变换及回波参数保留并全量记录。不得为了适配旧分析器，悄悄清零这些参数或手写替换官方发射器表。

如官方资产不满足旧的零偏置/单状态模型，必须先建立并静态验证完整的发射器与 tick 状态模型。房间不能覆盖其有效距离范围、剩余噪声过大或几何缺乏观测性时，记录资格不成立；不能以此声称该资产不复现异常。

### 4.3 API 路径与缓存输出

两条入口继续使用同一推进所有者和同一运动写入阶段。尽量匹配原生产品、GMO 通道、数据源时间和 annotator 集合，保存官方封装实际创建的产品及图结构。

`LidarSensor.get_data()` 的一次返回不天然等于一次新 tick。逐次保存原生 frame/reference 身份和读取时刻，用已验证的身份/时间判定是否为同一事件的重复读取；不能将轮询次数当作采样帧数，不能把当前物理时间补成原生源时间。

通过受支持方式在同一产品上取得时间证据。若官方运行路径无法提供等价的 source/ref 或输出拓扑，记录为“API 路径及拓扑组合对照”；仅对可证明的时间范围作结论，不关闭时间门槛使其通过。

A0 保留 006 四 annotator 的正常复现能力。若 A1/A3 的产品拓扑无法匹配，且它们与低层入口出现差异，增加一个原生入口的匹配拓扑桥接组，单独检验 annotator/附着差异；该桥接须先冻结再采，不能将初始差异直接归因于 API 封装代码。

### 4.4 T1 解释

同一资产内部按实际局部运动步和射线身份比较；跨资产只比较各自合格模型下的失败类别、有效偏差及候选规律，不能直接比较 XYZ 行或要求不同扫描模式的残差数值相同。

四组合均复现时，扩大了共用原生路径的证据范围；某个组合通过时，沿资产或 API/拓扑差异继续隔离。A3 未取得测量资格时，官方组合分支保持未完成，其他合格分支可独立推进。

## 5. T2：距离、方向与输出坐标的分层定位

### 5.1 输出表示对照

在 A0 的 MyAiry、原点纯旋转、已核验零发射器偏置和模型变换条件下开展：

| 组合 | 输出参考系 | 元素坐标表示 | 与基线的变量 |
|---|---|---|---|
| B0 | SENSOR | CARTESIAN | 等同本轮 A0，不重复创建相同条件 |
| B1 | WORLD | CARTESIAN | 仅改变 outputFrameOfReference |
| B2 | SENSOR | SPHERICAL | 仅改变 elementsCoordsType |
| B3 | WORLD | SPHERICAL | 可选交互组；两个主效应完成后预登记 |

三个完整属性名分别为 `omni:sensor:Core:outputFrameOfReference`、`omni:sensor:Core:elementsCoordsType`、`omni:sensor:Core:outputMotionCompensationState`。T2 保持 NONCOMPENSATED，不同时改变补偿状态。

原生文档列出了 SENSOR/WORLD 与 CARTESIAN/SPHERICAL，并说明这些输出属性不支持运行中修改。每个条件应在产品/模型初始化前设定，使用独立进程，读回有效 schema 和 GMO 头中的 reference/coordinates/compensation 枚举。[原生输出定义](https://docs.omniverse.nvidia.com/kit/docs/omni.sensors.nv.lidar/3.0.0/lidar_extension.html#defining-output)

### 5.2 必须先扩展解析器

现有 `math_independent.decode()` 明确只接受 SENSOR、CARTESIAN、identity model；当前 `analyze_independent.py` 又用 `norm(XYZ)` 计算距离。它们不能直接用于 B1/B2，更不能将球坐标三个分量误当 XYZ。

开跑前必须完成：

1. 依据安装头文件/枚举和官方 parser 核验每种模式的分量顺序、角度单位、坐标轴及模型变换；不根据字段名 x/y/z 猜测含义。
2. 为 WORLD 和 SPHERICAL 建立独立的规范化模块，与官方 parser 交叉核验，并用已知斜向射线、S0/S5 检查方向和距离。
3. 取得完整自有 GMO 后保留原始表示；派生出规范坐标、物理距离及方向，记录转换过程，不能改写原字节或头枚举。
4. 若 Extractor 始终输出 Cartesian、另有自带变换或该模式不支持其输出，按实际契约另存并比较；不能要求球坐标 GMO 三元组与 Extractor XYZ 直接逐值相等。
5. 无法验证布局或输出模式不被该构建支持时，结果为 unsupported/unqualified，不算仿真通过或失败。

规范化时，SENSOR 输出按源时刻实际 USD 世界变换转换；WORLD 输出本身已在世界系，不能再次乘传感器变换。SPHERICAL 先按已核验约定转换到其声明参考系的 Cartesian，再作必要参考系转换；模型到应用变换只按契约应用一次。原生 pose 头仅作被测元数据，不能用它替换实际输入真值来使几何通过。

GMO 分配长度可能大于头声明有效区间，继续保留全缓冲区，按声明范围校验字段。不能重引入 006 q01 的长度误判。

### 5.3 三类观测量

| 层 | 观测 | 比较方式 |
|---|---|---|
| D：距离 | 每射线物理径向距离 | 与当前及历史姿态的解析射线交点比较 |
| U：方向 | 规范化的传感器方向、世界方向 | 与原生发射器模型和源时刻姿态比较 |
| P：命中位置 | 规范化世界命中位置 | 与源时刻房间表面及可观测 yaw 比较 |

T2 的主条件中传感器原点与世界原点重合，发射器偏置为零。因此 CARTESIAN 输出的模长对纯旋转保持不变，可以作为坐标旋转之外的一项距离约束。仍需先排除模型变换、单位、数据对应和不支持模式的影响。

球坐标的径向分量也是对外输出，不能称为“内部未处理的射线距离”。若扩展到非零原点或发射器偏置，应从规范化命中位置减去相应真实射线原点后计算距离，不能继续直接取世界坐标模长。

### 5.4 因果判别

| 结果 | 优先解释 | 边界 |
|---|---|---|
| B0/B1/B2 的距离均不符合当前姿态、却符合相同历史候选 | 距离形成时的有效方向、几何状态或共同原生路径更值得检查 | 仍未直接看到实际射线和历史槽位 |
| 距离符合当前姿态，方向或世界位置错误，且依赖参考系/表示 | 优先检查输出转换、参考姿态或表示相关路径 | 不能仅凭属性名称锁定内部函数 |
| 改输出方式后物理距离也变化 | 输出模式可能切换了更早的处理路径，或规范化/语义尚不等价 | 不简单归因为“多转了一次矩阵” |
| 所有表示一致且当前姿态通过 | 当前构建/入口条件下未复现，应与 006 查差异 | 不宣布历史故障已被解释 |

“距离形成之前/期间”属于由不变量得到的机制约束；只有实际消费状态或内部中间量，才可进一步锁定具体计算位置。

## 6. T3：累积与运动功能的单因素干预

### 6.1 基础选择

优先在 A3 合格且稳定复现时以 A3 为基础 C0；否则使用本轮可复现的 A0。基础条件在本阶段开始前锁定，不能对不同开关各选最容易通过的资产或 API。

| 组合 | 相对 C0 唯一改动 | 检查目的 |
|---|---|---|
| C1 | accumulateOutputs=true→false | 是否依赖累积/跨帧输出路径 |
| C2 | Motion BVH=true→false | 是否依赖运动变换处理路径 |
| C3 | per-sensor TLAS=true→false | 可选；C1/C2 不能解释时检查渲染结构路径 |
| C4 | NONCOMPENSATED→COMPENSATED | 可选；T2 指向输出补偿或需交叉约束时开展 |

C1 与 C2 均以 C0 为底独立改变，不以 C1 为底继续关 Motion BVH。只有单因素结果提示交互时，才另外登记组合条件。

原生文档区分 Motion BVH 的运动几何支持与检测完成后的输出补偿；一个开关不能代替另一个。C4 需明确点时间与补偿参考时刻后再解释。[运动与输出补偿](https://docs.omniverse.nvidia.com/kit/docs/omni.sensors.nv.lidar/3.0.0/lidar_extension.html#motion-bvh-and-output-motion-compensation)

### 6.2 干预资格

每组先验证有效设置、10 Hz 原生节奏、完整扫描、射线身份、点时间分布及可比集合。关闭累积可能产生部分输出；这种结果先登记为扫描语义变化，不能与完整扫描基线直接比较并宣布修复。[扫描累积说明](https://docs.isaacsim.omniverse.nvidia.com/6.0.1/sensors/isaacsim_sensors_rtx_lidar.html#scan-accumulation)

Instant 语义不自动保证不同累积设置下内部路径相同。报告每事件 scanComplete、原生 new-scan 标志/可用等价字段、射线数量及身份分布，不能仅以点数相近认定同一次完整扫描。

Motion BVH 关闭后若不受支持、改变必要物理语义或实际节奏，就作为干预能力边界记录；不能包装为默认正确配置。保持 Multi-Tick 和显式 10 Hz，不同时关闭 Multi-Tick 来凑通过。

C1/C2 的有效干预结果无论改善、恶化或不变都保留。发现变化时用三次独立初始化确认，再决定是否构成工程候选；生产适用性另验收。

## 7. T4：有辨识力的运动控制

### 7.1 非匀速角增量编码

在固定 60 Hz 物理推进、10 Hz 采样下，使用预先生成的逐物理步角度表，不引入墙钟积分或在线反馈。建议首版确定性序列为：

```text
n = 1, 2, 3, ...，为局部运动步号
values = [0.02°, 0.05°, 0.10°]
j(n) = ((17 × n + 5) mod 31) mod 3
Δθ(n) = values[j(n)]
θ(n) = θ0 + sum(Δθ(1...n))
```

索引为零起始。完整角度表、算法版本和 SHA 在采集前保存，表一直覆盖到固定排空终点。周期 31 与采样步距 6 互质，可减少每次扫描只落在相同编码位置的混杂；不将该确定性序列称为随机样本。

每目标的预期扫描增量是实际两目标之间六步增量之和，不再使用固定 ω/10。输入资格按完整表核验。

预登记比较当前、前半步、前一步、前两步候选；半步是相邻实际旋转的最短弧中点，仅是诊断合成量。若增加固定秒数查询模型，须先冻结其参数和插值定义，并用另一物理频率的匹配输入验证；单一频率不能区分所有秒延迟与步延迟模型。

预测相同的“半步查询”和“相邻姿态中点”等模型保持等价组。非匀速序列用于区分预测不同的候选，不能凭命中率确定 SDK 内部使用了 SLERP 或某个浮点阈值。

### 7.2 传感器运动与场景运动互换

作为 T2/T3 仍不能收紧边界时的可选控制：

| 条件 | 传感器世界旋转 | 房间世界旋转 | 传感器坐标下的理想相对几何 |
|---|---|---|---|
| V-S | +θ(n) | 0 | R(-θ) × 原房间 |
| V-W | 0 | -θ(n)，绕同一原点 | R(-θ) × 原房间 |

两者的期望传感器局部射线距离相同，但世界坐标不同，须分别依据实际场景变换求交。将所有房间几何放在同一父节点下，并检查各墙实际世界矩阵，不继续把运动墙当作固定轴对齐平面。

若仅传感器运动出错，优先检查传感器变换路径；两者均出现相同有效滞后，则共同运动几何/历史消费路径更值得检查。由于场景运动和传感器运动可能走不同 Motion BVH 分支，该结果仍是约束，不能唯一定位函数。

## 8. 调度、保存及跨组比较

### 8.1 延续已验证的连续调度

使用 006 已验证的固定初始化和 24 次静态暖机。保存 PRE/POST 步号校准，运动开始前由原生源 tick 确定相位。

令步距 `s=6`，暖机结束当前步为 `k`，最后唯一源 tick 为 `a`：

```text
first = a + (floor((k-a)/s) + 2) × s
start = first - s + 1
target(i) = first + i × s，i=0...N-1
end = target(N-1) + 2 × s
```

首目标包含六个运动步。正常推进到固定 end，两周期排空期间继续按同一运动表旋转。不得按尚未收到合格帧而动态追加渲染、保持、fence、暂停或重新附着产品。

官方路径可以用受支持的正常推进流程，但必须保持一个仿真推进所有者。API 内部已经推进渲染时，不再叠加第二套推进。

### 8.2 事件、时间和射线身份

保存同事件的完整原始 GMO、可合法取得的原生输出、源时间、ReferenceTime、native frameId、产品作用域、epoch、回调单调时间、当时最新物理步以及复制/映射错误。

先取得自有字节，再记录映射与错误，离线做时间关联和几何分析。原生数组不能在寿命不明的异步任务中继续引用；禁止解引用未核验指针。

跨进程配对使用局部运动步和实际目标姿态，不比较绝对 epoch/frameId。射线对应使用资产模式定义的 emitter/channel/tick/echo 及必要的 tick state。官方资产如存在多状态/旋转模式，模型须包含每个 tick 的实际方位及偏置；不能继续仅用 emitterId 索引一张固定方向表。

同一资产/模式的不同输出表示需要完整射线集合可解释，才能比较逐射线距离。两边缺失或重复的身份单列，不通过只保留交集掩盖异常。跨资产不做射线逐点配对。

重复轮询和同源事件分别保存：轮询可以重复，但同一原生事件只占一个目标候选；原生事件自身重复、多个事件争同一目标或来源冲突仍计异常。去重依据必须先由身份契约核验，不能仅因载荷字节相同而去重。

### 8.3 数据目录与版本

建议新增独立命名空间，不覆盖 005/006 已锁定 spec 和原始数据：

```text
config/native_rotation_localization/<rules_version>/
  assets.json
  api_contracts.json
  conditions.json
  analysis_rules.json
  planned_order.json

reports/native_rotation_localization/<experiment_id>/<condition>/<profile>/<repeat>/<run_id>/
  run_spec.json
  environment.json
  effective_settings.json
  sensor_manifest.json
  output_topology.json
  pose_table.jsonl
  physics_states.jsonl
  raw_events.jsonl
  raw_payloads/
  normalized_data/
  analysis/
  run_result.json
```

上述为拟采用结构，并不表示工具已经实现。新分析器须独立发布版本；旧坐标模式的完整字节回归结果一致后再扩展。新模式只增加解析能力，不修改旧原始字节或把旧枚举改写成新枚举。

## 9. 指标、判据与证据等级

### 9.1 预登记指标

| 项目 | 判据/报告要求 |
|---|---|
| 推进、输入、时间关联 | 延续第 3.3 节；每目标唯一来源，固定 N 分母 |
| 静态解析资格 | S0/S5 每目标物理距离解析残差 P95 ≤10 μm，方向/坐标控制正确且 yaw 可观测 |
| 当前距离一致性 | 每目标当前实际姿态的解析射线距离残差 P95 ≤10 μm |
| 当前绝对几何 | 点到实际场景表面 P95 ≤5 mm，且可观测 yaw 偏差 ≤1e-4 rad；距离判据同时报告 |
| 扫描角增量 | 几何 yaw 增量与该两目标间规定增量差 ≤1e-4 rad；N 目标产生 N-1 对 |
| 原生 pose | 仅在字段语义已验证时，与源时刻实际姿态比较：位置 ≤1 mm、旋转 ≤1e-4 rad |
| 同资产表示间距离 | 按规范化物理距离和同射线身份比较，每目标绝对差 P95 ≤10 μm；集合差异单列 |
| 方向一致性 | 规范化单位方向的角差 P95 ≤1e-4 rad；另报分位数和最差射线 |
| 候选可区分 | 最佳组距离残差 P95 ≤10 μm，次佳至少 10 倍且差 ≥20 μm，否则 ambiguous |
| 数据与清理 | 完整自有字节、声明边界、布局、SHA 回读及有界清理全部检查 |

门槛沿用无噪声解析诊断口径，不代表真实传感器精度。某个官方资产不满足静态数值下限时，应先检查模型、有效噪声和量化；不能看过动态结果后单独放宽该资产门槛。确需新门槛时发布新规则版本和预登记依据，重新资格。

当前 yaw 局部拟合延续固定墙面分配、距离间隙 ≥0.05 m、至少 100 个点、两个非平行竖直墙各 ≥32 点、ΣJ²≥1 m²、float64 最多四次更新和 ±0.2°范围。新资产观测不足为 unknown，不用额外配准补救。运动房间须先将观测转换到已知房间坐标再应用等价几何规则。

各方向模式先保存原生向量和坐标约定，再作规范化。涉及世界方向时需原生发射器世界方向或有明确意义的方向字段；不能用“墙上命中点减传感器位置”反推方向后，再把同一个点同时当作独立方向真值。

### 9.2 定位结论的证据等级

| 等级 | 内容 | 可支持的结论 |
|---|---|---|
| E1：输出一致性 | GMO、Extractor/官方 parser、独立回读一致 | 保存或解析边界得到核验 |
| E2：几何与不变量 | 距离、方向、位置及姿态候选的独立解析 | 某些候选机制与观测一致/不一致 |
| E3：单因素干预 | 有资格对照下，仅一项变化稳定改变结果 | 该因素参与触发或影响处理路径 |
| E4：直接消费状态 | 核验语义后的实际历史端点、查询时刻、权重或射线状态 | 可以进一步定位实际状态选择/消费边界 |

E2 不能替代 E4。即使所有模式的距离都符合旧姿态，也不直接写成“已证明 SDK 取错历史槽位”。

### 9.3 终态与统计

分别报告 `capture_complete`、`measurement_qualified`、`comparison_qualified`、`distance_ok`、`direction_ok`、`geometry_absolute_ok`、`geometry_increment_ok`、`native_pose_ok`、`cleanup_ok`、`payload_generation_freshness`。

必要证据缺失为 unknown，不自动填 pass。静止状态的时间延迟不可辨识；新 callback/header 不等于实际重算。明确有一项质量判据失败即可报告相应失败，但不能据此丢弃整轮。

保留每目标与每相邻目标对的判定，分别汇总三轮。距离等点级指标先在每事件内统计，不能混成一个跨事件大点集。分位数统一 nearest-rank，报告 P50/P95/P99/max、带符号 yaw 和完整序列；首帧偏差不扣除。

全部本轮结果保持 `formal_continuous_acceptance=false`。功能关闭后通过、官方组合通过或输出坐标换算后通过，均不代表生产链已修复。

## 10. 首批矩阵、次序与扩展规则

### 10.1 首批必做范围

首批只包含六个不同条件：A0、A1、A2、A3、B1、B2；B0 与 A0 同条件共用本轮记录，不重复计数。

| 步骤 | 条件 | 每条件规模 | 总轮数/目标数 |
|---|---|---|---|
| Q1 | 六条件各 S0、S5、R6P | 各 12 目标、一次独立初始化 | 18 轮、216 目标 |
| Q2 | 六条件各 R3P | 12 目标、一次独立初始化 | 6 轮、72 目标 |
| M1 | A0、A3、B1、B2 的 R6P | 各 100 目标×3 次独立初始化 | 12 轮、1,200 目标 |
| 合计 | 前提全部满足时 | 每轮单 Kit 串行 | 36 轮、1,488 个计划目标 |

短轮 R6P 和 R3P 的动态几何失败是被测结果；只有输入、时钟、布局、静态模型或输出模式资格失败才阻断相应分支。所有分支失败/未执行状态均保留在矩阵里，不伪称完整 36 轮已完成。

A0/A3 的 M1 用于确认“当前原生复现/官方组合”的稳定性；B1/B2 的 M1 用于确认距离与坐标边界。A1/A2 首批仅短轮，报告中必须保留这一重复性边界。

### 10.2 固定次序

Q1 按 A0→A1→A2→A3→B1→B2，每条件 S0→S5→R6P；Q2 同条件顺序。测量链和各前提合格后锁定采集、解析源码及 M1 次序。

M1 顺序为：

```text
r01：A0 → A3 → B1 → B2
r02：B2 → B1 → A3 → A0
r03：A3 → A0 → B2 → B1
```

对照使用独立进程，不能同卡并行。初始化和缓存状态记录，不在条件间任意清缓存。运行时间和轮次差异不被当作几何机制本身。

### 10.3 扩展的预登记触发规则

| 触发 | 扩展动作 |
|---|---|
| 同资产的 A0/A1 或 A2/A3 短轮中，任一匹配目标的 pass/fail 或可区分候选不同 | 对该 API 对照先做拓扑/时序桥接核验；资格成立后补 R6P 100×3 |
| R3P 与 R6P 呈不同失败类别/候选，或候选切换需要解释 | 对相关对照补 R3P 100×3；保留两速度完整分母和共同朝向子集 |
| B1/B2 相对 A0 发生任一目标质量类别或距离候选变化 | 先复核规范化与静态控制；确认后增加 B3 的三短轮，必要时 R6P 100×3 |
| 首批复现仍成立，未找到明显 API/坐标差异 | 进入 T3 的 C1/C2，不重复旧历史容量 8/64 对照 |
| T3 某单项改变异常，且语义/完整扫描资格成立 | C0 与该条件分别 R6P 100×3，并用 R3P 短轮检查；之后才讨论组合干预 |
| T2/T3 仍不能解释历史候选，且接口无直接证据 | 进入 T4 编码运动；运动对象互换按第 7.2 节另行冻结 |

每个新增配置先做 S0/S5/R6P 各 12 目标，随后按触发进入主轮；不得因为首轮看起来更好而只保留改进条件。新增阶段的完整运行清单在启动前落盘，不根据已收到的帧实时选条件。

首批如 A0 不能复现，先比较构建、E 有效值、初始化和源码差异，登记“历史现象未复现”；不靠增加保持/修改角度来强行制造既有模式。

## 12. 资源、文件保护与实施边界

每轮建议延续初始化 180 s、总墙钟 600 s（预留 30 s 清理）、队列 256 MiB、轻量 trace 128 MiB、单份载荷 64 MiB 上限和每轮原始未压缩预算 2 GiB。RSS 上限为 `max(4 GiB, 2×初始化完成时 RSS)`，在运动开始前记录。

队列满、保存失败、布局不安全、资源超限时有界停止并保留前缀；不暂停物理等队列排空，不按误差丢事件。采集停止后执行有界清理并保存退出终态。
