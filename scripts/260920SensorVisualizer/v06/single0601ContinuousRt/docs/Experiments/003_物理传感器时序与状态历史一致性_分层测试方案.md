## 1. 测试目标与核心问题

验证连续采集失败是否来自以下链路中的时序不一致，并尽量定位最早出现分歧的边界：

```text
运动目标生成与位姿写入
  → 物理步及物理时间更新
  → USD / Fabric 当前状态同步
  → 原生变换历史记录与查询
  → 传感器 tick / 射线计算
  → GMO 及对外时间、位姿元数据
  → Writer 自有副本与文件
```

重点区分三个问题：

1. **时间数值是否一致？** 物理时间、渲染器读取的时间和传感器事件映射时间是否存在偏移、漂移或取错 epoch？
2. **时间和状态是否一致？** 时间已经到达 `t_k`，渲染使用的状态是否仍对应较早时刻？
3. **状态分量是否一致？** 位置、旋转、原生头及实际载荷是否使用不同历史样本？

物理 60Hz、传感器 10Hz 是合法的多频率采样。频率不同本身不构成故障；需要验证传感器在每个采样时刻使用了对应的完整状态。

本方案同时评估“一动一静”“四动两静”等保持窗口能否规避错误，但**根因证据与规避效果分别判定**。保持窗口通过，不意味着时钟或原生历史实现已经修复。

### 2.2 待区分假设

| 编号 | 假设 | 支持它的可观察结果 | 不能据此单独证明 |
|---|---|---|---|
| H1 | 物理、渲染或事件映射时间数值不一致 | 同源、同阶段比较出现稳定偏移或随运行增长的漂移 | 不同语义的 GMO timestamp 与 source time 数值不同 |
| H2 | 时间一致，但整份位姿历史落后 | 距离同时符合旧位置和旧旋转；延迟与阶段／相位相关 | 仅旋转误差恰好等于一个物理步 |
| H3 | 位置与旋转历史不一致 | `p(t_k)` 搭配 `R(t_k-δ)` 显著优于同一时刻完整位姿 | 因果发生在历史写入、查询还是下游消费 |
| H4 | 应用位姿写入与原生采样阶段错开 | 相同目标状态、同一时间网格下，改变合法写入阶段改变失败结果 | 直接断言 SDK 有缺陷或应用完全无责 |
| H5 | 小角度插值／数值分支异常 | 结果随每步角增量、绝对朝向或四元数表示变化，而非只随时间相位变化 | “float32 dot 接近 1”本身就是根因 |
| H6 | 缓存、跨 generation 或来源关联错误 | 新事件身份与载荷来源矛盾，或过期事件被关联到当前目标 | 静止时两份载荷字节相同 |

这些假设可以并存。允许结论为“支持 H3，尚不能区分 H4/H5”，不强制归入唯一原因。

## 3. 时间、状态与来源的统一定义

### 3.1 时间变量

| 字段 | 定义与使用规则 |
|---|---|
| `physics_step`、`t_phys` | 实际物理步编号及物理时间；正式状态账本的时间基础 |
| `t_timeline` | Timeline 的原始时间，仅用于诊断，不作为传感器时间戳来源 |
| `t_external` | Fabric `/ExternalSimulationTime.omni:time` 的实际读值；先核验类型、单位和采样阶段 |
| `reference_time_raw` | 同一原生事件的 RationalTime 分子、分母原值，保留整数表示 |
| `t_ref_mapped` | 经原生接口将 ReferenceTime 映射到物理时间的结果 |
| `t_sensor_source` | 同事件 `IsaacReadSimulationTime` 输出 |
| `gmo_timestamp/start/end` | GMO 各原始时间字段；分别记录语义，不默认等同于 source time |
| `t_callback_wall` | 回调到达的单调墙钟时间，只度量管线延迟，不能代替采样时刻 |

物理步使用整数；epoch/generation 使用明确的唯一标识，不根据时间数值猜测其归属。纳秒值保留为整数或十进制字符串。浮点 API 的原始返回值另存，不通过四舍五入到目标网格掩盖偏差。

`TimeSampleStorage` 的 ReferenceTime→物理时间映射与渲染器的变换历史是不同对象。前者检查通过，不能作为后者内容正确的证明。

`t_sensor_source` 与 `t_ref_mapped` 也可能共享物理时间服务或其样本；记录各字段的实际生产接口和依赖关系，不把两个一致的 API 读数自动计作两份独立真值。物理步数、回调原始 dt、阶段状态和解析几何分别提供其他约束。

### 3.2 状态变量

每次位姿写入及状态观测记录：`epoch_id`、场景 generation、物理步、应用目标 ID、写入 revision、实际采样阶段、root/关节/安装状态，以及传感器世界位置 `p`、旋转 `q/R`、矩阵 `T`。

分别保留命令目标、USD 实际读回、Fabric 当前读回、原生头矩阵和载荷诊断结果。不得把命令目标当作物理实际状态，也不得把回调中读取的最新状态替换为历史目标状态。

### 3.3 有限可观察性

| 等级 | 本轮应取得的内容 | 证据限制 |
|---|---|---|
| A：已有接口 | PRE/POST 物理状态、app update 前后、原生事件、当前 Fabric、原始 GMO | 只能证明这些边界的状态 |
| B：经核验的只读接口 | 原生历史样本时间、查询时间、返回变换；若 SDK 提供则记录 | 先核对本机构建接口及实际数据，不假设 API 存在 |
| C：内部计算 | GPU 实际射线原点、方向及采用的变换 | 若无法取得，标 `unavailable`，用解析几何约束候选机制 |

不同事件系统中的 `order=-100/100` 不具有天然可比较的全局顺序。必须记录真实回调顺序，不以注册数字推断早于原生历史提交。

不调用会刷新变换缓存的接口作为“只读探针”；不通过强制更新 Fabric、额外渲染或 fence 偷偷改变基线。若需要这类干预，应另开明确命名的实验条件。

## 4. 固定条件与试验资格

### 4.1 第一阶段只用最小房间

沿用已有非对称六面房间、单 MyAiry_front、零距离噪声和 10Hz 原生 tick。位置与旋转由规定轨迹驱动；不加入接触动力学。默认物理/loop 为 60/60Hz，当前渲染及 Motion BVH 设置不变。

记录实际 SDK/扩展/GPU 版本、源码和传感器参数哈希、`instantLidar`、发射器 fireTime、输出坐标/补偿模式、`tickRate` 与 `scanRateBaseHz`。后两者保持一致，本轮不把任意修改 LiDAR tick 当成无副作用的开关。

开始每轮前读回实际 dt、步数、时间和设置；配置 JSON 相同不代表运行状态一定相同。房间保持静态，路径预检始终处于内部。各条件使用相同初始位姿，warmup 条件和计入统计的范围预先固定。

### 4.2 规模与配对

- 新工具先运行 12 个计划目标的资格轮；资格轮全部事件保留。
- 正式诊断默认每条件 100 个 10Hz 计划目标、3 次独立 Kit 初始化。100 个目标首末间隔 9.9 秒；独立重复分别统计。
- 以真实源 epoch＋物理步＋sensor_id 关联；不按回调顺序、最近时间或几何最接近来选目标。
- C 先完成原始保存和排空，再由 F_room 应用全部计划目标的实际状态；C 有载荷失败而状态完整时，F 仍采相应目标。
- F 应用前后资格仍为位置≤10μm、旋转≤1e-6rad；有机器人时另查关节≤1e-6rad。资格失败单列，不计为连续链路质量失败。
- F_room 沿用已经验证的原 v06 SensorDrivers 保活及冻结生命周期。前序失败的自定义生命周期不重新作为默认参考。
- 不在同一卡上并行运行 C/F 或多个 Kit。

### 4.3 完整时钟配置与实际推进资格

每轮保存请求值、初始化后有效值、采样开始前有效值及设置来源。运行期出现设置变化时另记事件，不只保存最终值。

| 配置或读回 | 必须记录的内容 |
|---|---|
| 物理推进 | 请求 physics dt、实际回调 dt、真实步号、物理时间、每 app update 的物理步数 |
| Run loop | 请求 loop dt、manual mode/manual step、rateLimitEnabled/rateLimitFrequency、实际 update 序号与单调时间 |

## 5. 分层测试矩阵

### T0：测量链资格和观察开销

先补齐并验证阶段观测，不能直接用新增探针的结果替代旧基线。

| 条件 | 内容 | 目的 |
|---|---|---|
| T0-A | 原有运动/渲染策略＋共同原始保存旁路，不加扩展阶段探针；0.3m/s＋3°/s，100 目标×3 | 重现失败模式，锁定新轮基线 |
| T0-B | 与 A 完全相同，只增加 A 级阶段只读记录，100 目标×3 | 判断阶段观察开销是否改变覆盖、误差分类或可观察顺序 |
| T0-C | 静止，12 目标资格；必要时扩 100×3 | 检查时钟正常推进、新事件来源和静态数值下限 |

新增观测必须有界、异步落盘；物理线程只复制小型状态，不同步写大文件。A/B 的几何类别若变化，报告观察者效应，先缩小记录负担，不选择“看起来更好”的那一组。

A/B 共同锁定：同一目标表和初始姿态、原生 tick 相位、warmup、产品/annotator 集合、全部 XYZ 和完整 GMO 保存、CPU 拷贝/队列/落盘策略、线程数和预算。不能让 A 只保存三个 GMO、B 保存全部 GMO，也不能只在 B 中引入新的运动驱动。T1 拒绝前旁路是 A/B 共用的测量基础；其正常路径先与旧基线对照，不能把这个共同变化的影响归给阶段探针。

每次独立 Kit 初始化；默认预先固定运行次序为 A1→B1→B2→A2→A3→B3，或在采集前保存随机种子及完整次序。记录缓存/启动状态，不在条件之间清缓存。共同最小元数据、全目标覆盖、逐目标误差类别、回调耗时与资源统计都参与 A/B 比较；A 未观测的阶段顺序记为 unavailable，不能从 B 反推。若共同测量路径或阶段探针导致模式变化，先另开版本缩小观测负担并复核，不把不等价 A/B 当作无观察者效应。

静止状态不适合识别几何对应的具体时间：多个时刻位姿相同。T0-C 只检查时钟和新事件资格，不据此宣布时序正确。

### T1：时钟数值、实际步进与 tick 相位

在 T0-B 中同步记录以下阶段：app update 进入、PRE 写位姿前后、POST 实际读回、app update 返回、同一原生 Writer 事件。若存在经验证的渲染提交前只读钩子，可增补，但不可假装 app update 返回就是 GPU 射线执行时刻。

逐目标计算并保留原始量：

```text
Δ_ref = t_ref_mapped - t_sensor_source
Δ_state = t_sensor_source - t_phys_of_matched_state
Δ_external = t_external - 同阶段可比较的 t_phys
Δ_timeline = t_timeline - 同阶段 t_phys
实际每 app update 物理步数
相邻事件的源时间增量与真实物理步间隔
```

`Δ_ref`、`Δ_state` 继续使用 2ns 关联门槛。其他差值先按阶段及 SDK 语义判断；PRE 阶段的上一物理时间、GMO 扫描起点和异步回调晚到，不应自动判为故障。

**观测必须位于时间关联拒绝之前。** 现有后端在 source/ref 差值超限时会拒绝事件；本轮需要独立诊断旁路保留原始时间、原生身份及已合法取得的自有载荷，再记录拒绝原因。两个时间源冲突时均保留，载荷标 `unassigned`，不猜测一个目标进行配对；计划目标仍进入缺失／不合格分母。只要采样仍在推进且所有权和预算有效，就继续预定有界采样，不能因首次时钟异常而失去后续漂移证据。正式路径的 2ns 门禁保持不变。

该旁路属于开跑前必需实现项，固定处理顺序如下：

1. 取得同事件可用的原始 source/ref/GMO 字段、产品作用域、generation 和回调单调时间。建立本地 `diagnostic_event_id` 作为文件索引，明确它不是原生 frameId，也不是采样来源证明。
2. 仅按布局、有限性、所有权及预算检查取得独立 CPU 副本；原始 GMO 与解析副本分离。字段缺失、映射接口异常时仍保存其余合法证据；非法或无法安全取得的载荷只记录拒绝原因。
3. 先排队保存原始事件及合法载荷，再执行 ReferenceTime 映射、source/ref 比较、物理状态关联和计划目标关联。各阶段分别记录成功、失败或 unavailable。
4. 保存函数不调用 `ledger.exact_time()`，关联函数的失败不撤销已保存载荷。对冲突 source/ref 可列出各自唯一匹配的状态作为诊断，但不选择其中一个来制造合格配对。

正常目标之外的重复、迟到和未归属事件进入独立事件表，并受共同预算限制；不能只保存落在 `target_steps` 的事件，否则会隐藏相位跳变。有限计划区间加预先声明的启动/排空观察区间界定保存范围。计划目标按自身物理网格结束，不能因拒绝事件多而自动延长到“凑够成功数”。

先以离线构造的 source/ref 冲突、映射异常和缺失状态验证旁路：合法载荷可回读、拒绝原因完整、目标分母不变，正式路径仍拒绝不合格事件；这些故障注入结果不能冒充 SDK 实测故障。

检查是否有时间回退、epoch 混用、tick 重复、缺路、相位跳变，以及偏差是否随运行增长。正常基线期望相邻 10Hz 事件间隔为 0.1 秒、6 个真实物理步；实际计数仍以原生事件为准。

**判定：** 发现可重复的同语义时间分歧则支持 H1；全部一致只说明对外时间映射合格，继续 T2，不提前排除状态历史问题。

### T2：分离整帧滞后和位置／旋转分量滞后

使用以下规定运动，新增条件各 100 目标×3；已有 T0 混合块可复用同一轮证据，不重复计作新独立样本。

| 条件 | 运动 | 主要可观察量 |
|---|---|---|
| T2-P | 纯平移 0.3m/s | 位置历史偏差；旋转延迟不可识别 |
| T2-R+ | 纯旋转 +3°/s | 旋转历史偏差；位置延迟不可识别 |
| T2-R− | 纯旋转 −3°/s | 偏差是否随方向翻转 |
| T2-PR | 0.3m/s＋3°/s | 整份旧位姿与分量混合的区分 |

用实际发射器方向、已知六面和实际状态账本计算候选距离。候选预先限定为：

1. 当前完整实际位姿。
2. 前 1 步和前 2 步的完整实际位姿。
3. 位置与旋转使用相同半步时刻的合成位姿。
4. 当前位置＋半步/前 1 步/前 2 步旋转。
5. 半步/前 1 步/前 2 步位置＋当前旋转。

半步位置插值和旋转 SLERP 均标记 `synthetic_candidate`；不冒充实测状态，不用于重新配对，也不输出“补偿后的合格数据”。真实前一步负对照与合成半步对照分开保存。

先用 F 验证解析模型：同条件 F 的每组射线距离 P95 应≤10μm。该值是针对已有约 2.54μm 基线提出的**分析模型资格门槛**，不是替代正式 5mm 几何门槛；若达不到，先解释模型／条件变化，不据此做时延分类。

候选必须**先按状态等价归组，再比较不同组的解释力**，不能先选最佳/次佳标签后才处理等价。纯旋转时“前一步完整位姿”和“当前位置＋前一步旋转”可能是同一变换，它们的并列不能否定“旋转落后”的分量结论。

归组与判别规则在新实采前冻结：

- 状态等价的初始数值容差为位置差≤1e-8m、旋转测地角≤1e-8rad；这是合成分析数值容差，不是原生输出门槛。先检查有限性、矩阵刚性及四元数合法性，不用强制正交化或归一化掩盖非法原始输入。
- 按固定候选 ID 次序归组；加入某组须与该组全部成员满足容差，避免 A≈B、B≈C 却 A≉C 的链式合并。该组代表取固定 ID 次序首项，不按输出残差挑代表；保留全部成员及各自残差。
- 在不同状态等价组之间排序，报告最佳组、次佳组、各组每点残差与 P50/P95/P99。仅当最佳组全部成员 P95≤10μm，且次佳组最小 P95 相对最佳组最大 P95 同时满足十倍及≥20μm差距时，标为 `distinguishable_group`。零残差情况下仍必须满足绝对差距条件。
- 不满足差距、不同组预测几何不可区分或只有一个等价组时，保留 `ambiguous`/`unobservable`。不得靠候选枚举顺序生成唯一根因；缺少所需历史步时将该候选记为 unavailable，不能以不完整候选集声称已排除缺失候选。
- 分开输出 `position_delay_identifiable`、`rotation_delay_identifiable` 及候选延迟集合。纯旋转下位置延迟不可观察，不能写成位置延迟已证明为零；纯平移同理。多个不可区分组若共享某个分量结论，可仅报告该分量，其他部分继续保留歧义。

用独立解析运动生成器构造整步、半步和分量错配载荷，不仅把分类器自己的候选函数拿来生成预期答案。验证等价归组、真实前一步负对照和合成半步对照后，再将上述容差写入 `analysis_rules.json`。若资格检查需要修改容差，先保存新规则版本，不能根据新实采的好坏结果调整。

若恒速轨迹仍不足以区分候选，再增加预先保存的平滑非匀速、反转轨迹，使位置和旋转具有不同变化节奏；轨迹参数、范围及分析方法须在该轮开始前写入配置，不能依据输出临时调到最吻合。

### T3：物理时钟与传感器采样相位对照

保持 60/60Hz、10Hz、同样速度和初始姿态，只改变“运动开始”相对已经验证的原生 tick 的物理步相位，取 0、1、2、3、4、5 步。

先静止观察足够的新原生事件以确认实际 tick 节拍，再按预定物理步开始运动。相位锚点来自原生源时间与物理步，不来自 Writer 回调到达时刻；不重写传感器时间或使用未经验证的 tick-phase API。

每个相位采 100 目标×3。分析同时以绝对物理步、运动进度和实际 yaw 分组。相位变化会使传感器取到不同运动进度，不能把相同 `target_index` 当作相同输入位姿；各自以实际状态和 F 检查。

结果若跟随 tick 相位改变，支持调度／历史取样相关机制；若更稳定地跟随实际朝向或每步角增量，转向 T4/H5。相位实验本身不能完全分离绝对姿态的影响，存在混杂时明确记录，不宣称唯一根因。

六相位是完整条件表，是否启用由第 7 节的分支条件决定。开始 T3 前，按目标表预先保存各相位的实际预期采样朝向和共同朝向区间；整体统计保留全部 100 目标，按共同区间的比较是另外声明的分层统计，不插值点云以制造相同输入。

若“相位变化”与“采样朝向变化”仍无法分开，新增相位×初始朝向对照；例如固定相位 0/3 步、初始 yaw 0°/15°，形成四个完整条件，而不是只改变其中一个组合。精确初始值、目标表、资格与三重复清单在该补充批次开始前冻结。该对照用于区分两类影响，仍不能直接证明内部历史查询顺序。

### T4：改变步长，区分固定时延和角增量问题

保持 LiDAR tick/scanRateBaseHz 为 10Hz，先做下列条件，物理与 loop 始终同频：

| 条件 | 物理/loop | yaw 速度 | 每物理步角增量 |
|---|---|---:|---:|
| T4-A | 60/60Hz | 3°/s | 0.05° |
| T4-B | 120/120Hz | 3°/s | 0.025° |
| T4-C | 120/120Hz | 6°/s | 0.05° |
| T4-D，条件性补充 | 60/60Hz | 6°/s | 0.10° |

先执行 A/B/C 的纯旋转比较，再按需要扩到混合运动。每条件 100 目标×3，传感器目标数与仿真覆盖保持一致；实际目标步间隔分别为 6 或 12。按 4.3 核验完整时钟设置与真实 dt，而非只记录配置。T4-A 只有在运动目标、初始状态、相位、warmup、测量及保存策略均一致时，才可复用本轮 T2-R+；复用必须引用原 run，不重复计为新的独立样本。

A/B 的 10 秒运动角范围约为 30°，C 为 60°，所以不能直接将整轮差异全部解释为步长效应。主统计仍报告全部目标；机制比较在采集前声明共同区间，例如相对初始 yaw 的 `[0°,30°]`，并保存各条件目标索引清单、预计数量及相同宽度的朝向分箱。实际读回不符合目标表时标资格问题，不事后按误差挑点。分箱内分别报告样本数，不能把样本密度差异当作失败率改善，也不插值原始输出。

以 `δθ/ω` 计算等效旋转延迟，仅作为几何推断：

- 偏差更接近固定物理步数，支持按步历史滞后。
- 偏差更接近固定秒数，支持时间偏移／固定时间窗口，但仍需排除其他机制。
- A/C 表现相近、B 明显变化，提示每步角增量或小角度分支；不能仅凭这一点确认数值算法错误。

这里存在明确的可识别性限制：“始终取前一步旋转”和“某角增量下错误取前一步旋转”都可能在 A/C 产生相同角偏差。应先为各假设列出 A/B/C 的预期角误差、等效秒延迟及步延迟；预测相同的部分标记为不可区分。

若 A/B/C 后仍无法区分，按预先声明的分支启用 D，构成频率 60/120Hz×角速度 3/6°/s 的四条件比较；再依据共同朝向区间内的变化决定是否增补初始 yaw 扫描或非匀速轨迹。完整二维对照能增加约束，但仍不单独确认某个 SLERP 实现错误。`δθ/ω` 只用于恒定且非零角速度区间；保持和反转附近不作除零或不稳定延迟估计。

**四元数表示实验须先证明表示确实传入被测路径。** 当前房间入口将四元数转换为 `Gf.Matrix4d` 后写入，`q` 和 `−q` 得到相同矩阵；只改变 Python 四元数符号不构成有效的原生表示干预。仅在已核验的 orientation 属性或原生接口能够保留并观测表示差异时，另开表示对照，并检查实际旋转等价。更换矩阵/四元数 authoring 方式本身也属于新的写入路径条件，不能与符号因素混为一项。

如果 T1 显示每 app update 的物理推进不符合预期，才增加 `physics=120Hz/loop=60Hz` 或 `physics=60Hz/loop=120Hz` 的短资格对照。它们会改变每次渲染前的物理步数，单独解释，不与默认同频条件合并；无物理步的 app update 不要求产生新传感器事件。

### T5：位姿写入阶段对照

仅在纯 USD 房间中进行，避免把 articulation 求解和接触行为一起改变。

对照现有 PRE 写入，与 SDK 支持且已验证的其他写入阶段，例如同一 PRE 事件内不同顺序或 POST 阶段。一次只改变一个阶段／顺序条件；不得把“POST”天然理解为早于原生渲染历史提交。

执行前必须完成：

1. 实测各阶段 `physics_step` 与 `t_phys` 的约定，防止 PRE 计算下一步目标、POST 却再次加一步。
2. 从同一预定义目标表取得该物理时刻的目标位姿，不依赖回调调用次数累计运动。
3. 在每种写入策略之后读取实际状态，确保所有正式采样目标仍落在相同物理时间网格，且实际位置/旋转满足输入资格。
4. 调整实际状态观测的依赖顺序，不能先记账、后改写同一步位姿。

共同目标表须先在原 PRE 路径验证能重现预定输入与已知失败模式，再切换写入阶段。每步最终实际状态只发布一次到正式状态账本；同一步多阶段的观测另存 trace，不覆盖不可变历史。记录 app update ID、事件类型、回调进入/退出顺序及位姿写入 revision，这些仍仅证明 CPU 可观察顺序，不推断 GPU 完成先后。

若目标资格不成立，该条件标记为“改变了输入时序”，不能用于直接宣称更新顺序修复。先做 12 目标资格，合格后才扩 100×3。

若实际输入一致而结果随写入阶段稳定变化，支持 H4；仍需通过 B/C 级观测或进一步控制，区分应用提交时机、历史写入和 GPU 消费。

### T6：保持窗口规避测试

保持窗口定义：**物理时间和正常 app/render 更新继续推进，传感器实际世界位姿保持不变。** 不调用 Timeline pause，不增加手动 Replicator 冻结步，不临时开关产品。关节、父节点及安装变换都应保持；发出零速度命令并不等于实际位姿立即停止。

在每六个真实物理步的末步采集，首先比较：

| 条件 | 六步内的运动／保持安排 | 用途 |
|---|---|---|
| HOLD0 | 动、动、动、动、动、动 | 连续基线 |
| HOLD1 | 动、动、动、动、动、保持 | 一步保持 |
| HOLD2 | 动、动、动、动、保持、保持 | 用户提出的四动两静 |
| HOLD3 | 动、动、动、保持、保持、保持 | 检查增加保持长度是否进一步收敛 |
| HOLD_ALT | 动、保持、动、保持、动、保持 | 用户提出的一动一静 |

HOLD2 的目标状态序列为 `P1,P2,P3,P4,P4,P4`。末步对应事件是否真实落在保持窗口，要由实际源时间验证。若传感器各自相位不一致，不能依靠全局 `%6==0` 假定所有路都已保持两步。H1–H6 专指第 2 节假设，不再用来命名保持模式。

**保持数值相同与不再写入，是两个独立条件：**

| 写入方式 | 保持步行为 | 必须记录 |
|---|---|---|
| `WRITE_SAME` | 在原写入阶段每步调用相同 API，将捕获的同一目标值写回；不重新积分出“近似相同”的值 | API 调用次数、参数摘要、写入 revision、前后实际矩阵 |
| `SKIP_WRITE` | 保持步不调用位姿写入 API；其他物理与渲染推进方式相同 | 跳过记录、最后写入步、实际矩阵以及是否有其他写入者 |

同一 HOLD 模式的两种方式使用相同逐步目标表、采样相位和实际姿态资格，运动步的写入方式完全相同。先检查整个保持窗口内实际世界矩阵是否在输入容差内恒定，不仅检查末步。父节点、关节或其他回调仍改写状态时，该 `SKIP_WRITE` 对照不合格。

当前 `_room_pre()` 即使速度为零也会每步 `Set` 矩阵，因此现有“零速度”不能代表 `SKIP_WRITE`。两种方式可能影响脏标记或历史提交，这只是待测机制，不能预设 SDK 一定会插入不同样本。

默认先执行机制组：HOLD0 一份共同基线，加 HOLD1/HOLD2/HOLD3/HOLD_ALT 各自的 WRITE_SAME、SKIP_WRITE，共九个唯一条件；每条件按下文先资格再三重复，分批运行。HOLD0 没有保持步，不为两种写入方式重复计数。若与本轮 T0/T2 对应条件的输入、相位、观测和保存策略完全一致，可引用其原始 run 作为 HOLD0，不重复计为新独立样本。若因预算缩小条件表，必须在该批开始前锁定所选模式及其成对写入方式；看到某组通过后不能删掉同批失败或尚未完成的对照。

需要分两组开展，避免混淆原因：

- **机制组：** 运动步保持原来的角增量和速度，不补偿静止时间。用实际几何评价，只回答保持是否改善；各条件平均速度与目标路径可能不同。
- **应用组：** 预先设计每个采样边界具有相同目标位姿的轨迹表，运动集中在前若干步完成，再保持到采样。它改变了运动段速度／加速度，要单独与原基线比较，不能仅按“速度乘 1.5”假定转弯路径完全相同。

保持平均推进速度时，HOLD2 的运动段平均速度约需增加至原来的 1.5 倍，HOLD_ALT 约需 2 倍；这也改变每步角增量，可能触发不同数值分支。因此不能只做应用组就归因于保持窗口。应用组另开批次，至少保留被选 HOLD 模式的两种写入方式和边界位姿一致的连续参考，不能自动沿用机制组的“同路径”结论。

每条件先 12 目标资格，再 100×3；不得因某个保持长度恰好通过就删除其他条件。若 HOLD2 仍失败，结合 T1 检查相关历史是否只在传感器 tick 更新。必要时另开跨完整 tick 的保持条件：它会降低目标运动更新频率或增加额外传感器事件，必须重算目标数和吞吐量，不可伪装成相同的 10Hz 运动产出。

相同位姿、静态场景下，旧/新载荷可能完全相同。分开评价：

- `event_provenance_ok`：原生事件身份、产品/generation、source/ref 及目标映射具有合法来源。
- `payload_freshness_ok`：有证据支持该载荷属于本次生产结果，而非旧载荷附上新的事件时间。记录 `freshness_evidence_kind` 为经核验的生产端契约、可区分的变化响应，或 unavailable。

新的回调、项目计数、header 或 frameId 不能脱离其原生语义单独证明载荷重算；字节相同也不能单独判旧帧。若只能确认事件来源，稳定保持片段的载荷新鲜度标 unknown，不将其计为已证明重算。经核验的同事件生产契约可以支持来源结论，但应保留其版本与适用条件，不宣称取得了内部 GPU 执行记录。

必要时另开新鲜度资格轮：保持传感器，按预先保存、能排除固定旧帧解释的目标序列移动一个已知解析几何标记，记录标记每步实际状态，计算各候选历史下的预期返回，并让 F 重放同一标记状态。该轮改变了环境的静态条件，独立报告传感器与物体历史，不混入主房间的六面残差统计。它只能证明所测变化与转换边界的响应；不能由一次边界响应反推所有稳定保持事件都重新计算。

**通过含义：** 所测保持模式的几何通过，只说明其载荷与实际状态一致；来源与新鲜度另列。若只有 SKIP_WRITE 改善，支持写入/状态更新路径影响，不能解释成“单纯多等两步”。任一保持规避通过都不等价于假设 H1 被证实，也不等价于匀速连续运动已通过。

### T7：最小场景外的适用性确认

只有房间中选定模式完成三重复且共同门槛通过后，才扩到 scene18 的 front＋MyAiry。相机明确选择与 F 相同的单 DomeLight，保留原始噪声与标定条件。

检查机器人根节点、关节和安装状态，不能只保持传感器局部变换。若加入动态物体，还需区分传感器历史与物体历史；保持传感器位姿不会自动修复动态物体的历史问题。

对保持模式额外记录采样时刻实际速度、平均路径推进速度及墙钟合格产能。图像需独立已知标记重投影，不能把 LiDAR 通过推广为相机通过。4 相机＋13 LiDAR、IMU 融合、接触动力学及长期行为仍是后续独立资格。

## 6. 指标与判断规则

| 层次 | 必须报告 | 通过或解释规则 |
|---|---|---|
| 计划覆盖 | 全目标数、实际事件数、缺失、重复、未归属、失败前缀 | 分母始终为预定目标；不能只统计保存成功的目标 |
| 输入资格 | 实际位姿、root/关节/安装、采集前后状态 | 沿用 10μm、1e-6rad 输入门槛 |
| 对外时间 | 原生 source/ref、物理步映射、epoch、各阶段差值 | source/ref 与目标关联≤2ns；其他字段按语义判断 |
| 原生位姿 | 位置与旋转误差、与载荷几何的交叉表 | 输出≤1mm、≤1e-4rad；不单独作为总通过条件 |
| 独立几何 | 每组点到面 P50/P95/P99、yaw、不可观察项 | 房间点到面 P95≤5mm、可观察 yaw≤1e-4rad，逐组检查 |
| 原始载荷 | GMO 原始 SHA、独立解码与 XYZ、文件回读 | 不修改源字节，解析副本与保留副本分开 |
| 来源与新鲜度 | 事件生产语义、generation/产品身份、载荷新鲜度证据及其适用范围 | 事件来源与载荷重算分开；不能观察的项为 unknown，不以新 header 代替证明 |
| 机制分析 | 候选等价组残差、分量可识别性、等效延迟、最佳/次佳组、歧义 | 仅作解释；不可用拟合后的点云重新计算原始通过率 |
| 代价 | 仿真采样率、实际墙钟合格组/s、路径推进/s、额外渲染、内存 | 10Hz 仿真输出不等于 10 组/墙钟秒，也不等于原运动速度 |

主统计采用**时间×原生 pose×独立几何**的互斥联合状态，三轴均为 `pass/fail/unknown`。三轴全部可判定时为 8 个互斥单元；其余带 unknown 的组合独立列出，合计最多 27 个单元。C/F 分侧、按条件/轮次/启动/运动/保持边界分别统计，不以全局均值掩盖失败。

以每个计划 sensor-target 一行记账，所有联合状态行数之和必须等于计划分母。缺失载荷、重复/冲突、输入不合格和不可观察原因另列字段与计数；这些原因可以重叠，不能直接相加。重复事件保留在事件表，不使目标表增加行。未归属事件没有合法目标键，单列事件计数，不能为了填满联合表将其分配给任意缺失目标。

同时从联合表派生“时间通过但几何失败”“原生 pose 通过但几何失败”“姿态与几何均失败”“三轴全部通过”等关注指标，并明确它们可能重叠，不能相加作为总失败数。输入资格及来源/新鲜度不混进这三轴；三轴全通过但输入不合格或新鲜度 unknown，仍不能宣布总体通过。

完整条件正确性判定要求所有计划目标具备合法来源、完整载荷、合格输入、可观察几何及足够的新鲜度证据，且共同门槛逐组通过。不可观察项为 `unknown`；覆盖不足、输入不合格或必要证据 unknown 时，不发布总体通过结论。可以单独报告“本模式几何通过，新鲜度未证明”。诊断测量链资格不要求 C 几何通过，否则会排除本方案需要研究的失败样本；T7 若缺少完整资格，只能标为探索性适用性观察。

## 7. 实施顺序与停止规则

推荐执行顺序为：**测量/分析器资格 → T0/T1 → T2 → T4 → 按证据选择 T3 或 T5 → T6 → T7**。不默认一次跑完全部矩阵。

若近期优先目标是取得可用数据，可在 T1/T2 的测量链合格后先执行 T6，但须分别交付“保持模式效果”和“根因证据”。不得以规避通过跳过未完成的根因记录。

| 阶段或分支 | 启用条件及交付 |
|---|---|
| 开跑准备 | 8.1 的离线资格通过，8.2 的必需测量缺口已实现；12 目标验证输入、来源/保存、有效时钟条件和 F 解析模型，C 几何失败不阻止继续 |
| T0/T1 | 形成共同测量基线及探针影响结论；存在明显观察者效应时先修正测量条件，保留所有旧结果 |
| T2 | 至少分清平移/旋转的可观察性、状态等价组及拒绝前证据；此时可根据近期目标启用 T6 |
| T4-A/B/C | 用纯旋转、共同朝向区间核对按步与按秒预测；仍歧义时按已声明分支补 D，或保留结论为不可区分 |
| T3 | T1 或 T4 显示相位相关线索，或需专门区分朝向混杂时启用；启动前锁定完整相位/朝向条件表 |
| T5 | 已核验合法事件接口及目标表一致性，需要区分写入阶段时启用；缺少 B/C 内部接口不妨碍合格的 A 级阶段对照，但限制其归因深度 |
| T6 | 机制组和应用组独立批次；同一模式的 WRITE_SAME/SKIP_WRITE 成对比较，分别报告几何、来源、新鲜度与代价 |
| T7 | 选定模式完成重复与资格后扩场景；任何必要项未知都应保留为探索性结果 |

“按证据选择分支”只决定尚未启动的下一批工作，不允许删除已经锁定批次中的失败条件。满足分支条件也不意味着一定取得唯一根因；B/C 级观测不可用时，完成有区分力的 A 级对照并报告机制范围即可，不能靠继续增加同类样本填补内部观测缺口。

每个阶段先落盘锁定条件清单、目标数、repeat、初始状态、采样相位、warmup、逐步目标表及哈希、候选等价/判别规则、共同朝向区间与分箱、运行次序和预算。条件表标注 `planned/running/completed/failed/not_run`，另记分支启用依据、未运行原因及来源 run；条件增补另开版本，原失败轮次保留。

默认资源上限，执行前依据实际可用资源校核：

- 单侧保存队列 256MiB；单侧全部证据预算 2GiB，其中阶段 trace 子预算为 128MiB。
- 初始化期限 180 秒；C 总墙钟 600 秒、F 总墙钟 900 秒，初始化包含在总期限内。
- 一批最多 6 对 C/F，单对包含一次 C 和一次 F，保存总预算 24GiB；12 目标资格轮也计入本批对数与字节预算。开始前除本批预算外至少保留 8GiB 可用磁盘。若容量不足，先缩小预定批次，不在采集中删旧证据。T6 默认机制组九条件的资格与三重复超过一批，必须事先分批，不能把 6 对理解成 6 个各含三重复的条件。
- 主轮保存全部 XYZ、全部元数据和全部完整 GMO；按现有包大小估计单侧 100 组低于 2GiB，仍以实测累计字节为准。
- 内存/RSS 上限在资格轮根据实际基线及剩余 RAM 固定，不临时无限扩队列；记录 GPU 使用并确保单 Kit。

几何超限和可保存的时间关联失败不终止预定采样。所有权失效、物理时钟／状态账本停止推进而无法继续定义目标、原始保存预算耗尽、进程崩溃或房间越界时停止该轮并保留前缀。到达墙钟期限应记录具体阶段，不能把“等待超时”直接解释为物理同步根因。

任何新增接口若需要更新 SDK、安装依赖或使用调试构建，应单列为后续工作；本测试方案不默认包含这些环境变更。

### 8.1 分析器自身资格

沿用已有字节解码、SHA、负对照和分母测试，额外验证：

- 独立解析生成的整步、半步、仅位置落后、仅旋转落后，能够被候选分析区分；不能区分时返回歧义。纯旋转/纯平移/静止的等价候选先归组，单分量不可观察性正确保留；候选缺失不形成虚假的唯一解释。
- PRE/POST 同一目标表不会重复推进一帧，保持窗口实际状态不变而物理时间正常增加。
- WRITE_SAME 在保持步实际调用相同值写入，SKIP_WRITE 没有该调用；两者全部目标和保持窗口的实际位姿等价，其他写入者会被识别。
- source/ref 冲突、映射接口异常及 ledger 缺失时，合法自有载荷仍被保存，关联失败不会撤销文件或缩减计划分母；非法载荷不绕过所有权检查。
- 无物理步的 update、回调晚到、epoch 切换和缺失目标不会被误配为当前采样。
- 相同静止载荷不会仅凭字节相同被判旧帧，也不会仅凭项目计数增加被判新帧。
- 三轴联合表互斥且计数和等于计划 sensor-target 数；重复和未归属事件不增加目标行数，派生关注指标的重叠被明确保留。
- T3/T4 的共同朝向区间及分箱由目标表预先生成；全目标统计不因分层分析而缩减，无物理推进/请求频率未成立时正确标资格失败。

这些测试只验证新增观测和分析逻辑；原生历史是否正确仍须实采证据。

## 9. 结果解释模板

| 实测结果 | 允许形成的结论 | 下一步 |
|---|---|---|
| 同语义时钟确有偏移，修正后原始几何同步改善 | 支持 H1；需以三重复确认修正效果 | 保留同状态冻结参考，验证其他运动和启动阶段 |
| 时间全部一致，完整旧位姿等价组可区分，且位置/旋转均可观察 | 支持整份状态历史滞后 H2 | 定位历史提交和查询边界 |
| 时间一致，当前位置＋旧/半步旋转组可区分，且位置延迟亦可观察 | 支持分量不一致 H3 | 写入阶段、角增量及内部历史观测 |
| 纯旋转中旧完整位姿与当前位置＋旧旋转等价 | 只支持可识别的旋转延迟；位置延迟未知 | 混合或独立非匀速运动，不能强行区分 H2/H3 |
| 改写入阶段后改善，但实际目标位姿也变化 | 对照不具备直接因果资格 | 先修复目标表和实际读回，重做资格轮 |
| 同一写入方式和运动组内，保持两步几何通过、一步失败 | 所测模式需要更多保持余量 | 判断物理步历史还是传感器 tick 历史；不能直接锁定内部函数 |
| 同一 HOLD 模式只有 SKIP_WRITE 几何改善，实际状态与 WRITE_SAME 等价 | 支持写入/更新路径影响，单纯等待解释不足 | 定位位姿 authoring、脏标记与历史提交边界，仍需原生观测 |
| 保持几何通过、原生事件来源合格，但载荷重算不可观察 | 几何与来源结论成立；载荷新鲜度 unknown | 单列资格轮或核验生产端契约，不发布总体通过 |
| 所有短保持均失败，跨 tick 保持改善 | 提示相关状态可能按传感器 tick 或更长窗口更新 | 直接观测历史更新频率，单列吞吐损失 |
| 保持通过，但 60→120Hz 关系不支持固定时延 | 规避有效，时钟偏移解释不足 | 优先检查角增量和插值分支 |
| 只有元数据变好，载荷几何仍失败 | 规避／修复未通过 | 继续以解析几何及原始 GMO 为主 |

最终报告必须说明：已证实事实、支持的机制范围、尚不可观察的内部环节、所测模式的适用范围及运动/吞吐代价。原生时钟、TF 和原始点云都不得通过移帧、改 header 或事后旋转来制造通过。
