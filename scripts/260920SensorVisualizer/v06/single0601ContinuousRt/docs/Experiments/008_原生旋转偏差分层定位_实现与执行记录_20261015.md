# 原生旋转偏差分层定位：实现与执行记录

日期：2026-10-15，Asia/Shanghai。对应 [007 实验方案](007_原生旋转偏差分层定位_下一阶段测试方案.md)。状态：本轮已执行并归档；首批强制矩阵为部分覆盖（29/36 轮实际采集，1140/1488 个计划目标）。全部结果 `formal_continuous_acceptance=false`。

核心结果：MyAiry 的官方 API 与原生入口短轮一致；三次长轮确认距离的历史姿态候选与输出参考系差异。关闭累积改变原生输出节奏；关闭 Motion BVH 改变姿态和距离候选，但没有恢复当前姿态正确性。结论收紧到原生运动姿态与距离生成相关路径，尚未取得实际历史消费追踪，不能定位具体 SDK 函数，也不能把官方示例资产的动态问题记为已复现。

## 2. 实现

- 独立采集入口继承已验证的单推进者、PRE 写入、实际 POST 状态、24 次静态暖机、10 Hz 源事件相位和固定排空终点；不按几何质量在线选择或丢弃事件。
- A1/A3 用安装版 `Lidar` 包装现有传感器，`LidarSensor` 管理产品并通过 `get_data("generic-model-output")` 取数。保留四 annotator 同事件 Writer 作为来源证明。该对照先标为 API 与产品/annotator 拓扑组合差异，不能直接归因于一个 API 函数。
- 每次 API 轮询先取得自有 CPU 字节，记录读时物理步与单调时间；以 epoch、产品、frameId、timestampNs 确定原生事件。同身份、同完整 SHA 的重复载荷引用已有文件，重复轮询行仍保留。相同身份的声明区完整字节须与 Writer 一致，随后才使用 Writer 的 source/ref 精确关联。
- 独立 GMO 解析器验证 1.0.0 布局、声明长度和分配长度，保留分配尾部；支持 SENSOR/WORLD 与 CARTESIAN/SPHERICAL。球坐标为度、度、米，按右手坐标转为 Cartesian；WORLD 不再乘传感器姿态；本轮仅允许已核验的单位模型变换和零原点。
- 官方 parser 的逐字段对照安排在固定采集结束、清理、保存队列关闭以后，避免在运动回调中增加解析工作。
- 距离、输出方向一致性、世界几何、绝对 yaw 和相邻增量分别报告。输出方向由输出表示推导，不冒充独立观测的实际发射射线方向。
- 数值门槛保持 007 原值；全部结果 `formal_continuous_acceptance=false`。

## 11. 机制结论及证据边界

1. **应用业务链与 API 封装不是当前主要解释。** A0/A1 同资产短轮在完整身份集合配对下没有质量类别或候选差异，径向输出相同；A1 只有短轮证据，不能外推长期稳定性。官方 API 产品/annotator 拓扑差异已记录，因未触发差异，没有增加桥接组。

2. **输出参考系与距离形成必须分开。** 在 6°/s 主轮，WORLD 输出方向与前一步/frameStart 对应，距离却对应报告端点中点；3°/s 和编码输入多数符合该模型，但分别保留 9 个、6 个反例。SENSOR/SPHERICAL 的径向分量保留同一距离候选。因此仅修改世界坐标转换不能解释或消除全部距离异常。

3. **Motion BVH 对原生姿态和距离候选有可重复影响。** C2 的独立完整输出重复确认候选变化，且仍未达到当前姿态距离门槛。有效返回集合差异同时存在；严格逐点配对未通过，E3 结论限于单因素对整组输出行为的约束，不是等价扫描下的质量修复证明。

4. **报告端点更新是更具体的候选边界。** 匀速与非匀速数据检验端点预测；是否存在小旋转更新阈值、精度影响、历史状态构造或查询时间规则，仍需直接追踪。不能把几何候选名称当作实际历史槽位号。

5. **官方资产对照仍有缺口。** A2/A3 静态原始采集、解析和时钟检查成功，但原参数下的名义射线模型不合格。保留噪声和 emitter fire time，未降低门槛；因此不能宣称‘官方示例资产与官方 API 的动态组合也已复现’。

G4 已审阅 68 份安装版接口/契约文件。`Transformation.interpolationFactor` 是调用方构造后传给 `ILidarPCConverter.setTransformation` 的输入，并非读取实时传感器内部权重的接口；SimulationManager 的 31 样本时钟映射也不是 64 槽变换历史。未发现可读取实际消费端点、查询时间及逐射线 origin/direction 的公开入口。没有把新建对象的默认字段冒充内部证据。

下一层应在厂商调试构建或明确的原生诊断接口中关联同一原生事件的：输入 Xform 提交、渲染实例更新、历史端点写入、实际查询时刻/权重、射线 origin/direction 与 GMO 打包时刻；再做构建版本交叉。当前结果支持优先排查 SDK/渲染原生运动状态路径，但不足以裁定具体代码缺陷。
