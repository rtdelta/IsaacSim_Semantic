## 2 必须守住的设计

1. 一个 Isaac GUI 进程拥有实际场景、运动、视口和正式传感器，一个 CPU worker 负责 PNG/CDR/MCAP；不默认另起 Isaac 重放交互快照。
2. 主路线为常驻 RenderProduct/Annotator/Writer 的连续 RT2，同一物理仿真时间组包，正式每次一次渲染完成事件；消除逐组16+2子帧、产品重建和stop/drain。
3. 先探测实际版本与接口。已有环境报告用过6.0.1 rc7，不能仅凭官方文档认定方法及事件行为相同。
4. 首版默认60Hz物理步、10Hz同相位采样；实际读回scanRateBaseHz与tickRate。已有scene18清单为13路10Hz Instant LiDAR，不能擅改扫描模型。
5. 使用实际物理时间和步计数。全部输入经过唯一运动控制器，每物理步积分一次；移除旧墙钟运动时钟及主动暂停原生Timeline行为。
6. 载荷源时间与目标物理步误差<=2ns，并有对应原生事件/渲染引用与位姿证据。该阈值只覆盖转换误差，不允许最近邻、插值或统一平移header。
7. TF、关节、整机和安装数据取自渲染之前生成的不可变实际状态。无法取得可靠源证据的载荷不能保存为正式组。
8. 所选传感器必须全到齐，每路一次，检查时间和位姿后才能交给编码器。借用SDK缓冲不得跨回调交给后台。
9. 默认strict_complete，采样之前预留槽位/credit，过载减速或安全暂停，不静默丢帧。strict_latest必须显式配置，丢整组且完整记账。
10. 仅在首组正式提交前自动选已经验证的continuous或barrier后端。运行中同步失效则失败排空，禁止静默切换。barrier_only不得宣称连续目标完成。
11. 每组写group_commit；MCAP关闭并由独立程序回读验证后，生成含文件hash的manifest与READY。内存release不等于written，更不等于持久化。
12. 单相机、单LiDAR、混合及全组合都要通过；总选择为空报错，未选相机不要求存在/标定。不降低分辨率、改JPEG或删传感器来达成性能指标。

同步保证以002中的传感器模型、误差界限和验收证据为范围。规定运动模型保持明确，不声称接触动力学或真实扫描畸变已验证。

## 4 验证要求

独立验证器必须重新读MCAP，解码ROS消息、PNG和XYZ，核对消息数、提交hash、目标索引、raw源时间、header、TF和实际状态。不能只是读取生产端ok字段。

除内部一致性外，用已知平面与标记检查运动几何，检测一物理步相位偏移。构造非对称变换检查Gf/ROS坐标转换，注入旧载荷、错epoch与旧槽位generation，验证都被拒绝；静止新帧内容相同不能误判过期。

性能与质量按002第16节执行：scene18全组合对未改v06 keepalive基线，至少2倍稳态有效组/墙钟秒为快速采集验收目标。普通无profiler各三轮，预热20组后至少测200组。正常负载引擎控制延迟目标P95<=50ms、P99<=200ms，最大值另列。全组合墙钟实时10Hz是扩展目标，未达不能夸大。

分别报告启动、采集、排空、回读与完整操作耗时。图像质量、同步和完整性通过之后，才能把速度提升解释为可交付数据产能提升。性能不达标时继续定位有证据的瓶颈，最终如实报告未验收项。
