可以实现。建议把 **single0601ContinuousRt 做成独立项目，复用 v06 的控制、数据格式和后台保存逻辑，重新设计采集调度与时间轴管理**。目前只是分析，没有修改代码。

**1. 核心目标**

- 连续播放场景，使用 **RTX Real-Time 2.0** 生成传感器数据。
- 支持任意非空传感器组合，包括“仅一个雷达”和“仅一个相机”。
- 在 Isaac GUI 的三维视口聚焦时，通过键盘控制关节和整机运动。
- 继续保存点云、图像、标定参数、TF、关节状态和仿真时间，并重点验证运动与数据是否对应。

需要区分：**Real-Time 2.0 是渲染模式，连续调度是采集方式，并不保证真实时间下达到指定帧率。** NVIDIA 对应的设置名称是 `RealTimePathTracing`。[官方渲染模式说明](https://docs.isaacsim.omniverse.nvidia.com/latest/reference_material/rendering_modes.html)

**2. 采集链路如何调整**

当前 v06 主要采用：

```text
推进运动 → 固定姿态 → 预热子帧 → 正式渲染 → 等待数据 → 保存 → 下一组
```

新版改成：

```text
键盘／参数／轨迹
        ↓
统一运动控制器，在引擎更新阶段提交姿态
        ↓
Isaac 时间轴持续推进、传感器持续渲染
        ↓
原生 Writer 回调接收已完成的传感器数据
        ↓
匹配该数据对应的时间、TF、关节状态
        ↓
有界队列 → 后台图像编码 → MCAP 写入
```

具体调整：

- 移除每组主动暂停时间轴、固定姿态和重复预热的调度。
- 初始化及大幅修改资产后保留必要预热。
- 采用 Replicator 的播放采集机制和 Writer 回调，避免每组调用冻结式 `step_async`。官方提供 `set_capture_on_play(True)` 与按帧触发接口。[Replicator API](https://docs.omniverse.nvidia.com/kit/docs/omni_replicator/1.12.27/source/extensions/omni.replicator.core/docs/API.html)
- 保留 v06 后台编码和 MCAP 写入，USD、关节控制与引擎调用仍在 Isaac 主线程执行。

**最关键的是同步。** 回调到达时，挖掘机可能已经进入下一姿态，因此不能读取“此刻最新的 TF”配给刚收到的图像或点云。需要保留运动状态历史，根据传感器输出的时间和可取得的帧标识匹配，并用输出携带的渲染位姿进行核验。

连续模式也不能保证获得冻结后多子帧累积的相同画质；可以保持分辨率、标定和现有 RT2 设置，但需要单独检查运动中的清晰度与残影。

**3. 单雷达、单相机如何支持**

本地 v06 当前明确要求“至少一个相机和一个 Instant LiDAR”，需要解除这个限制。

新版统一规定：

| 选择值 | 含义 |
|---|---|
| `None` | 选择该类全部可用传感器 |
| `[]` | 不采集该类传感器 |
| 指定 ID 列表 | 仅采集这些传感器 |

面板提供传感器勾选列表，比填写名称方便。雷达和相机均过滤未激活、未加载的节点；未选中的相机不检查其标定，也不创建对应采集资源。

仅雷达时跳过图像预热和编码；仅相机时允许雷达列表为空。MCAP 保留对应传感器话题及必要的运动状态话题。还需要检查场景原有传感器图是否继续运行，否则“只保存一路”不一定等于“只计算一路”。

**4. 视口键盘控制如何实现**

v06 已有原生键盘订阅和按住按键积分运动的逻辑，可以复用；但当前检查的是整个应用窗口聚焦，需要增加**视口窗口聚焦判断**。

建议操作规则：

- `Play Simulation` 后，点击三维视口即可控制。
- 点击参数输入框、Script Editor 或切到其他窗口，立即清空按键状态。
- Pause、Stop、关闭项目时立即停止键盘运动。
- 按键事件只更新按键状态；运动控制器根据仿真步长计算角度和平移。
- 提供明确的“Keyboard Control”开关，启用时解决与视口导航快捷键的冲突。

技术上使用 `carb.input`、`omni.kit.viewport.utility` 和窗口的 `focused` 状态；仅取得“活动视口”并不能证明它拥有键盘焦点。[视口接口](https://docs.omniverse.nvidia.com/dev-guide/latest/programmer_ref/viewport/get-active-viewport-window.html)、[窗口焦点接口](https://docs.omniverse.nvidia.com/kit/docs/omni.ui/2.25.26/omni.ui/omni.ui.Window.html)

另外，新版必须取消 v06 交互控制器中“发现原生时间轴播放就主动暂停”的逻辑，让面板播放状态和 Isaac 时间轴保持一致。

**5. 实现与验证顺序**

1. 创建独立项目，保留 v06 控制功能及数据契约。
2. 完成可为空的传感器注册表，先验证单雷达、单相机。
3. 接入连续 RT2 调度和统一时间轴。
4. 接入视口键盘控制，再接后台保存。
5. 在 combine scene 18 下，测试静止、连续运动、暂停恢复和重复录制。

日志重点记录：**按键收到至姿态提交的延迟、传感器采集时间、回调延迟、位姿匹配结果、队列深度、编码及写盘耗时、缺帧与重复帧**。

这条路线有望减少反复冻结、预热和等待造成的停顿，单传感器采集也能减少负担。但传感器渲染和数据回读仍可能阻塞引擎，是否达到流畅键盘控制，需要实际测量，不能仅凭采用连续调度就认定解决。
