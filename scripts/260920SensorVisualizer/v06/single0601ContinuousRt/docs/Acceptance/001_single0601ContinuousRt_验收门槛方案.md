“当前版本”指`v06/single0601ContinuousRt`独立项目；原v06的门槛另见[002_v06验收门槛方案](002_v06_验收门槛方案.md)。本文件整理[002实现契约](../ImpPlan/002_single0601ContinuousRt_快速同步采集实现方案.md)、[003任务书](../ImpPlan/003_single0601ContinuousRt_Agent执行任务书.md)和[004连续修复方案](../ImpPlan/004_single0601ContinuousRt_连续主路线修复与流水线实现方案.md)，不放宽原有要求。

## 1 适用范围与结论等级

正式目标为scene18、60Hz物理与loop、10Hz同相位采样，支持单相机、单LiDAR、1+1及4相机+13LiDAR。相机1920×1080、无损PNG；LiDAR保留原Instant、scan、范围和噪声参数。使用一个Isaac GUI拥有实际场景、运动及采集，一个CPU记录进程负责编码/CDR/MCAP。

| 结论 | 必须满足 | 不能据此推导 |
|---|---|---|
| 诊断采样完成 | 原始事件、参数、错误及清理证据可追溯 | 正式连续数据合格 |
| 数据段可交付 | 段关闭、独立回读、同步及文件完整性通过；按相应完成类别发布 | 请求完整或项目性能通过 |
| `strict_complete`请求完成 | requested=scheduled=validated=written=readback_verified，缺口为0 | 主路线连续能力或质量/性能通过 |
| `barrier_only` | 屏障后备独立通过其同步与输出验收 | `continuous_ok=true` |
| 主方案完整交付 | 七项结果全部true，且有连续后端的独立回读READY数据 | 无证据的其他SDK/配置/传感器也通过 |

`strict_latest`只可发布明确记账的整组缺口数据，`completeness_ok=false`，不参加默认完整采样通过判定。Stop/失败前缀保留原请求数；前缀导出不得改写原会话为完成。

当前运行器对`strict_latest`返回`policy_unverified`；以上为后续实现后的验收要求，不表示该策略现已可用于正式录制。

## 2 门槛总表

| 编号 | 门槛 | 通过条件 | 未通过处理 |
|---|---|---|---|
| G0 | 版本、资产与配置 | 实际SDK/GPU/驱动、依赖、有效设置、源码/资产SHA和非空传感器集合完整；预算明确 | 不启动正式录制 |
| G1 | 原生事件与数据所有权 | 同一有效完成事件绑定载荷、原生引用、源时间及位姿；有效窗口内取得独立CPU数据 | 拒绝该事件及相应完整组 |
| G2 | 精确物理时间 | 各路源时间与目标实际物理步差≤2ns；同频同相位；实际状态在渲染前固定 | 连续能力unsupported，不用时间平移补救 |
| G3 | 原生位姿及独立几何 | 平移≤1mm、旋转测地角≤1e-4rad；独立几何门槛同时通过 | 保留失败证据，不进入正式连续闭环 |
| G4 | 全路完整组与MCAP | 所选每路一次；状态/TF/标定归属正确；逐组commit及独立解码回读通过 | 无完整READY；保留失败/停止类别 |
| G5 | 有界在途与故障 | 预留资源后才采样；槽位、历史、编码credit有界；旧回调/ACK及故障均按契约处理 | 不扩大窗口，不静默丢组或切换后端 |
| G6 | 控制与生命周期 | 原生焦点、参数、轨迹、暂停恢复、Reset及安装revision通过；20轮×至少10组 | interaction/lifecycle保持false或null |
| G7 | 质量 | 正式scene18重点场景及受控基线对照通过 | 不把速度当作合格产能 |

| G9 | 长期运行 | 至少30分钟墙钟全组合strict_complete；全部输出回读；资源未超预先锁定预算 | 不宣称长期有界或完整交付 |

G0–G4先通过，才进入G5并发优化；同步、完整性、质量先通过，才认定G8速度提升为合格数据产能。

## 3 时间、位姿与几何的具体检查

### 3.1 时间与状态

- 组主键为`(recording_id, epoch_id, target_step)`；各路原生引用按自己的作用域检查，不要求不同产品frameId数值相等。
- 使用实际物理步及仿真时间，按理数目标网格采样；不按回调到达顺序、墙钟或Timeline显示时间猜测目标步。
- 实际root、关节、安装及传感器状态在渲染前保存为不可变历史；command与actual分开。回调中读取最新USD不能代替历史。
- 源时间差≤2ns为数值转换容差，不能用于最近邻配对、状态插值或旧载荷统一改header。
- GMO主timestamp、frameStart/frameEnd、点offset分别保留真实来源及单位，说明时间锚点和坐标基准。`frameEnd`数值接近目标时间、点offset全0或`instantLidar=true`，均不足以单独证明单时刻语义。
- 有效新事件可产生相同RGB/XYZ字节；新鲜度不能只由内容hash判定。

### 3.2 原生位姿与独立几何

| 指标 | 门槛 | 统计/证据口径 |
|---|---:|---|
| 原生渲染位姿平移误差 | 每个有效样本≤1e-3m | 对实际历史传感器位置的欧氏距离 |
| 原生渲染位姿旋转误差 | 每个有效样本≤1e-4rad | 合法旋转矩阵/四元数的测地角；坐标转换独立验证 |
| 理想诊断图像重投影 | P95≤1px | 固定规则提取的标记/特征；报告有效、拒绝样本和覆盖区域 |
| 理想无噪声点到面 | 每个诊断目标组P95≤5mm | 已知几何、完整自有XYZ、actual状态；同时列最大组P95 |
| 独立几何估计的有效旋转残差 | 可观测目标组≤1e-4rad | 本次补充门槛，沿用位姿角度上限；估计方法、有效方向和不确定性预先固定 |

最后一项用于防止“元数据对齐，但点云输出坐标仍错位”漏检。当前水平平面yaw拟合只约束可观测的水平旋转，不代替完整三维位姿或全部射线时刻验证；点云错位仍需区分追踪位姿与输出坐标变换的问题。

采用非对称标记和至少三组独立法向几何，覆盖静止、平移、低速/高速旋转、混合、方向反转、启停、非匀速、关节运动和遮挡显露。独立分析不依赖生产端“ok”字段。真实前一物理步作为负对照，并选择能使一步偏移明显超过门槛的轨迹。

理想诊断的曝光/噪声覆盖明确登记；正式scene18仍保留原噪声。不能把无噪声房间通过等同于正式场景质量通过，不能用actual矩阵覆盖错误原生矩阵或旋转点云后自证通过。

## 4 最低测试矩阵

| 用例 | 最低规模 | 必需检查 |
|---|---|---|
| 最小单LiDAR机制诊断 | 静止、纯平移、纯旋转、混合各40有效事件；各3次独立初始化 | 原生字段、所有权、阶段、几何；覆盖3°/s低速及10°/s对照 |
| 非匀速及暂停恢复诊断 | 每模式至少40有效事件 | 符合目标时间与状态，恢复首个有效载荷正确；只证明物理时钟冻结不足以通过 |
| 单相机正式连续 | 静止、运动各至少200组 | PNG/标定/TF、原生源证据、首尾组及独立回读 |
| 单LiDAR正式连续 | 至少200组 | XYZ、源事件、坐标和单时刻语义、几何 |
| 1相机+1LiDAR正式连续 | 至少200组 | 共同网格、全路到齐、实际状态一致 |
| 全4相机+13LiDAR正式连续 | 至少100组 | 所有模型/安装类型、完整状态话题及回读 |
| 同GUI重复录制 | 至少20轮，每轮至少10组 | 清理计数、epoch/revision、暂停/停止/Reset/安装切段 |
| 全组合长测 | 至少30分钟墙钟 | strict_complete、全部回读、RAM/VRAM/FD/线程及资源趋势 |

单路还需覆盖不同传感器模型与安装类型，不能由MyAiry_front或一台相机外推全组合。每次正式会话重新验证实际所选集合；初期只允许一组在途，扩大到2/3组必须另有提前量、完成边界和资源证明。

## 5 数据输出与故障门槛

独立ROS/MCAP读取器重新解码CDR、PNG、XYZ，重算raw/encoded/CDR及文件SHA，检查源时间、header、Clock、TF、root、JointState、标定、target索引、epoch和安装revision。

每组普通消息`3*C+L+5`条，加commit为`3*C+L+6`条；全组合为30条普通消息加1条commit。段首另有2条元数据。以实际选择集核算，不能要求单传感器输出包含未选话题。

MCAP关闭并独立验证后才发布manifest与READY，READY对应manifest实际字节SHA。`release`、`written`、`segment_closed`、回读通过与READY分别记录。合法无返回场景的空点云、静止同字节帧不因内容相同被误拒。

故障矩阵至少包含：延迟、乱序、重复与冲突重复、旧帧、错时间、错epoch、缺路、慢编码/写盘、worker退出、ENOSPC、旧release/written、槽位generation复用、超槽点数、历史容量耗尽和在途暂停。合法乱序/重复按预定规则处理；错误身份、时间、位姿及内存所有权不合格必须拒绝。失败不能发布完整READY或把前缀改为已完成请求。

组deadline默认5秒，全组合必要时明确配置15秒等值；它是故障检测界限，不是10Hz墙钟性能指标。512MiB是当前录制credit配置，不代表整个Kit/worker/RAM/VRAM预算；整进程和长测预算必须在对应验收前另行锁定。

## 6 质量与性能门槛

正式质量固定抽样覆盖铲齿、细杆、鱼眼边缘、遮挡显露、快速旋转和恢复首帧，并记录标定、原始参数、ROI、特征方法及结果。PSNR/SSIM可辅助报告，不能用某一张图片或单一分数替代几何和运动质量。

目前没有来自原002的统一PSNR/SSIM通过阈值。需要这类量化阈值时，应以受控参考和重复性试验预先锁定；阈值未定、专项未做或覆盖不足，`quality_ok=null`，不得事后依据候选结果放宽。

速度基线固定为未改v06、scene18全组合、`persistent_gated+keepalive`、16相机预热子帧+2正式子帧。候选为已经通过上述连续正确性门槛的实现，正式每目标一次完成事件，无逐组16+2预热、产品重建或stop/drain。

两边各3轮，共6轮交错；每轮先排除20组预热，再测至少200组。同单卡、SDK、资产依赖、轨迹及实际采样状态、标定、PNG、可见GUI/视口与控制/预览负载；原v06的独立采集进程和当前版单Owner架构按实值记录，不伪装成相同进程拓扑。仅采集与含交互负载的比较分别出表，不混用headless与GUI结果。

| 指标 | 定义与通过规则 |
|---|---|
| 稳态合格吞吐 | 稳态written且最终回读合格组数/对应采集墙钟秒 |
| 全操作合格吞吐 | readback_verified组数/启动、加载、采集、排空和验证的总墙钟秒 |
| 必需速度目标 | 三轮候选稳态吞吐中位数/三轮v06基线中位数≥2；逐轮值同时保留 |
| 引擎控制目标 | 正常负载accepted-to-actual-applied P95≤50ms、P99≤200ms，最大值单列；不能用按键状态回执替代姿态应用 |
| 扩展目标 | 全组合RTF≥1，且实际合格输出约10组/墙钟秒；未达不宣称墙钟实时10Hz |

同实例monotonic计性能，物理仿真时间计采样，UTC仅作记录。分位数方法和正常/过载样本范围预先固定；建议本次统一nearest-rank，原工具其他统计口径须同时标明。普通性能轮关闭profiler和高频诊断；阶段时间存在重叠，不能直接相加成总墙钟。

旧v06格式的只读baseline_adapter及同条件运行驱动仍需验证；现有`compare_performance.py`不能直接把旧writer报告当作新schema验证。允许生成有来源映射的外部比较报告，不为旧MCAP伪造新commit、原生事件或READY。
