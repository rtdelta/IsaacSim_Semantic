# v02 实施与验收记录

日期：2026-09-23。目标环境：现有 Isaac Sim 6.0.1-rc.7、ROS 2 Jazzy、L40。所有实际验证使用本任务独立的 Kit；已有用户 GUI 保留。没有安装、升级依赖或修改桌面环境。

## 已实现

- 独立入口、运行包、旧运动组件副本；不导入父目录 v01。临时 USD 修改只在 Session 层。
- 唯一场景控制协程：推进规定运动 → 暂停 → 固定时间渲染 → 全部传感器新结果检查 → 独立数据快照 → 后台录制。
- 三种关节／Pitch／Roll 控制，整机 XYZ／Yaw／速度，固定 cab-track；安装调整审计、显式保存、结束恢复。
- 交互模式最多 0.1 倍速，离线解除墙钟限速。离线仍保留仿真秒和采样率的含义。
- 三个有界 mmap 槽、本地 UNIX socket、四线程 PNG 编码、单一 rosbag2 MCAP writer。Isaac 不同步编码／写 PNG；后台处理可以和下一组采样重叠。
- MCAP 包含全部点云、四路畸变鱼眼图像、标定、相机位姿、TF、时钟、关节状态、组索引和任务元数据。点云沿用旧 XYZ / FLOAT32 / 12 字节契约。
- 组边界暂停、恢复、修改安装、停止并排空，分段、回读校验、阶段耗时和进程／整卡 GPU 采样。
- 若 RTX 返回旧源时间或旧位姿，保持场景和时钟不动，最多重渲染三次；仍不一致则失败，保留已写完整组，不改写旧数据时间戳冒充新结果。

## 实测证据

1. 已知几何体探针：在 MyAiry_front 局部放置临时 1 m 立方体，初始命中约 7084 点；整机移动 0.25 m、旋转 10° 后约 2094 点，面距离误差小于 3 cm，传感器渲染矩阵与 USD 一致。探针只存在于测试 Session 层。
2. 全传感器运动验收：`20260923_160636_404362_2e36a05245`，12 组、48 张图像、6,787,146 点、每组 30 个话题、三个 MCAP 分段。ROS 回读验证了 CDR 哈希、组完整性、共同时间、冻结时钟、图像解码、点格式及 TF 合成。测试涵盖直接关节角、目标角加角速度控制、周期运动、整机倾斜和位移。
3. 面板验收：`20260923_161429_085946_feeaf4307d`，5 组、5 张图像、244,045 点。实际创建 omni.ui 面板，测试关节 Apply、安装位置调整／保存／复位、Save Job、暂停时钟、恢复、Stop + Drain、启用 ROS 发布。该 MCAP 也通过回读。此项未替用户在可见桌面中逐项鼠标点选 RViz。
4. 六项本地测试通过：整数采样时钟、非法速率、破碎 socket 数据流、mmap 生命周期及边界、TF／光学坐标、三种运动控制。
5. 最终画质配置全传感器验收：`20260923_161934_678611_6ec2f24850`，3 组、12 张图像、1,696,639 点、两个 MCAP 分段；同样通过全部回读检查。相机 16 子帧单独预热时暂时禁用本任务 LiDAR 产品，之后重新启用并等待实际新源时间和新位姿通过验证，才保存完整组。
6. 最终面板回归：`20260923_162544_588654_567467251b`，5 组正常结束；额外验证了来自控制器实际状态的周期运动能被 Save Job 保存，避免只保存界面草稿而遗漏已加载／事件启动的运动。

本地证据在 `reports/`；远端会话内有 `validation_report.json`、`writer_report.json`、`performance/`。测试组数有限，不代表长时间生产运行的稳定性认证。

## 性能结论

12 组全传感器测试的前版配置为 Quality DLSS、2 个共同采集子帧，未启用额外相机预热：采集耗时 130.03 秒，约 10.84 秒／组。四路图像编码及消息准备平均 0.313 秒／组，写入平均 0.0386 秒／组；推进合计 47.25 秒，渲染合计 76.12 秒，读回检查平均 0.0327 秒／组。

后台编码已不占 Isaac 主线程，队列未成为瓶颈；整体吞吐没有达到原先设想的高速目标。旧版约 2.614 秒／组的编码数据可作方向性对照，但图像内容、压缩参数和整组同步条件不同，不能作为公平的总体倍数提升。

原生 `SimulationManager.step` 曾将推进阶段缩短，但 RTX 图时钟出现约 3.125 ms 偏差，未采用。正式路径使用已通过源时钟校验的 Kit 固定步推进。不能通过增加 Python 渲染线程来修复这一原生同步问题。

最终画质配置三组耗时 48.63 秒，约 16.21 秒／组，文件约 47.8 MB；这明确是更高渲染收敛度的取舍。`config/throughput.json` 可切换到不额外预热相机的配置。没有把“离线不限速”描述为“保证快于旧版”。

本次整卡 GPU 值受已有 GUI 影响，不用于宣称 v02 独占利用率。多 GPU 分片、多 Kit 并发、原生 GPU 编码均未实施。

## 3DGS 画质

实际是 `RealTimePathTracing`（RTX Real-Time 2.0 路径），原生 OpenCV fisheye，1920×1080；保存无损 PNG。USD 原生镜头定义是标定依据；该版本 `CameraParams.cameraModel` 的旧字段仍返回 pinhole，不能用这个字段否定鱼眼投影。

固定同一时刻、同一姿态，对比 Performance/2 子帧和 Quality/2、8、16 子帧，全部源时间保持 0.133333333 s。16 子帧中护栏文字、地面和铲斗细节明显改善。梯度值并非单调，不能将它当作无参考清晰度评分。

USD 加载计数为零、六个 Gaussian Splat prim 存在，但这本身不能证明 GPU 资源全部驻留。本次视觉证据支持渲染历史／收敛不足是模糊的一个原因；没有证据证明所有模糊都是加载延迟，也不排除素材、视角和高斯重建本身的限制。原始对照 PNG 在远端 `v02/reports/quality/`，本地 `reports/quality_center_crops.jpg` 是有损预览。

## 警告与原生限制

没有屏蔽整类 warning。已解决本项目 Writer 版本、图像直接 host-copy 路径、可选 LiDAR 原生指针读取和过渡旧帧录制问题。

| 警告 | 实际证据与处理 |
|---|---|
| hydratexture interface already released | 全传感器测试重复 206 次，约随产品数和组数增长；属于当前原生产品生命周期路径，尚未消除。该次完整数据仍通过检查，不能据此宣称所有影响都排除。 |
| MotionBVH disabled | 保留现有设置；只接受 Instant 且采样期间完全冻结，几何探针已通过。没有宣称支持连续运动畸变。 |
| `channels` / VtArray string | 定位到 `/Render/Vars/GenericModelOutput` 的 `[BASIC]`，不是 3DGS 纹理文件。XYZ 提取已通过；未改装引擎。 |
| robot_motion.schema 模板占位路径、anim.graph 注册、Fabric 接口版本 | 已安装 RC 环境启动警告；本项目不依赖运动规划／动画图节点，不对安装目录打补丁。关节使用 Articulation tensor 路径。 |
| PhysX tensor view invalidated | 出现在临时层清理／测试结束阶段；未在继续采集时复用失效 view。 |
| 音频、Cache Server、PerfSDK | 无界面环境启动项；不为采集安装音频或缓存服务。 |

## 操作范围与外联记录

项目代码通过已有 SSH 凭据引用和主机校验传输，执行留有本地审计。父项目不覆盖；v02 自身修订前副本在 `deploy_history/`。未新下载外部依赖、模型或纹理。

本地 13 个原始组件与任务开始复制时的字节哈希一致。远端旧源码与本地有历史 CRLF/LF 差异，规范化换行后 13 个组件一致；初始远端探针中四个文件的原始哈希另行复核，避免把换行差异误判为此次修改。根场景 hash 在几轮测试前后一致。

早期独立探针原生崩溃时，Isaac 默认崩溃报告器曾尝试向 `https://services.nvidia.com/submit` 上报；是否上传成功未知，已向用户说明并登记。后续 v02 启动器显式关闭该进程自动崩溃上报、扩展注册表下载、HTTP 服务和匿名遥测；不代表整台实例的网络隔离。公开 NVIDIA 文档阅读另有自报访问记录。
