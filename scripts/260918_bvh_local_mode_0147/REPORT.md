# Gaussian 局部普通 BVH 与场景 Motion BVH：执行结果

2026-09-18。远端：`/root/gpufree-data/diagnostics/bvh_local_mode_20260918_0147`。
本轮完成 54 次独立进程尝试，其中 48 次有效采集、6 次准备失败。旧文件保护清单中的 1,187 个文件前后 SHA256 一致；所有本轮 Isaac/GDB 进程已退出。

## 核心结论

**当前版本中，Gaussian 的普通局部 BVH 可以参与仍开启 Motion BVH 的场景查询。原来的失败有一个已验证的直接原因：Gaussian 构建函数收到运动模式参数后主动退出。**

本轮只在新进程的函数入口把 Gaussian 的 mode 参数从 1 改为 0，保留全局设置和实际引擎的 Motion 标志。随后普通构建命令被调用，相机恢复 Gaussian 图像，NZ3 恢复 Gaussian 返回。这比“接口不兼容”进一步：建立了参数、资源槽、原生构建调用、输出之间的因果联系。

这是**二进制与运行时机制分析**，没有取得 NVIDIA 的原始实现源码或 GPU 查询着色器源码。干预是限定版本、限定进程的诊断手段；没有改安装库或业务配置，也没有把它作为生产修复部署。

## 1. 实际改变了什么

仅对已校验的 Gaussian 对象，在 `buildTlas` 入口把寄存器 `ecx` 中的模式实参 1 改为 0，再读取确认。没有修改其他函数实参、对象内容或磁盘二进制。

以下证据来自同一个对象的关联跟踪：

| 环节 | 原始 Motion ON | Motion ON + 局部干预 |
|---|---|---|
| 实际 RTX 引擎创建标志 | Motion 开启 | Motion 仍开启 |
| Gaussian 初始化描述中的模式 | 0 | 0 |
| 初始化后的普通 TLAS / scratch 槽 | 非空 | 非空 |
| 初始化后的运动 TLAS / scratch 槽 | 空 | 空 |
| 调度任务保留的模式 | 1 | 1 |
| Gaussian 构建入口实际使用的模式 | 1 | 0，由 1 改写 |
| 普通构建命令调用及返回 | 未经过 | 经过 |
| Gaussian 相机图像 / NZ3 返回 | 消失 | 恢复 |

普通构建的实际调用目标属于 `libcarb.graphics-vulkan.plugin.so`。CPU 函数返回本身不代表 GPU 完成；恢复的图像和点云补上了下游输出证据。仍未直接解析着色器绑定表和 GPU 遍历指令。

可以将已观察的机制概括为：

```text
场景运动标志 = 1
    ↓
构建任务携带 mode = 1
    ↓
Gaussian 初始化的已观察路径使用普通资源 mode = 0
    ↓
Gaussian buildTlas 收到 mode = 1，检查后退出
    ↓
该 Gaussian 构建未完成，图像与雷达中的 Gaussian 贡献消失

干预：仅将 Gaussian buildTlas 的实参 1 → 0
    ↓
普通构建执行；全局引擎仍为 Motion ON
    ↓
图像与 NZ3 返回恢复
```

因此，目前可以把直接障碍定位到**构建模式分派与 Gaussian 已支持路径之间的边界**。还不能据此断定这只是一个可安全删除的检查，或推断 NVIDIA 加上检查的完整设计动机。

## 2. 静态对照与重复性

几何为同一真实牙齿 Gaussian，只读引用后在新根层中归一化、放置；背景为内壁约 ±10 m 的 Mesh 房间。相机和 LiDAR 分进程测试，相机组没有活动 LiDAR，LiDAR 组只有一个 RenderProduct，均无活动视口。

| 组 | 场景 Motion | Gaussian 局部干预 | 相机目标 | NZ3 每完整输出中 0–8 m 有效返回 |
|---|---:|---|---|---:|
| A | 关闭 | 无 | 可见 | 658–715 |
| B | 开启 | 无 | 消失 | 0 |
| C | 开启 | 1→0 | 恢复 | 667–731 |
| D | 关闭 | hook 开启但不改参数 | 可见 | 658–715 |
| E | 开启 | 仅 Mesh，无干预 | 无 Gaussian | 0 |
| F | 开启 | 仅 Mesh，Gaussian hook 零命中 | 无 Gaussian | 0 |

A、C 的相机与 NZ3 均补到三次独立启动。每次预热 60 次、采集 120 次更新。NZ3 每组记录 120 个完整输出缓冲区，涉及 21 个不同 `timestampNs`；**不能把它们写成 120 次独立物理扫描**。

有效返回同时检查有限 XYZ 与 flags 的有效位。静态组背景距离至少约 10 m，移除 Gaussian 后 8 m 内返回为零，因而此处近距离统计能隔离 Gaussian 的贡献。这个距离阈值**没有被用作传感器移动后的统一 Gaussian 标签**。

具体重复性：

- A 三次启动：按输出更新、发射器、tick 和回波匹配，XYZ 与射线键逐位一致。
- C 三次启动：同样逐位一致。
- A 与 D 的 NZ3 输出一致；E 与 F 一致，支持 hook 没有污染对应控制组。
- A 与 C 并非逐射线一致。共同近处返回的绝对距离差 P95 为 2.779 m。
- 但 A 自身相邻输出的同类差异 P95 为 2.820 m，C 自身为 2.838 m。两组汇总近处距离的经验分布最大 CDF 差约 0.00454。

最后两项说明：**不能把 A/C 的逐射线差值直接叫作新增几何误差。** 固定场景仍存在随输出更新变化的返回序列；它与采样序列变化相容，但没有 GPU 源码证据证明具体随机机制。汇总分布接近也不足以证明统计等价或真实雷达精度。

强度使用当前安装版本的 `GenericModelOutput.scalar`，安装内 LiDAR 测试代码将其作为 intensity 检查；保留原始 scalar，不宣称它经过真实红外回波标定。首轮 v2 没有保存该字段，r2/r3 补齐；没有补造旧数据。

## 3. 运动测试验证到哪一步

运动采用 PhysX 刚体速度 ±2 m/s、固定步长 1/60 s，记录每次更新的 timeline、physics time 和实际世界变换。使用 8 通道 ROTARY、10 Hz 扫描、1000 Hz firing，逐射线 offset 覆盖 0–99 ms。测量窗约 1 s，每组 10 个完整扫描。

本轮配置保留 multi-tick 与 per-sensor TLAS 为关闭，避免把这两个因素与局部构建干预同时改变。

### Mesh 时间与干预范围

真值由**本次记录的位姿历史**在射线时间上插值得到，再与 ±10 m 平面的解析交点比较；没有沿用旧实验的固定时钟偏移，也没有通过拟合点云来校准位置。

| 场景 | XYZ 误差 P95 |
|---|---:|
| 静态 Mesh，Motion OFF / ON | 约 0.0050 mm |
| 传感器 2 m/s，Motion OFF | 32.503 mm |
| 传感器 2 m/s，Motion ON | 0.840 mm |

本次初始化中 physics time 比 timeline 提前约 33.3 ms，这由实际记录观察到。直接使用 `速度 × timestamp` 会引入约 6.7 cm 的假误差，因此最终分析用实测位姿历史。ON 仍有约 0.84 mm P95 残差，没有宣称达到此前不同配置中的 0.0041 mm。

加入 Gaussian 并实施局部干预后，背向 Gaussian 的半空间中，3,920 个匹配 Mesh 返回与没有 Gaussian 的对应 Motion ON 测试逐位一致。结合实际引擎标志，可确认此次干预没有取消场景中 Mesh 的运动处理。

### Gaussian 外层平移的一致性

同一模式内比较，以控制已经观察到的模式相关返回序列差异：

- Gaussian 与传感器同步平移，相对位姿保持不变：共同近处返回与静态对应组一致；OFF 匹配 126 点，ON 匹配 117 点。
- 传感器 +2 m/s 与 Gaussian −2 m/s：相同相对运动的共同近处返回一致；OFF 匹配 278 点，ON 匹配 280 点。
- Gaussian 本地构建入口在这些刚体运动 case 中仍只命中一次，输出却随外层平移变化。

这些结果支持“Gaussian 的局部结构可以保持普通构建，外层变换另行影响查询”的解释。它们没有单独证明外层变换由哪一个具体 TLAS、着色器或插值函数实现。

### 冻结参考与敏感性限制

对 0.401 s、0.801 s 的代表射线，将同一 Gaussian / 传感器冻结在记录位姿对应的位置，保持相同模式、发射器、方向、tick、时间戳与输出更新索引。

每个模式与运动类型计划检查 16 条发射射线。只在两边均有返回且距离小于 7 m 的代表目标返回中比较：传感器移动每个模式 9 点，Gaussian 移动每个模式 2 点，差值均为零。逐射线结果保存两边返回的并集；两边均无返回的数量由已知发射列表核对，背景返回不算目标命中。

**不能把这些零差异当成运动插值已获认证。** 故意将冻结位姿错开一帧（约 33.3 mm）后：

- 0.401 s 的 4 个传感器运动目标返回仍全部不变。
- 0.801 s 的 5 个目标返回中出现变化，最大约 0.682 m。
- Gaussian 运动的 2 个目标返回仍不变。
- 更大的 0.5 m 位姿错误会使部分返回发生明显变化。

这说明当前有限射线上的输出对小位移存在不敏感或跳变现象，尚不能提供稳定的毫米级时序判据。**Gaussian 运动精度保持“证据不足”**，没有测试旋转、内部中心/尺度形变，也没有做生产稳定性认证。下一项有价值的工作是先建立对小位移敏感、可控制采样的 Gaussian 查询参考，再深入其距离生成与时间传递实现。

## 4. 对最初问题的回答

- 为什么原项目关闭 Motion BVH 才能看到 Gaussian 返回：本版本的共享场景构建路径把运动模式传给 Gaussian 构建函数，后者在该模式下提前退出。
- 是不是 NZ3 本身必须关闭：不是本次消失现象的必要原因。无 LiDAR 的相机也复现；保留全局 Motion 并仅改 Gaussian 局部构建参数，NZ3 Instant 返回恢复。
- 是不是 3DGS 数据转 USD 损坏：同一只读资产在 A/C 都有输出，不能用资产损坏解释本次 B 的变化。
- 普通 Gaussian BVH 是否绝对不能与 Motion BVH 共存：该绝对判断被本次静态共存实验否定。
- 是否已经读懂闭源底层、可以直接修项目：尚未。已定位并干预原生构建路径；GPU 查询着色器、距离生成机制、完整运动语义和厂商设计原因仍未确定。
