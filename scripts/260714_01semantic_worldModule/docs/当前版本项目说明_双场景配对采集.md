# 260714_01semantic_worldModule 当前版本项目说明

## 1. 项目目标

本项目是一个独立运行的 Isaac Sim 语义数据采集项目，用于：

1. 按固定物理时间步驱动四关节挖掘机。
2. 使用指定 USD Camera 采集 RGB 和语义分割数据。
3. 保证图像帧、物理时间、关节状态和相机状态严格同步。
4. 对同一个仿真帧生成两套配对结果：
   - 完整场景：正常保留地面、土体、环境和挖掘机。
   - 仅挖掘机：隐藏配置白名单之外的可见 Prim，重新渲染挖掘机。

第二套结果不是从第一张完整场景图像中抠图。它会在保持同一个物理状态的条件下，让地面、土体等背景几何体不再参与第二次光线求交和语义计算。因此，被土体遮挡但实际存在的斗齿网格可以在第二次渲染中重新显现。

## 2. 当前版本的数据协议

当前版本包含四个主要协议版本：

| 协议 | 当前版本 | 作用 |
|---|---:|---|
| 业务启动配置 | schema 2 | 定义 Stage、Camera、运动、渲染参数、四个输出目录和第二次渲染开关 |
| Prim 白名单配置 | schema 1 | 定义仅挖掘机渲染时保留的 Prim 子树 |
| 运行清单 `run_config.json` | schema 5 | 记录实际运行参数、可见性报告、Writer 统计和任务状态 |
| Writer | 3.0.0 | 写出双版本 RGB、语义数组、语义彩图和元数据 |

当前远端验证环境为 Isaac Sim `6.0.1-rc.7`。

## 3. 项目目录与模块职责

### 3.1 顶层调度

`simulation_orchestrator.py`

- 读取唯一的业务参数 `--config`。
- 创建和关闭 `SimulationApp`。
- 打开 USD Stage 并执行预检。
- 初始化物理世界、Articulation、相机和 Writer。
- 按固定时间步推进仿真。
- 在每个采集帧内编排完整场景和仅挖掘机两次采集。
- 写出 `run_config.json` 和 `motion_state.jsonl`。

### 3.2 业务参数

`capture_launch_config.py`

- 严格加载 schema 2 业务 JSON。
- 拒绝未知字段、缺失字段和错误类型。
- 解析所有相对路径。
- 校验四个业务输出目录互不重复、互不嵌套。
- 控制仅挖掘机第二次渲染是否启用。

`isolated_render_config.py`

- 加载独立的 Prim 白名单 JSON。
- 要求每个值都是绝对 USD Prim Path。
- 拒绝重复路径和已经被父路径覆盖的冗余子路径。

### 3.3 物理世界与运动

`world_scheduler.py`

- 配置固定物理频率。
- 负责 Timeline 的启动、暂停和恢复。
- 精确推进指定数量的物理步。
- 在渲染期间冻结世界。
- 校验渲染前后物理步、数据集时间和 Timeline 时间没有变化。

`excavator_joint_motion.py`

- 读取 CSV 四关节轨迹。
- 在物理步之前向 Articulation 写入目标位置。
- 在物理步之后读取实际关节位置。
- 记录命令值、实际值和误差。

`joint_control_profile.py`

- 定义四关节逻辑顺序：
  - `cab`
  - `boom`
  - `small_arm`
  - `bucket`
- 定义关节名称、限制、角度单位和允许的回读误差。

`articulation_adapter.py`

- 将逻辑关节名称绑定到实际 DOF 索引。
- 进行角度和弧度转换。
- 执行批量四关节读写。

`articulation_stage_validator.py`

- 检查 Articulation Root、固定基座和关节链。
- 检查刚体、质量、惯量、关节限制和控制模式。

### 3.4 相机与图像采集

`semantic_capture_custom.py`

- 创建一个持续存在的 Camera RenderProduct。
- 完成渲染预热。
- 挂载自定义 Writer。
- 使用 `delta_time=0.0` 执行冻结世界下的渲染。
- 在场景可见性改变后更新 RTX external frame counter，重置时序或路径追踪历史。

`capture_context.py`

- 定义一个采集请求对应的权威帧状态。
- `CaptureVariant` 包含：
  - `full_scene`
  - `excavator_only`
- 同一 `frame_id` 可以分别完成两个 variant。
- Writer Ledger 使用 `(frame_id, variant)` 作为唯一键，防止串帧和重复回调。

`semantic_dataset_writer.py`

- 使用 `rgb` Annotator 读取 RGB。
- 使用 `semantic_segmentation` Annotator 读取运行时语义 ID。
- 在启用仅挖掘机采集时使用 `distance_to_camera` Annotator。
- 根据语义 mapping 将运行时 ID 转换为稳定的数据集 ID。
- 根据 variant 将结果路由到不同业务目录。
- 仅挖掘机 PNG 的透明 Alpha 来自第二次渲染自身的深度缓冲，不来自完整场景图像。

### 3.5 场景隔离

`scene_visibility_controller.py`

- 在 Stage Session Layer 下创建匿名 visibility Layer。
- 匿名 Layer 在整个任务期间保持挂载，避免 Hydra 持有已经销毁的 Layer 引用。
- 仅在第二次渲染前向该 Layer 写入临时 `visibility=invisible`。
- 第二次渲染结束后清除临时 visibility opinion。
- 不调用 `SetActive(false)`，不会卸载物理对象、Payload 或 Articulation。
- 不修改、不保存源 USD。
- 自动保护采集 Camera 及其父级依赖。
- 白名单内 Prim 及全部后代保留原有可见性。

### 3.6 语义映射与校验

`semantic_mapping.py`

- 读取数据集语义 schema。
- 将 Isaac Sim 每次运行可能变化的 runtime ID 转换为稳定 dataset ID。
- 生成固定颜色的语义 PNG。

`validate_semantic_output.py`

- 检查运行清单状态必须为 `complete`。
- 检查 Writer 没有未完成的 CaptureContext。
- 检查每个启用 variant 的帧数。
- 检查 RGB 分辨率。
- 检查语义 ID 数组的数据类型、形状和有效 ID。
- 检查语义彩图是否与语义 ID 数组完全一致。
- 检查双版本 metadata、receipt、物理时间和帧编号。
- 检查运动帧的四关节状态。

### 4.1 关闭第二次渲染

```json
{
  "excavator_only_capture": {
    "enabled": false,
    "render_prim_paths_config": null
  }
}
```

关闭后：

- 每帧只执行完整场景采集。
- 不加载 Prim 白名单文件。
- 不创建仅挖掘机图像。
- Writer 完成数量等于业务帧数。

### 4.2 开启第二次渲染

```json
{
  "excavator_only_capture": {
    "enabled": true,
    "render_prim_paths_config": "excavator_only_render_prims.json"
  }
}
```

开启后：

- Prim 配置文件必须存在且合法。
- 每个业务帧执行两次渲染。
- Writer 完成数量等于业务帧数的两倍。

## 5. Prim 白名单配置

当前 `configs/excavator_only_render_prims.json`：

```json
{
  "schema_version": 1,
  "render_prim_paths": [
    "/root/Xform",
    "/root/Light"
  ]
}
```

含义：

- `/root/Xform`
  - 保留挖掘机主体及其全部子级。
  - 包括小臂、动臂、驾驶室、履带、铲斗和斗齿。
- `/root/Light`
  - 保留用于照明挖掘机的灯光。
  - 灯光不作为背景几何显示。

采集 Camera 会由代码自动保护，不要求重复写入白名单。

实际隐藏的 Prim 会被记录到：

```text
run_config.json
└── excavator_only_capture
    └── visibility_report
        ├── included_prim_paths
        ├── protected_prim_paths
        └── hidden_prim_paths
```

## 6. 同一帧双版本采集流程

每个业务帧执行顺序如下：

```text
推进物理到目标数据集时间
        ↓
暂停 Timeline 并冻结 World
        ↓
读取关节状态和 Camera 世界矩阵
        ↓
建立 full_scene CaptureContext
        ↓
渲染完整场景 RGB + 语义
        ↓
断言物理时间、Timeline 和物理步未变化
        ↓
在临时 Session Layer 隐藏白名单外 Prim
        ↓
重置 RTX 渲染历史
        ↓
建立 excavator_only CaptureContext
        ↓
重新渲染仅挖掘机 RGB + 语义
        ↓
清除临时 visibility opinion
        ↓
再次重置 RTX 渲染历史
        ↓
断言冻结世界仍未变化
        ↓
记录两份 CaptureReceipt
        ↓
恢复 Timeline，进入下一帧
```

两个 variant 共享：

- 相同 `frame_id`
- 相同 dataset time
- 相同 Timeline time
- 相同 physics step
- 相同关节命令和回读状态
- 相同 Camera Path、世界矩阵和光学参数
- 相同分辨率和渲染 profile

唯一业务差异是第二次渲染中参与可见性和遮挡计算的 Prim 集合。

### 7.1 RGB

- 完整场景 RGB 保留场景原始渲染结果。
- 仅挖掘机 RGB 是第二次真实渲染结果。
- 仅挖掘机 PNG 使用 RGBA。
- Alpha 为 0 的像素来自第二次渲染中没有几何命中的位置。
- Alpha 不是根据完整场景图或完整场景语义图生成的。

### 7.2 语义数据

- `semantic_id/*.npy`
  - 权威训练标签。
  - 当前类型为 `uint16`。
- `semantic_color/*.png`
  - 根据固定 mapping 生成的可视化图。
- `semantic_runtime_id/*.npy`
  - Isaac Sim 本次运行产生的 runtime ID。
  - 仅在 `save_runtime_ids=true` 时保存。

## 10. 已修复的重要问题

首轮双版本测试中，代码曾在每帧结束时从 Session Layer 中移除并销毁匿名 visibility Layer。第一帧完成后，Hydra 仍然持有该 Layer 的弱引用，导致进入第二帧时发生：

```text
attempted member lookup on NULL TfWeakPtr<SdfLayer>
```

当前修复方案：

1. 匿名 visibility Layer 在控制器初始化时创建。
2. Layer 在整个采集任务中持续挂载。
3. 第二次渲染前只写入临时 visibility opinion。
4. 第二次渲染后只清除这些 opinion。
5. 不在 Hydra 工作期间销毁 Layer。

修复后 3 帧、6 次渲染全部完成，Isaac Sim 正常输出 `Simulation App Shutting Down` 并以退出码 0 结束。

## 11. 注意事项

### 11.1 性能

启用 `excavator_only_capture` 后，每个业务帧至少渲染两次。PathTracing 模式下，总耗时通常接近原来的两倍。

### 11.2 Prim 白名单

- 应选择能代表完整业务物体的上层 Xform。
- 不要重复列出已经被父路径包含的子路径。
- 如果没有保留任何有效灯光，挖掘机 RGB 可能过暗。
- 如果错误保留地面或天空 Prim，它们会继续参与第二次渲染。

### 11.3 原始不可见状态

白名单表示“允许该 Prim 子树参与第二次渲染”，不会强制显示 USD 中原本就不可见的碰撞网格、辅助网格或备用 LOD。

### 11.4 输出覆盖

生产任务建议保持：

```json
"overwrite": false
```

每次运行使用新的输出目录，避免覆盖历史数据。

### 11.5 运行警告

Isaac Sim 运行日志中可能出现 Synthetic Data、HydraTexture 或 OmniGraph 警告。判断任务是否成功应以以下条件为准：

1. 日志出现 `[semantic-capture] Complete`。
2. 日志出现 `Simulation App Shutting Down`。
3. 进程退出码为 0。
4. `run_config.json` 的 `status` 为 `complete`。
5. Writer `pending` 为 0。
6. `validate_semantic_output.py` 通过。
